### 根因（一处不可重入锁的自死锁）

同一线程第二次 acquire 自己等自己 → 分析线程永久卡死。

### 修法（main.py，3 处）
1. `_is_result_deleted` **去掉锁**：改成遍历 `list(_analysis_tasks.values())` 快照的无锁读
   （CPython 单线程读原子；宁可看到过期快照，也不能让整个任务卡死），并写明注释。
2. 成功分支把 `_write_analysis_checkpoint(company_id,"done","ok")` 从锁块内**移到锁外**
   （现在放在 `with` 块结束、`finally: db.close()` 之前）。
3. `except` 分支（错误路径）**保持**在锁内调 `_write_analysis_checkpoint` —— 它现在安全（因为
   `_is_result_deleted` 已无锁），而且正是这条路径让新闸门还能抓到回归。
验证：`scripts/_verify_lock_fix.py` ——持锁调写回路径 0.062s（改前无限阻塞）、复跑 0.040s、

### 实现（engine/industry_resolver.py，CRLF，bare-LF=0）
- `industry_hints_from_text(text)`：复用 `scope_industry_hint` 判据，从任意文本抽
  「行业级线索」投票表（只采纳 service 侧映射 + 排除购销兜底口径）。
- `reassess_industry(current_industry, *, purchase_goods, material_hints,
  contract_text, current_source, pipeline_log)`：决策三态 change/keep/insufficient。
  ★ 只能推翻、不能凭空定：
  · 无新证据 → insufficient（不猜）
  · current 是购销兜底口径 → ≥1 路证据一致即可推翻（兜底本就低置信）
  · current 是高权威（销项品名/外部工商/工商登记）→ ≥2 路证据**同时**指向同一具体行业
  · **并票（多个行业同票）= 没有共识 → 一律 keep**，绝不挑一个
  · 商品/物料名不算行业（铁律 R1，只采纳 service_industries 映射）
- pipeline `_run_analyze` 在 Phase 2 之前接线（line ~2190），证据三路 = 进项票品名 /
  已上传资料名+类型 / 合同台账名；decision=change 时同步 `main_biz_cost` 行业口径并留痕。

### ★★ 反向验证的四条大坑（本轮踩全，务必复用）
1. **破坏点必须打准**：一开始把「排除 svc 过滤」和「排除购销兜底口径」两个破坏点搞混，
   改错地方 → 假绿。改守卫前先确认自己改的是哪一个条件。
2. **.pyc 缓存 = 假验证**：破坏后源与已有 `.pyc` 落在同一秒，Python 复用旧字节码，
   子进程/同进程探针都看不到破坏。设 `PYTHONDONTWRITEBYTECODE=1` 只挡写不挡读必须靠；
   **正解是破坏后 `os.utime(path, 未来时间)`**，并在子进程 env 加该变量。
3. **`python -c` 的中文参数会被 Windows 控制台代码页吞成 '?'** → 探针假绿。
   探针命令必须纯 ASCII（中文写成 `\uXXXX` 转义）。
4. **同进程探针也会被 pyc 骗**（`importlib.import_module` 照样用旧字节码）——
   以 subprocess 探针 / pytest 结果为准。
