## 修复：报告三处数字缺失 + 红冲明细/标准（用户三点质疑）

用户查看重跑后报告，指出三处问题并质疑红冲判定标准。根因与修复：

### ① 「可定性 条」空白（0 被吞）
- 根因：`static/js/tax-doc-analysis.js` 的 `esc(s)` 用 `if(!s) return ''`，把数字 0 当 falsy → 空串。
- 修复：`esc` 改为仅对 `null/undefined` 返回空（数字 0 正常显示 "0"）。
- 数据：`report.enterprise_readable_report.redline_summary = {suspicion_total:22, confirmed:0, unconfirmed:22}`（账套1）。
- 现渲染「可定性 0 条、待补证后定性 22 条」。

### ② 「13张」被吞 + 伪「3张」 + 明细缺失
- 根因A：`engine/sentencekit.py` 的 `_LEAD_MARK` 字符类含裸 `\d`，把「13张」「6名」量词前计数当列表编号剥掉 → terminal_signal 成「张发票…」。
- 修复：移除 `\d`，新增 `_LEAD_NUM = ^\d{1,3}[\.、\)）]` 仅匹配「1. 」「2) 」类编号；`strip_meta_prefix` 同时用两者。
- 根因B：`engine/clue_chain.py` 的 `extract_numbers(detail+" "+how)` 把 `_enrich_short_findings` 拼入的阈值文字「>=3张触发」抽成伪数字「3张」。
- 修复：新增 `_strip_methodology` 剥「税务合规方法/税务影响/处理建议/法规依据」后缀，`numbers = extract_numbers(_strip_methodology(detail))`。
- 根因C：`engine/pipeline.py::_enrich_evidence_rows` 对每条 finding 重置 `evidence_rows=[]` 并按关键词通用采样（「集中红冲」触发「供应商/客户/集中」分支 → 压成 5 行高频对方汇总），覆盖作者构建的 13 行逐笔明细。
- 修复：循环开头 `if f.get("evidence_rows"): continue`（作者已构建的证据行必须保留，通用采样仅作兜底）。
- 现：terminal_signal 含「13张」；红线疑点明细表 13 行（发票号/对方/金额/日期/备注）；numbers 不再含「3张」。

### ③ 红冲 vs 折扣 标准不清
- 修复：`engine/domain_analysis.py::_domain_red_void_invoice` 重写：拆分红冲/作废计数；说明红字发票须凭《红字发票信息确认单》法定更正（非作废、非折扣折让），折扣折让是同一蓝票净额列示；13 张全部为带确认单的红字发票（非作废非折扣）；逐张核验要求。detail 现明示「红字发票（红冲）13张、作废0张，合计价税合计-1,285,450.57元」。
