# 项目长期记忆（caishuixitong 税务稽查系统）

## 系统定位（用户明确，2026-08-22）
双定位，所有功能设计须同时满足：
1. **给税务稽查人员**做企业稽查分析（稽查视角）；
2. **给企业**从"被稽查视角"自查税务风险、并指引合规（自审+合规指引视角）。

## 用户核心诉求主线
- 反复强调：系统必须"有稽查实质"，不是漂亮外壳。凡属"解析了但没研判/研判薄弱"的模块，都是要持续加固的对象（BOM、进销存、委外加工、关联方、发票网络等）。
- 能力须**全行业/全企业通用**，不要只针对达冠一家公司。

## 关键认知修正（2026-08-26，用户指正 + 官方口径核实）
- **数电票 + 申报自动预填 + 一窗式比对下，"已开票未申报"差异已被系统锁死**（税务数字账户预填销项/进项，有开票却零申报被拦截，销项填不满发票汇总即票表比对失败）。故原"接云帐房做开票 vs 自报比对"路线价值已近冗余，云帐房从 P0 降级为 P1（真实价值在账套+银行流水）。
- **差异主战场已迁移**：①未开票收入栏留空（私有收钱不填，主通道）②增值税收入 vs 所得税收入差>10% ③私户/个人码收款 vs 申报（银税互动资金流）④虚开（票真业务假，票表比对反通过）。
- **下一阶最高优先级 = 资金流比对**（银行流水/企业网银 vs 申报收入，抓未开票+私户+资金回流），而非发票数据。路线图 docs/capability_boundary_roadmap.md 已按此重写。
- **资金流比对已实现**（2026-08-26，提交 0ad40587）：engine/bank_flow.py + pipeline 主链路 comprehensive["bank_flow"] + 报告第十三章 + 前端渲染。引擎 run_bank_flow_compare 量化未开票敞口/私户收款/资金回流；样本列用 贷方金额/借方金额（借贷标志+交易金额 在 pipeline 标准化下不会被拆分 credit/debit）。

## 三对矛盾信息铁律（2026-09-04 确立，平台运营商误读纠错）
系统极易把电商平台（天猫/阿里妈妈/京东/抖音等）开出的**服务费发票**误读为「对消费者销售→账外收入敞口」，并把平台商标成「核心客户」。凡涉平台/服务费判定，三对矛盾必须**全部结论层代码路径一致区分**：
1. **平台运营商 vs 个人消费者**（购方性质）
2. **服务费 vs 货物销售**（交易性质，税码 3 开头 = 服务费）
3. **三方归集 vs 账外收入**（资金性质）

- 「结论层」vs「事实层」：事实层（前5大购买方/销项客户明细/void_by_buyer 交叉核对）如实呈现购方，不构成误标；结论层（集中度/画像/图谱/变名开票/逐户匹配/风险信号/AGI 上下文）必须剔除平台。
- 关键工具函数（`engine/verified_rule_engine.py`）：`_is_platform_operator(name)`（4337）、`_invoice_is_service_fee(inv)`（4328，税码 3 开头或品名含 _SERVICE_FEE_GOODS_HINTS）、`_goods_category`/`_GOODS_CATEGORY_MAP`（2554-2569）。
- 全路径闭环 12 commit 见 daily log 2026-09-04；集中度范式 = `sorted(...)[:3]` 切片 + 聚合集合剔除非业务实体。
- 第二对矛盾的服务费剔除须覆盖**所有「进销品名匹配」结论层**：VR033、agi_pipeline.perceive（goods_match_ratio）、`_domain_advanced_rules` 规则3（购销品名匹配度）。排查法：grep「进销品名/品名背离/变名/goods_match/品名匹配」逐处确认是否调用 `_invoice_is_service_fee`。

## 工资/社保分析铁律（2026-09-04 确立，用户报缺陷后修复）
1. **先按 (姓名, 所属月份) 归位，再谈人数**：工资/社保表每行是「一人一月」记录，每行自带 `period_start`/`period_end`（文件名也带账期）。逐行聚合会把同一人 12 个月记成 12 个人——实测 6 名员工被误报成「51 名员工工资高度均一」（徐瑶12+黄奕珊12=24 条被当成 24 人）。凡工资/社保统计，人数一律 `set(姓名)` 去重，用 `_row_period()` 取月份。
2. **拆分工资判据 = 「同月多人同薪」**（同一月份 ≥3 人领取相同整数整额）。**同一人分多月领取等额工资属固定薪酬，不得报警**——这是消除该类误报的关键。
3. **过滤表头/合计行**：用 `_is_noise_name()` 剔除「合计/小计/姓名/总计/序号」等噪声名，否则会被当成未匹配人员（实测报出「仅在社保清单的人员：合计、姓名、小计」）。
4. **结论必须带明细表格**：list-of-dicts 明细放进 `observed_metrics`（如 `person_month_detail` / `salary_person_month_detail`），`_build_detail_table`（enterprise_report.py:345）自动渲染成表，异常行排前。**禁止只给「举例」**。
5. **实质违规线索不受比例阈值限制**：`有工资无社保`（未依法参保）即便仅 1 人（占比 <20%）也必须报出待证——与「不得抬高阈值放过信号」铁律一致。
