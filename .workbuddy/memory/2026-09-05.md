# 2026-09-05 工作日志

## 修复「新建账套显示不了在选择账套页」（commit 881e5c29）
- **根因**：前后端契约缺失——`select-company.html`/`new-company.html` 依赖的
  `GET/POST/DELETE /api/companies` 三个端点后端从未实现（只有 industry/online-lookup 子路由），
  创建时 POST 404、选择页 GET 404。
- **修复**：
  - main.py 补三端点：GET（按授权过滤，admin 全量/普通用户按 company_ids）、
    POST（name 非空 + uscc 18位 + uscc 唯一校验，创建后 `grant_company_to_user` 立即授权创建者）、
    DELETE（删 Company + `delete_company_cascade` 级联清理）。
  - security.py 新增 `grant_company_to_user` / `revoke_company_from_user` / `delete_company_cascade`
    （清理 users.company_ids 与 sessions.selected_company_id）。
  - 权限全部交给既有中间件 `enforce_request_security`（非 GET 仅 admin + CSRF + can_access_company）。
- **验证**：新增 tests/test_company_api.py 集成测试（子进程 + APP_DATA_DIR 临时目录隔离，
  同 test_llm_api.py 模式），11 契约场景全过；全量单测 152 全过；端到端 4 家 OK。
- **架构要点（复用）**：
  - 系统两个库：`security.db`（users/sessions，sqlite3 直连 security.py）与
    `accounting.db`（companies 等业务表，SQLAlchemy database.py），路径都在
    `runtime_storage.py`，可用 `APP_DATA_DIR` 环境变量整体重定向（import 时求值，
    测试须用子进程）。
  - 集成测试模式：`subprocess.run([sys.executable, "-c", script], env={APP_DATA_DIR: tmp,
    APP_ADMIN_USERNAME/PASSWORD, APP_COOKIE_SECURE=0, APP_ALLOWED_ORIGINS=testserver})`。
  - 中间件对 `/api/companies` 非 GET 已内置 admin 拦截，端点本身无需再查 role。
