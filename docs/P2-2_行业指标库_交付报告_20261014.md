## 四、核心实现

### 4.1 量纲**与换算系数同源**（不另写「哪个是百分比」）

```python
def indicator_unit(key) -> str:
    zh = _LABEL.get(key)
    return "%" if float(_METRIC_SCALE.get(zh, 1.0)) > 1.0 else ""
```

历史事故：首版统一 ×100 把进销比 0.4~0.95 变成 40~95（单位错误）。**量纲必须由换算系数派生**，
不能在别处按指标名硬编码。实测：毛利率/税负率/期间费用率 = `%`，进销比 = `""`（比值）。

### 4.2 入参必须是**行业名**（实测踩到的坑）

```python
# ❌ 传 industry_id（manufacturing）⇒ match_industry 按名称匹配失败 ⇒ 落入兜底区间
# ✅ 传 label（制造业）
det = _indicators_of(label or iid)
```

若传 id，页面会把**兜底区间**当成该行业基准 —— 这是"拿错口径冒充行业基准"，必须避免。
闸门同时断言**代码里不得硬编码行业 id**。

### 4.3 兜底区间**单列**，未登记行业如实 404

`/industry-indicators/generic` 独立端点展示宽松兜底区间；单行业详情对未登记行业返回 `None` ⇒ 404，
**绝不**把兜底区间包装成"该行业基准"（两者口径不混）。

### 4.4 口径警示**只转发不重写**

读层出现 `IB.BENCHMARK_CAUTION`（薄转发），**不得**出现警示语字面量。
闸门 `check_industry_indicators_wiring` 对"代码里出现警示语字面量"报 ERROR。

## 五、接口清单

| 端点 | 说明 |
|---|---|
| `GET /api/v1/industry-indicators/meta` | 字典（来源清单 / 口径警示 / 指标键 / 解析优先级） |
| `GET /api/v1/industry-indicators/stats` | 统计（行业数/指标键/来源分布/未覆盖键） |
| `GET /api/v1/industry-indicators/generic` | 宽松兜底区间（单列） |
| `GET /api/v1/industry-indicators?q=` | 行业清单（每行业基准来源 + 指标区间） |
| `GET /api/v1/industry-indicators/{industry}` | 单行业详情（登记项原文 + 指标区间） |
| `GET /industry-indicators`（页面） | 行业指标库浏览页 |

权限：`industry.view`。路由顺序：`meta`/`stats`/`generic` 在 `{industry}` **之前**。

## 七、未完成 / 风险

- **3 个行业落兜底区间**：`static/industry_data.json` 缺餐饮/建筑安装/科技服务的基准。
  这是**既有数据缺口**（本轮未擅自补数），页面如实标注 `resolve_source=通用宽松区间(未匹配到行业)`。
- 实测校准表未生成（`industry_benchmarks_calibrated.json` 不存在）⇒ 全行业走"通用参考"。
  如需提升精度，运行 `tools/calibrate_industry_benchmarks.py`（需真实账套）。
- 指标键仅 4 个（毛利率/税负率/期间费用率/进销比）——属既有口径，扩展需在
  `industry_benchmark._METRIC_ZH_TO_EN` + `_METRIC_SCALE` 各加一行。
- 页面**只读**：不支持在线改区间（区间属权威数据，须走数据文件 + 校准工具）。
