**实测额外发现并修复的真缺陷（不在原差距清单内）**：

1. `parse_enhance.safe_nrows()` 在 `worksheet.max_row is None` 时返回 **0**
   ⇒ 无 worksheet dimension 的 xlsx（`write_only` 生成、部分第三方导出）
   被当成"0 行空表" ⇒ **整份账套静默丢光**（5 万行实测 `rows_read=0`）。
2. `bank_statement.keywords` 混入「记账日期/凭证号/发生额」等账簿通用词
   ⇒ 标准序时账被判成**银行流水**，整份账簿进错域。
3. `trial_balance` / `journal` / `general_ledger` 未登记进 `document_categories.json`
   ⇒ 账簿族类型无法映射到业务大类。
4. 借贷六列缺英文键别名（`open_debit` / `current_debit` / `close_debit`）
   ⇒ 期初/本期四列**永远取不到**（科目余额表取数恰恰依赖本期发生额）。
5. 结构模式表**没有报表模式** ⇒ 资产负债表被判 `invoice` 并覆写关键词阶段的正确判断。
6. 表格画像**两处独立剔除汇总行**（采样一处、计数一处，口径互相打架）
   ⇒ 报表 `total_rows` 只剩 2，报表模式被 `min_rows` 直接排除。
7. 项目 `taxpayer_id` 缺失被判"必须 18 位" ⇒ 与 API schema"不硬性阻断缺项"冲突。

## 二、遗留事项（本轮明确不做）

### B-01 天眼查 / 企查查 API 对接（外部数据源）

- **现状**：`engine/external_verifier.py` 如实返回 `status="not_integrated"`；
  系统在缺此数据源时按"外部核验不可得"走中性口径（不臆断、不降级为风险）。
- **为什么不做**：需要①正式商务账号 ②按厂商文档实现签名/限流/字段映射
  ③法务确认调用范围 —— 三件都不在代码侧。
- **启动条件**：取得商务账号 + 法务书面确认后，按厂商文档实现；
  实现时**必须**同步登记「外部核验不可得 ≠ 无风险」的口径。

### B-02 根目录 52 个 `_*.py` 一次性脚本的归档

- **现状**：均为历史验收/探针/文档行号同步脚本，**全仓零代码引用**；
  但被 `docs/` 多份交付报告**按文件名引用**（作为当时证据）。
- **为什么本轮不动**：物理删除或移动会破坏 `check_doc_ref_graph`（跨文件引用一致性）
  ⇒ 属"改了但会更糟"。须与文档一起改，属独立一轮。
- **启动条件**：先批量改写 `docs/` 中的路径引用，再 `git rm` 并跑 D5 闸门。

### B-03 旧 `/api/*` 路由下线（约 159 条）

- **现状**：已收敛权限点（`_LEGACY_WRITE_PERMS`）与 API 边界（`api_common`），
  但旧路由仍在线，与 `/api/v1/*` 双轨并存。
- **为什么不做**：前端多个页面仍在调用旧路由；下线需同步改前端 + 回归全部流程，
  属"大改"，不适合与收口同轮。
- **启动条件**：逐页面替换为 `/api/v1` 后，按端点清单灰度下线。

### B-04 SQLite 并发扩展性

- **现状**：单实例 + WAL，并发写有 503 语义转换；未做多实例/连接池压测。
- **为什么不做**：当前定位是单机部署；换库（PostgreSQL）是架构级改动。
- **启动条件**：出现"多实例部署"需求时，先做连接层抽象再换库。

### B-05 既有测试失败（16 项，均为本轮之前存在）

- **清单与归因**：见《系统终验报告》附录 A（逐项给出"基线是否同样失败"的证据）。
- **为什么不做**：其中多数是**产物级**断言（依赖 `scripts/four_reports/*.json`
  的当时内容）与历史口径遗留，改动会牵动报告生成链，须单独一轮。
- **启动条件**：先明确"这些断言守护的口径是否仍有效"，再决定改代码还是改判据。

### B-06 历史行号引用（`docs/` 按行号引用 `tools/audit_consistency.py`）

- **现状**：已用 `scripts/_sync_doc_line_numbers.py --apply` 同步到当前行号；
  但**每次改审计文件都会漂移**，必须记得重跑。
- **为什么不做**：根治做法是文档改为"按函数名引用"而非行号，属文档重构。
- **启动条件**：文档重构轮统一改为「函数名 + grep 命令」索引。

### B-07 申报表行次映射的覆盖广度

- **现状**：`config/declaration_lines.json` 目前只登记**增值税一般纳税人主表** 15 个行次
  （实测真实 PDF 已能抽 15 个字段且数值与 PDF 一致）。
- **为什么不做**：企业所得税/个税/社保申报表各需按其官方行次表逐表核对，
  属数据录入工作，需要逐表对照官方模板。
- **启动条件**：拿到目标申报表官方模板后，**只加一个 `declarations.<key>` 数据块**，
  不改代码（设计已支持）。

### B-08 结构类型识别仍偏"关键词 + 形态"的组合

- **现状**：本轮补了 `require_any`（必须有本类型独有信号）与 `required_bonus`（缺主特征降权），
  但仍有"同形不同类型"的边界（如 `voucher` vs `trial_balance`）。
- **为什么不做**：再细化需要行业/税种上下文，属能力增强而非收口。
- **启动条件**：出现实测误判样本时，先补样本到 `_STRUCTURE_CASES`，再调模式表。
