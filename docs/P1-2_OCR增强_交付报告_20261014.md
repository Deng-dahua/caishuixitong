## 一、先扫描现状（改动前）

既有 **OCR 唯一收敛点**：`main._ocr_png_bytes`（`main.py:1659`），按
`rapidocr-onnxruntime → easyocr → pytesseract` 依次尝试；PDF 侧由
`main._ocr_pdf_pages` 用 `fitz` 渲染成 PNG 后走同一收敛点。

扫描发现 **4 处缺口**（全部实际可复现）：

| 编号 | 缺口 | 后果 |
|---|---|---|
| O-1 | **全部引擎不可用时静默返回空串** | 用户拿到空结果，**无法区分**"这张图确实没文字"与"本机根本没有 OCR 引擎" |
| O-2 | 引擎返回的**置信度被丢弃** | rapidocr 的 `item[2]`、easyocr 的 `conf` 均未使用 ⇒ 低质量识别与高质量识别同样对待 |
| O-3 | 失败只 `print` 到 stdout，**无结构化留痕** | 现场排查只能翻日志文本；接口层无法回答"最近 OCR 跑得怎么样" |
| O-4 | **无法提前告知引擎可用性** | 只能"试到成功为止"；用户事前不知道扫描件能不能读 |

---

## 二、目标

1. 把"有哪些 OCR 引擎、当前是否可用"变成**可查询的结构化状态**（补 O-4）。
2. 每次 OCR 运行留下**结构化留痕**（引擎 / 段数 / 字符数 / 耗时 / 低置信度计数）（补 O-3、O-2）。
3. 空结果**必须给出原因**，绝不静默（补 O-1）。
4. **行为等价**：治理层不得改变 OCR 正文（返回值与既有拼接逐字符相同）。

## 四、核心实现说明

### 4.1 引擎登记与探测（**不初始化，故极快且无副作用**）

`ENGINES` 登记表：`rapidocr`（优先级 0）/ `easyocr`（1）/ `tesseract`（2），
每项含依赖模块名、是否需要系统可执行文件、说明。`probe_engines()` 用
`importlib.util.find_spec` 判断模块存在性；`tesseract` 额外用 `shutil.which` 与
**既有实现同款的 2 个安装路径**判断。

`engine_status()` 返回结构化状态：`engines[] / available / any_available / preferred / conf_floor / note`。
**无可用引擎时 `note` 显式说明**"提取不到文字 ≠ 没有文字，请安装 rapidocr-onnxruntime"。

### 4.2 运行留痕与**行为等价**

`record_ocr_run(chunks, engine, *, elapsed, confidences)`：

```python
text = "\n".join(chunks or [])          # ← 与既有实现**完全同口径**
```

**返回值与 `"\n".join(chunks)` 逐字符相同**（测试用字符串相等断言，覆盖 4 组样例含含换行样例）。
留痕字段：`at / engine / segments / chars / elapsed / conf_n / low_conf / empty / reason`；
留痕上限 50 条（不无限增长）；`chunks` 为空时 **`reason` 非空**且额外留一条 stderr 说明。

### 4.3 置信度治理

`CONF_FLOOR = 0.5`（唯一权威）；`record_ocr_run` 按阈值统计 `low_conf`。
阈值经 `/api/v1/ocr/meta` 下发，前端不硬编码。

### 4.4 新增接口

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/v1/ocr/meta` | 引擎状态 + 阈值 + 最近一次运行 | `document.view` |
| GET | `/api/v1/ocr/runs` | 最近 N 次运行留痕（默认 20，上限 50） | `document.view` |

## 六、未完成 / 风险

1. **未做结果缓存**：同一扫描件重复解析会重复 OCR（成本高）。本轮的改动限于"不改既有行为"，
   加缓存需要在 `_ocr_png_bytes` 入口插入逻辑（会改变函数结构），故**留待后续**。
2. **未做多页/DPI 参数化**：`_ocr_pdf_pages(max_pages=20, dpi=300)` 仍是硬编码默认值。
3. **留痕仅存进程内**：重启即清空（已在接口 `note` 中如实声明）。若要持久化，应落
   `runtime_storage` 的 append-only 流水（与 `analysis_jobs` 同款）。
4. **置信度仅统计不拦截**：低置信度识别结果仍会进入解析链路（不因置信度低而丢弃文本）。
   这是有意的（"宁可给可疑文本 + 标注，也不静默丢字"），但需业务侧确认。
