## 一、审判结论：四类提示不契合实际 + 两个真缺陷

### ① 银行流水提示「借贷不平衡」——**不合理**（37 条全错）
- 银行流水的「借方发生额＝支出、贷方发生额＝收入」，两列合计**本来就不该相等**
  （差额＝期间净流入）。旧判据把账簿的借贷平衡规则套到流水上，把常态打成了 error。
- 真实样例：`2023.8.xls 借方 254,549.80 / 贷方 312,120.00 / 差额 -57,570.20`——
  那只是当月收大于付。
- 逐行验证真实流水（文档 577，12 行）：**完美满足余额连续性**
  （上一行余额＋收入−支出＝本行余额，8/8 个跨日行对全对）——数据本身没毛病。

### ② 发票「号码重复（可能是重复导入或错填）」——**误导**
- 实测同号成对出现且**一正一负**（117.22 / -34.25）＝数电发票平台把蓝票与
  红字冲销**同号一并导出**的正常形态，不是重复导入。

### ③ 凭证「完全重复的数据」——**多为合并记账**
- 实测 42 条抽样全部是**同一凭证内**同科目同金额多行
  （记-4「银行手续费」两笔 9.00 元＝两行），属正常记账形态。

### ④ 分类 93% 落「其他」——**识别能力在，结果没回填**
- 上传时的分类**只看文件名关键词**；125 份里 116 份（93%）文件名不含关键词。
- 而解析后的表头内容早已被正确识别（`extracted_tables.doc_type`：bank_statement
  37 张表等）——缺口只是**从不回填到文档级分类**。

### 真缺陷 A：删除资料后解析产物残留
`delete_document` 只删 `documents`+`document_pages`，漏了三张解析登记表 ⇒
真实库 **281 表 / 1506 字段 / 240 条异常成孤儿**，「项目级校验异常清单」**87% 是幽灵**。

### 真缺陷 B：结构层误判覆写关键词
达冠 3 份银行流水（表头：交易时间/收入金额/支出金额/账户余额/对方户名）被
**结构分析层**以 0.975 置信度覆写成 `financial_statement`——流水与数字报表在
纯结构层面不可区分，而列名语义只有关键词层看得见。

## 二、修法（全部分域/数据驱动，无特例分支）

| 问题 | 修法 | 落点 |
|---|---|---|
| 流水借贷误报 | bank 域跳过借贷平衡，新增 `bank_balance_check`：**组间不变量**（相邻日期组 R1→R2：R2 某余额 − R1 某余额 ＝ R2 净额，顺序无关）＋聚合勾稽（期初＋Σ贷−Σ借＝期末） | `engine/extract_validate.py` |
| 发票红冲误报 | 同号按金额方向分诊：一正一负＝红字冲销（请核对对应关系）；同号同额＝真重复；同向不同额＝请人工核对 | 同上 |
| 凭证重复误报 | ledger 域：同凭证号内整行重复不报（数量如实写入 detail）；凭证号列不存在（无法区分）⇒ 保守仍报 | 同上 |
| 分类落"其他" | 解析成功后用表级内容识别回填文档级分类（人工修正永不覆盖；note 记录依据）；分类代码统一 `other` | `engine/extract_service.py` / `document_types.py` |
| 结构覆写 | `STRUCT_AMBIGUOUS_PAIRS` 补 bank_statement↔financial_statement（冲突信任关键词） | `main.py` |
| 删除残留 | 复用声明出口 `_reset_document_extract` 清三张登记表 | `engine/document_service.py` |

**★ 为什么流水检查不用"逐行链式"**：实测 0720 两笔同秒、真实时间顺序与稳定排序
**相反**——链式检查会假报"余额断裂"。顺序歧义必须用"组间余额集合存在性"吸收，
才能既不漏报也不误报。

**★ 二次教训**：识别器修好后，"已有分类不动"的守卫把此前写错的分类**固化**了
⇒ note 以「内容识别：」开头的（即自动内容推导）允许被更正的识别覆盖；
人工修正（manual）仍然永不覆盖。
