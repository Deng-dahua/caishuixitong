## 〇、判据勘误（2026-10-14 追加，**必须先读**）

> ★★ 本报告 §一 原写「`.nav-item` 共 17 项，**全部可见**」，该结论的**判据不成立**：
> 当时用的是 `document.querySelectorAll('.nav-item').length` —— 数的是 **DOM 节点数**；
> 而 `rbac-nav.js` 用 `style.display='none'` 隐藏节点，**节点仍在 DOM 里** ⇒ 数节点**分不出可见/隐藏**。
>
> **正确判据**：
> `getComputedStyle(el).display !== 'none' && el.visibility !== 'hidden' && el.offsetParent !== null`。
>
> **重测结果（2026-10-14，新代码隔离实例 + 真实 Chrome）**：
> DOM 节点 **19** ／ **计算可见 19** ／ 隐藏 0（含全部 8 个 `data-perm` 项）⇒ 结论恰为"全可见"，
> 但**原判据不可作为证据**，故在此勘误。
>
> **同源风险已实测命中真实场景**：用户实际运行的**旧进程**上，8 个 `data-perm` 项**确实被隐藏**
> —— 若沿用"数节点"判据，会**完全看不到**这个差异。详见
> `docs/排查_侧边栏少8项_旧进程_20261014.md`。

## 二、★ 主因：主内容区可能**永久空白**（`lastPage` 落在渲染不了的页）

### 现象（实测）
- 侧边栏 17 项**照常显示**；
- 右侧主内容区 **完全空白**（`#content-area` 文本长度 = **0**）；
- **刷新无效**（仍为 0）。

### 根因（代码级，两处不一致）
`static/js/core.js`：

1. **允许名单**（第 780 行）把 `methodology` 列为合法页：
   ```js
   var _allowedPages = ['tax-doc-analysis', 'methodology', 'system-logs'];
   ```
2. **渲染分派** `switch(page)`（第 806 行起）**没有 `case 'methodology'`** ——
   于是 `navigateTo('methodology')` 会：把容器 `display` 打开 → 但**没有任何渲染分支命中** → **内容区留空**。
3. **并且它被持久化**（第 789 行）：
   ```js
   localStorage.setItem('lastPage', page);   // ← 在渲染之前就写入
   ```
4. 启动时（第 473-474 行）：
   ```js
   const lastPage = localStorage.getItem('lastPage') || 'tax-doc-analysis';
   navigateTo(lastPage);
   ```
   ⇒ `lastPage='methodology'` 时，**每次打开都空白**，刷新、重登、换账套都不清除。

### 实测四步复现（同一浏览器会话）
| 步骤 | 内容区文本长度 | `localStorage.lastPage` |
|---|---|---|
| ① 注入 `lastPage='methodology'` 后访问 `/` | **0（空白）** | `methodology` |
| ② 刷新 | **0（不自愈）** | `methodology` |
| ③ 点击侧边栏「资料风险分析报告」 | **167（恢复）** | `tax-doc-analysis` |
| ④ 再刷新 | **167（已持久修复）** | `tax-doc-analysis` |

### 附带发现（同源缺陷）
`core.js:1046-1066` 的 `switch(page)` 中保留了一组新 UI 已不再提供的页名
（`tax-risk-rules-list` / `pipeline-analyze` / `domain-panel` / `compact-clues`），
它们全部 `navigateTo('methodology')`；而这些入口**在当前的 HTML/JS 里已无任何调用方**（实测 grep：调用方 0）。
⇒ 说明 `lastPage='methodology'` 是**历史版本残留**（localStorage 永久保留，跨版本生效）。

### ✅ 立即处置（用户侧，一条命令即可）
在浏览器控制台执行，然后刷新：
```js
localStorage.removeItem('lastPage');   // 或 localStorage.setItem('lastPage','tax-doc-analysis')
```
或**不用控制台**：直接点侧边栏「📁 资料风险分析报告」即可恢复（实测第三步起即恢复且持久）。

### 🔧 代码侧修法（建议，未实施）
1. **两处必须一致**：`_allowedPages` 与 `switch` 的 case 集合应同源派生（避免"白名单里有、渲染不了"）；
2. **`lastPage` 写入前先校验可渲染**：仅当该页确有渲染分支时才 `setItem`；否则回落到 `tax-doc-analysis`；
3. 给 `switch` 兜底 `default:` 分支 —— 未命中时渲染 `tax-doc-analysis`（而不是留空）；
4. 加一条闸门：断言 `_allowedPages` ⊆ `switch` 的 case 集合（**防复发**）。

## 三、`/users`（用户管理）默认加载即失败

### 现象（实测）
页面正文出现 **「加载失败：[object Object]」**，用户表格停在「加载中…」。

### 根因（前后端各一半）
1. **前端**：`static/users.html:168-172` 拼查询串时把**未选择组织**也带上，值为**空串**：
   ```js
   + "&tenant_id=" + encodeURIComponent($("f-tenant").value)   // 默认空 ⇒ "tenant_id="
   ```
2. **后端**：`/api/v1/users` 的 `tenant_id` 声明为 `int` ⇒ 收到空串报 **422**：
   ```
   HTTP 422  {"detail":[{"type":"int_parsing","loc":["query","tenant_id"],
              "msg":"Input should be a valid integer, unable to parse string as an integer","input":""}]}
   ```
   （实测：`tenant_id=` ⇒ 422；`tenant_id=1` ⇒ 200）
3. **错误展示**：`users.html:176` 直接字符串拼接
   ```js
   showMsg("加载失败：" + (res.data.detail || ...))   // detail 是数组 ⇒ "[object Object]"
   ```

### 🔧 修法（建议，未实施）
- 前端：空值**不发该参数**（或发 `tenant_id` 省略）；
- 后端：`tenant_id: Optional[int] = None`（空串归一为 None）；
- 错误展示：`detail` 非字符串时取 `msg`/JSON 化，避免 `[object Object]`。
- 同类检查：`/api/v1/audit-logs?...&tenant_id=` 实测 **200**（那处是 `str`）⇒ 只有 users 这一处踩坑。
