## 2. 核心实现说明

### 2.1 ★★ 复用而非另造（本模块最重要的原则）

本项目**已有**成熟的解析链路（`_parse_excel_structured` 含 **20+ 个专用解析器**：科目余额表/发票/银行流水/申报表/工资/社保/公积金/报关/出口退税/研发辅助账…）。本模块**只做"登记 + 标准化 + 校验 + 人工校正"**，**不另写一套解析器**：

| 环节 | **复用谁**（唯一权威） |
|---|---|
| Excel / CSV 表格解析 | `main._parse_excel_structured(filepath, ext, original_name)` ⇒ `{type, rows, confidence, source, _trace}` |
| 图片 OCR | `main._ocr_png_bytes(png_bytes)`（**三档降级**：rapidocr → easyocr → pytesseract） |
| PDF 文本/表格 | `pdfplumber`（既有依赖） |
| 字段别名 | `engine/fieldkit.py` 的 `*_KEYS` 常量（字典里用 `aliases_from` **引用常量名**，不抄第二份） |
| 金额解析 | `engine/numparse.to_number_checked`（能区分"真 0"与"解析失败"） |
| 异步作业 | `engine/analysis_jobs.py`（作业流水 + 状态机） |
| 审计 | `engine.audit_trail.record` |
| 表结构变更 | 幂等 `ensure_schema`（`audit_trail` 模式，**不引入 Alembic**） |

**判据**：`GET /api/v1/extract/meta` 的 `parser_reuse` 段**显式声明**了复用关系（可机器核对），单元测试断言其指向 `main.`。⇒ 防后人误以为这里又写了一套解析器。

### 2.4 六类校验（`engine/extract_validate.py`）

| 规则 | 实现要点 | 严重度 |
|---|---|---|
| `required_missing` 必填缺失 | 按**域**判定（只要求该域必填字段），整表无值才报 | error |
| `amount_format` 金额格式错误 | 逐行逐列 `numparse` 解析，**带行号与原值** | error |
| `period_mismatch` 期间错配 | **只在给了项目稽查期间时才判** | warning |
| `duplicate` 重复数据 | 整行标准字段完全一致；**全空行不算** | warning |
| `debit_credit_unbalanced` 借贷不平衡 | Σ借 vs Σ贷；**缺一侧 ⇒ 跳过（不伪装通过）** | error |
| `cross_check` 报表勾稽异常 | 资产 = 负债 + 权益；**三项缺一 ⇒ 跳过** | warning |

**设计口径**：只报不修；**不确定就不报**（取不到参与量 ⇒ 跳过该规则，报"无法判定"而非伪装"通过"）——与项目铁律「缺失≠0」一致。

### 2.5 ★ 纵向键值表兜底（本模块的增量能力，不改既有解析器）

**实测发现的真实缺口**：**资产负债表**这类表是**纵向键值对**布局（A 列=项目名"资产总计"，B 列=金额），既有 `_parse_excel_structured` 会判定类型为 `financial_statements` 但**产出 0 行**（它期望"表头 + 多行"横表）。

处理：本模块加**保守兜底** `_fallback_vertical_kv`：
- 只在「**恰好 2 列** + 首列非空文本 + 次列 ≥80% 可解析为数值 + ≥2 数据行」时启用；
- 关键一步是**透视**：纵向表的**字段名在「项目」列的值里**（如"资产总计"），必须转成 `{资产总计: 500000}` 一行，否则 `total_assets`（别名="资产总计"）**永远取不到**；
- 不满足条件 ⇒ 返回 `None`，调用方照常报"未识别出结构"（**不伪造行**）。

⇒ 该兜底把资产负债表三项从**全 MISS** 提升为**全部命中**。

### 2.6 可追溯（验收要求「解析结果可回链原始文件」）

三层回链：

| 层 | 落点 |
