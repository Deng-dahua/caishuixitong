不能只把 LLM 接进来——任务书硬约束是「**AI 辅助不替代规则，只做辅助**」，
必须有**机制**（而非文档声明）保证 AI 文本不会被当成判定结论。

**三重机制**保证"只做辅助"，且 **LLM 不可用时如实降级**为"规则侧线索"。

## 四、核心实现 —— 「只做辅助」的三道机制

### 机制① 角色声明（**每个产出都带**）

```python
{"role": "advisory", "advisory_only": True, "replaces_rules": False, "disclaimer": DISCLAIMER}
```

接口层**原样透出**这四字段，**不得裁剪**（裁剪即等于给前端机会把它当结论展示）；
闸门断言 `assist()` 里必须**显式**写 `"replaces_rules": False`（不能只靠文档说明）。

### 机制② 不产出判定 —— **清洗拦截**

```python
FORBIDDEN_CLAIM_TERMS = ("已构成违规", "已认定", "应补缴", "定性为", ...)
def sanitize(text) -> (清洗后文本, 命中词列表)
```

AI 文本命中定性用语 ⇒ **改写为「（待人工复核）」**，且命中词**如实记录**并回传
（只改写不记录＝静默改写，测试双向断言这一点）。

### 机制③ 可用性如实 + **不冒充 AI**

| 情形 | `engine` | `is_ai` | 产出 |
|---|---|---|---|
| LLM 可用且返回文本 | `llm` | **True** | AI 文本（已清洗） |
| LLM 不可用但输入足够 | `rule_hint` | **False** | **规则侧线索**（确定性拼接） |
| 输入不足 | `unavailable` | False | `None` + 原因（**不编造**） |

规则侧线索是**确定性**的（同输入同输出，测试断言 `a == b`），且在 `reason` 里明确写出
「以下为**规则侧线索**（确定性拼接，非 AI 生成）」。

## 七、未完成 / 风险

- **LLM 实测未跑通**：本机无云端凭据也无 Ollama ⇒ `engine="llm"` 分支**未在真实模型上验证过**
  （代码路径与清洗已用 `allow_llm=False` 覆盖；真实调用需配置凭据后复测）。
- AI 辅助**不写入任何台账**（不留痕、不落盘）——当前定位是"即时辅助"，是否需留痕待业务确认。
- `sanitize` 是**词表拦截**，不是语义判断：改写后的文本仍可能隐含定性倾向 ⇒
  四字段声明 + 人工复核仍是最终防线。
- 未做：辅助结果的"采纳/忽略"记录、prompt 版本化、token 计量与限额。
