# 工商信息自动查填 + 资料风险分析报告并入报告模块（2026-10-19）

> 需求来源：用户两条口头要求 ——
> ①「工商信息是自动添加，而不是手动的」；
> ②「把资料风险分析报告模块融入报告生成与导出模块，然后删除资料风险分析报告模块」。
>
> 本文按「**你会看到什么** → 为什么之前做不到 → 怎么实现 → 我怎么验的 → 遗留」
> 排列。**不含"我改了什么"式自证** —— 每条结论都能用命令复核。

## 一、你会看到什么

### 需求 ①：工商信息自动查填

打开 `/projects` → 【＋ 新建稽查项目】→ 在**企业名称**里输入企业全称
（如「深圳海更数字传媒有限公司」）：

- **不点任何按钮**，输入停顿约 0.7 秒后自动查询；
- 企业名称右侧的状态徽标依次显示 `自动` → `查询中…` → `已自动填报` / `未查到`；
- 下方字段自动被填入（实测填入 5 项）：
  ```
  已自动填报 5 项（来源：本地账套库（companies），命中缓存）；3 项未取得，请手工补齐
  填入字段：统一社会信用代码 / 法定代表人 / 经营范围 / 注册资本 / 成立日期
  ```
- **已手工填写的内容不会被覆盖**（提示里会写「N 项因已填写保持不变」）；
- 登记状态为注销/吊销时，仍弹红色警告（后端判据驱动）；
- 查不到**不阻断保存**，只给提示（原行为保留）。

**原【自动查填】按钮已改为状态徽标**（`role="status"`，不可点击）—— 需求是"自动"，
留一个"仍需点击"的按钮只会让人以为没生效。

### 需求 ②：报告并入 + 删除原模块

| 位置 | 你会看到 |
|---|---|
| 侧边栏 | **不再有**「📁 资料风险分析报告」（原「二、风险分析」分组已整体移除，分组编号重排为 一、项目管理 / 二、系统 / 三、知识库与统计） |
| `/reports`（报告生成与导出） | 第一个页签就是 **「分析报告」**，打开即显示**最近一次一键稽查分析的完整报告**（原内页的阅读与复核能力） |
| 该页签工具条 | 【导出PDF】【缓存】【删除报告】仍可用（与原来一致） |
| `/reports` 其它页签 | 「生成报告」「报告列表 / 历史版本」「版本台账」**全部保留**，未被削弱 |
| 引擎仪表盘等处遗留的「资料风险分析报告」链接 | 点击后**自动跳到 `/reports`**（不再落到空白页） |

## 二、为什么之前做不到

### 需求 ①：原实现要人工点击
`projects.html` 里是 `<button id="btn-fetch-bizinfo">自动查填</button>`，
`projects.js` 在 `bind()` 里绑它的 `onclick` ⇒ **不点就不查**。
"自动查填"四个字描述的是"查回来会自动填字段"，但**触发仍需手动** —— 与用户要的"自动"不是一回事。

### 需求 ②：两个模块本来就是两条不同的渲染链
这是本轮**最关键的一处认识**（若不先厘清，很容易改错地方）：

| | A. 「资料风险分析报告」（SPA 内页） | B. 「报告生成与导出」（独立页 `/reports`） |
|---|---|---|
| 地址 | `#page-tax-doc-analysis`（SPA 内页） | `/reports`（独立页） |
| 数据源 | `GET /api/tax-risk-docs/last-analysis` | `engine/report_service.build_document`（12 章节文档模型） |
| 渲染 | `tax-doc-analysis.js::renderTaxDocReport`（345KB，**五章文书式**） | `reports.js`（生成/下载/台账/预览，**不渲染正文**） |

**A 是"看报告"，B 是"出报告"**。用户要把 A 并进 B，不是让 B 重新实现一套报告渲染
（那会导致两条链各出各的报告 —— 本项目反复强调的铁律），而是把 **A 的阅读能力挂到 B 页面上**。

## 三、怎么实现（单一权威）

### 3.1 需求 ①：改为自动触发

| 环节 | 做法 |
|---|---|
| 触发 | 企业全称输入框绑 `input`（防抖 700ms）+ `blur`（兜底立即查） |
| 去重 | `_bizLastQuery` 记住"上次已发出的全称"⇒ 同名不重复查；`_bizInFlight` 防并发 |
| 门槛 | 全称 < 4 字不查（半截输入），且**不报错**（避免边打字边闪红字） |
| 覆盖保护 | 只填**当前为空**的字段；已手工填写的计入 `kept` 并在提示里说明 |
| 权限 | 复用原 `data-perm="project.write"` 门控：无权限 ⇒ **完全不查**（`bizAllowed()`） |
| 元素 | 按钮 ⇒ `role="status"` 状态徽标（四种状态：`idle/busy/ok/none`） |

唯一调参点：`BIZ_DEBOUNCE_MS` / `BIZ_MIN_LEN`（`projects.js` 顶部）。

### 3.2 需求 ②：并入 /reports 并删除内页

| 环节 | 做法 |
|---|---|
| 新增页签 | `reports.html` 加 `#tab-analysis` + `#pane-analysis`，**排在第一位**（默认页签） |
| 报告容器 | `#tda-report-area` —— **id 不能改**，`renderTaxDocReport` 硬编码取它 |
| 数据加载 | `reports.js::loadAnalysisReport()`：取 `last-analysis` → 取 **`.report`（双层嵌套）** → 调 `renderTaxDocReport` |
| 渲染复用 | **不新写渲染**，直接调 `tax-doc-analysis.js::renderTaxDocReport`（唯一实现） |
| 账套接线 | `window.currentCompanyId = Number(CID)` —— `_tdaCid()` 读它，否则导出/缓存/删除报告报「未选择账套」 |
| 删除内页 | 侧边栏项、`_allowedPages` 条目、`pages` 标题映射、`switch` 分派、`taxDocPageActive` 的跨文件改写 —— 全部移除 |
| 兜底页 | `_FALLBACK_PAGE` 由 `'tax-doc-analysis'` 改为 `'home'`（兜底到"已删除的页"会建空容器 + 「模块加载超时」） |
| 深链兼容 | `navigateTo('tax-doc-analysis')` → `/reports`，**且必须放在白名单校验之前**（否则先被兜底改成首页，用户看不到任何解释） |

### 3.3 关键设计：为什么新建 `static/js/dom-utils.js`

`renderTaxDocReport` 调用 4 个原本**只在 `core.js` 里定义**的全局工具：
`normalizeDisplayValue` / `escapeHtml` / `escHtml` / `toast`。

三条约束把方案逼到唯一解：

1. **不能引 `core.js` 到 `/reports`**：它是 SPA 主控制器，加载即自启 `_startApp()`
   （拉账套、注册导航、切页、在不相干的容器上渲染）⇒ 一堆无关请求与报错；
2. **不能在 `reports.js` 里再抄一份**：那是**多头维护**，两份转义实现迟早分叉
   （转义分叉 = 显示错乱或 XSS 风险）；
3. **审计闸门 `check_js_undefined_calls` 按"每个 HTML 页面的脚本包"求定义**：
   `/reports` 一旦加载 `tax-doc-analysis.js` 而无这 4 个定义，直接报
   「调用 `escHtml(...)` 但该页加载的全部脚本中查无此名」。

⇒ 抽成 **`static/js/dom-utils.js`（唯一权威）**，`index.html` 与 `reports.html`
都加载；**`core.js` 不再自带实现**（改注释指向该文件）。
`dom-utils.js` 里 `normalizeDisplayValue` 的逻辑与 `core.js` 原实现**逐字一致**
（等值迁移，不是重写 —— 它被报告正文大量使用，语义变化会直接改报告内容）。

## 五、本轮自查抓出的问题（判据自身，四处）

这些都是"判据写得太松 ⇒ 注入后仍绿"的假判据，属**工具坏了比没验证更危险**那一类：

| 问题 | 现象 | 修法 |
|---|---|---|
| `_code()` 未剥 HTML 块注释 | 我在 `index.html` 注释里写了 `data-page="tax-doc-analysis"` 做说明 ⇒ 「侧边栏无该入口」判据**误报** | 加 `re.sub(r"<!--.*?-->", "", flags=re.S)`（块注释可跨行） |
| 判据扫全文而非剥注释 | `d.report` 在注释里也出现 ⇒ 把真正取数那行改成 `d` 仍**通过**（R5 抓出） | 判据改为正则 `renderTaxDocReport\(\s*d\.report\s*\)` + 作用于剥注释代码 |
| 判据只查"有赋值" | `window.currentCompanyId = 0`（切项目清空）也算通过 ⇒ 真正的接线被删仍**通过**（R7 抓出） | 收紧为 `window\.currentCompanyId\s*=\s*Number\(\s*CID\s*\)` |
| 反向验证锚点未归一化行尾 | 文件是 CRLF、锚点写 `\n` ⇒ 报"锚点未命中"（R3/R8） | 注入前统一 `replace("\r\n","\n")` |

另有一处**注入方式无效**（不是判据假）：把「分析报告」页签的 `active` 去掉后仍全绿 ——
因为 `reports.js::boot()` 会显式 `switchTab('analysis')` 把它拉回。这类注入**必须换一种**
才能真正验证（已换成"移除渲染依赖"，一次命中 2 项）。

## 七、遗留（未做，如实登记）

1. **`tax-doc-analysis.js` 文件保留**（345KB，未删）。
   **这是刻意的**：它是报告级渲染的**唯一实现**（链②文书式），`/reports` 正在用它；
   同时 `tools/audit_consistency.py` 有 **43 处判据**（对应 15 个检查函数）在扫描该文件
   （`_buildEnterpriseReadableBody`、`cost_recon_detail`、`action_plan_note`、
   `_sanitizeExportClone`、5 个报告级辅助函数的作用域等）。删文件会让这些判据
   **集体报错或静默跳过**，并直接丢掉报告渲染能力。
   ⇒ 用户所说的"删除模块"落实为：**删除它的入口与页面（SPA 内页）**，保留渲染实现。
2. **`taxDocPageActive` 仍由 `tax-doc-analysis.js` 定义并使用**（`reports.js` 不依赖它：
   `renderTaxDocReport` 不检查该标志）。未清理该全局变量 —— 它仍控制"是否自动恢复服务端报告"，
   清理属独立小工程，本轮不做。
3. **`index.html` 的 `#tda-report-area` 移动端样式已迁至 `reports.html`**；
   但报告正文的**其它**移动端适配（如宽表格横向滚动）未逐条核对。
4. **`data/rule_version_events.jsonl` 等运行期数据**未受影响（本轮纯前端 + 一处测试/权限表文案）。
