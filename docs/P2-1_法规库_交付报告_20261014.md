## 二、目标

给法规库补一个**只读的浏览与检索层**：按法名/条款号/正文关键词检索、看单部法全部条文、
看每部法的**版本状态**与**覆盖率**。硬约束：**法规库不硬编码条文**（条文一律来自数据文件）。

## 四、核心实现

### 4.1 「读路径唯一」——不是新写一份，而是把路径抽出来共用

```python
# engine/legal_citation.py（唯一权威）
LIBRARY_FILES: Tuple[str, ...] = ("legal_library.json", "legal_refs.json")
def library_paths() -> List[Path]: ...          # 只列真实存在的
def library_file_entries() -> List[Dict[str,str]]: ...   # 逐条原样条目（含 source）
def _load_library() -> Dict[...]:               # 解析用索引（**改用同一 LIBRARY_FILES**）
```

`engine/legal_library.py` **不出现任何数据文件字面量**，只调 `library_file_entries()`。
闸门 `check_legal_library_wiring` 断言这一点（掩掉注释/文档串后仍不得出现文件名）。

### 4.2 版本状态**薄转发**、缺失如实

每一条正文都带 `version`：`status/status_cn/current_version/effective_from/registered/blocking`，
全部来自 `legal_version`（`status_of` / `entry_of` / `is_blocking`）。**未登记 ⇒ `registered=false`
+ 状态 `unknown`**，绝不默认按现行有效呈现。

### 4.3 「不硬编码条文」的**结果级**判据

测试 `LegalLibraryNoHardcodeTests` 把读层返回的**每一条** `content` 拿去数据文件里**逐字反查**；
反向验证 S5 给 `content` 追加「【编造】」⇒ 判据**必须变红**（实测变红）。

### 4.4 路由顺序

`meta` / `stats` / `laws` 三个字面量段注册在 `{law}` **之前**——
否则 `/legal-library/laws` 会被 `{law}` 吃成"名为 laws 的法"（静默 404）。闸门断言此顺序。

## 五、接口清单

| 端点 | 说明 |
|---|---|
| `GET /api/v1/legal-library/meta` | 字典（来源文件 / 5 档状态枚举 / 覆盖口径） |

## 七、未完成 / 风险

- 法规库**只读**：不支持在线增删改条文（写入仍走 `scripts/_load_legal_texts.py`，人工核实后录入）——**有意如此**（条文属权威数据，不允许在页面随手改）。
- 覆盖率是**红线库引用**的匹配率，**不等于**「法规库完整」；页面已显式写明该口径与"不得编造条文凑覆盖率"。
- 4 部法版本未登记（页面如实标 `unknown`），需人工核对后补入 `config/legal_versions.json`。
- 未做：条文全文高亮、版本变更 diff、法规库导出。
