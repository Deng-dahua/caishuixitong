# 模块精简：下线 SPA 内联页「系统日志」，能力并入「审计日志」

- 日期：2026-10-14
- 触发：用户提问「系统日志模块 / 资料风险分析报告模块 是否与其他模块功能重复」→ 裁定「做精简，保留新研发的模块」
- 改动文件：`static/index.html`、`static/js/core.js`（**后端与数据库零改动**）
- 结论：**页面级下线完成**，留痕查看能力并入 P0-8 的「审计日志」独立页

---

## 一、为什么精简它（而不是审计日志）

两者**同名不同源**，是**两个层次**：

| 维度 | 📋 系统日志 `/system-logs`（下线） | 🧾 审计日志 `/audit-logs`（保留） |
|---|---|---|
| 数据源 | **文件** `data/logs/access.jsonl` | **数据库表** `audit_logs` |
| 写入方式 | 中间件**每请求自动追加** | 业务代码**显式** `record()` |
| 粒度 | HTTP 请求（URL / 状态码 / 耗时 / IP） | 业务动作（动作码 / 目标对象 / 中文名） |
| 权限 | 无（所有登录用户） | `audit.view`（企业财务 403） |
| 可否删除 | **可一键清空**（直接删文件） | **不可删**（留痕证据） |

**保留「审计日志」（P0-8 新研发）、下线「系统日志」的三个理由**：

1. 审计日志**受权限保护、不可篡改**，符合审计用途；系统日志可被任意登录用户一键清空，不具备证据效力。
2. 系统日志页面**名实不符**：`module-headers.js` 称其记录「引擎全量运行记录 —— 每次分析的完整执行过程」，
   实际读的是 **HTTP 请求日志**（`access.jsonl`），自称与实际不符。
3. 它的「操作」列是**从 URL 猜测**出来的动作（`main.py:521-526`：`if "upload" in path: action="upload"`），
   属于审计日志显式动作码的**弱重复**。

## 二、改了什么（最小改动，2 个文件）

1. **`static/index.html`**（LF 行尾）
   - 删除侧边栏「📋 系统日志」入口 ⇒ 侧边栏 **19 → 18 项**
   - 删除 `<script src="/static/js/system-logs.js?…" defer>` 载入
2. **`static/js/core.js`**（CRLF 行尾）
   - `navigateTo()` 开头加一次性重定向：
     `if (page === 'system-logs') { window.location.href = '/audit-logs'; return; }`
     ⇒ 引擎仪表盘等处既有的 **6 处** `navigateTo('system-logs')` 调用**无需逐处修改**，点击即落到审计日志页
   - SPA 白名单 `_allowedPages` 移除 `'system-logs'`
   - 删除 `switch` 中的 `case 'system-logs': _sR(container, 'renderSystemLogs'); break;`

**有意保留（不删）**：

- `static/js/system-logs.js` 文件本体 —— 改动后**零引用**，保留便于回滚；
- 后端 `/api/system-logs`、`/api/system-logs/clear` 端点，以及 `access.jsonl` 的写入中间件 ——
  删端点会牵动「端点数基线」（现口径 API 206），写入中间件是通用留痕，不宜触动。

## 四、影响与回滚

- **影响**：
  - 侧边栏少 1 项（19 → 18）；
  - 引擎仪表盘中 6 处「系统日志」链接改为跳到审计日志页（语义从"引擎运行日志"变为"业务留痕"，如实说）；
  - 原「系统日志」页的 **HTTP 请求明细**（含 IP、耗时、状态码）在界面上不再可达 —— **数据仍在 `access.jsonl`**，
    需要时可直接读文件。
- **回滚**：还原 `static/index.html` 与 `static/js/core.js` 两个文件即可，后端与数据库未动。
