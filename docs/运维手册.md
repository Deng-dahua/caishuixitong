# 运维手册

> 适用版本：`VERSION` 文件（当前 `2026.10.17`）。本文只写**可执行**的东西：
> 在哪看、怎么启停、出问题按什么顺序查。评估报告里「无运维手册」即指本文缺位。

---

## 1. 启动与停止

| 动作 | 做法 |
|---|---|
| 启动 | 双击 `start8001.bat`（会经守护器 `scripts/serve_supervisor.py` 拉起） |
| 访问 | **`http://127.0.0.1:8001`**（用 `127.0.0.1`，不要用 `localhost`：后者可能解析到 IPv6 `::1`，而服务只绑 IPv4） |
| 停止 | 关闭服务窗口，或结束进程：`Get-CimInstance Win32_Process -Filter "Name='python.exe'" \| Where-Object { $_.CommandLine -match 'uvicorn' } \| ForEach-Object { Stop-Process -Id $_.ProcessId -Force }` |
| 崩溃 | 守护器自动重启（退避 1/2/5/10/30/60 秒）；`data/logs/supervisor.log` 有每次启停记录 |

★ **只允许一个实例**。两个 uvicorn 指向同一个 `security.db` 必然报
`attempt to write a readonly database`（表现为 `/api/auth/me`、建用户随机 500）。
守护器启动前会探端口，占用即拒绝启第二个；手工排查前先确认只有一个进程。

|---|---|
| `data/` | **运行数据根目录**（可用 `APP_DATA_DIR` 改到别处） |

## 3. 五个高频故障

### ① 浏览器打不开 / 连接被拒
1. 看端口：`curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8001/healthz` → 期望 `200`；
2. `000` ⇒ 服务没起。双击 `start8001.bat`，或看 `supervisor.log` 里有没有反复重启；
3. 反复重启 ⇒ 看 `server8001.combined.log` 尾部报错（常见：端口被占、`.venv` 缺失）。

### ② 登录后立刻 401 / 反复跳登录页
- 本地 HTTP 必须 `APP_COOKIE_SECURE=0`（`start8001.bat` 已设）。若手工起服务，务必带上；
- 浏览器时间与服务器时间相差过大也会导致会话判定异常。

### ③ 随机 500（`/api/auth/me`、建用户）
- **先确认只有一个 uvicorn 进程**（见 §1）；
- 仍有 ⇒ 看是否为 `readonly`：`grep -c readonly data/logs/server8001.combined.log`；
- 该问题已在 2026.10.17 修（会话读取改只读主路径 + 不再每连接切 `journal_mode`）。

### ④ 法规库页转圈很久
- 已修（2026.10.17）：正常应 < 100 ms。若又变慢，先看 `static/legal_library.json` 是否被换成超大文件，
  再跑 `python -m pytest tests/test_legal_library_perf.py -q` 看守护判据是否变红。

### ⑤ 资料上传成功但分析没结果
- 资料页看 `parse_status`：`pending` 表示**还没解析**（事故恢复后重新登记的资料就是这种）；
- 点「开始解析」→ 成功后再「开始分析」；解析失败看「解析问题」页签里的行级原因。

## 4. 备份与恢复（S-10 / D-02）

```powershell
# 看现状（份数、最近一次多久前、占用空间）
.venv\Scripts\python.exe scripts\backup_cli.py list

# 立即备份
.venv\Scripts\python.exe scripts\backup_cli.py create --note "上线前"

# 校验某份备份（重算 SHA-256 + 完整性；坏了会明确报出来）
.venv\Scripts\python.exe scripts\backup_cli.py verify 20261017T171809_manual

# 恢复（★ 必须先停服）
.venv\Scripts\python.exe scripts\backup_cli.py restore 20261017T171809_manual --yes
```

- 备份是**在线一致快照**（`VACUUM INTO`），不需要停服；**不含 `uploads/` 原件**；
- 保留最近 14 份（`APP_BACKUP_KEEP`），`pre-restore` 快照永不轮转；
- 恢复前自动生成 `pre-restore` 后悔药；恢复后自动做 `integrity_check` 与行数比对；
- 界面入口：侧栏「💾 备份与恢复」（仅管理员）。

## 5. 每日巡检清单

- [ ] `http://127.0.0.1:8001/healthz` 返回 200
- [ ] `python scripts\backup_cli.py list` → 最近一份 **< 24 小时**
- [ ] `data/logs/server8001.combined.log` 当日无 `500`、无 `readonly`、无 `Traceback`
- [ ] `python -m pytest tests/ -q` 失败集合与基线一致（基线见 `docs/元质量_20261016/23_总收口报告.md`）
- [ ] `python tools/audit_consistency.py` → **ERROR 0**
- [ ] 磁盘剩余空间 > 20%（`data/backups` 会持续增长）

## 6. 发版与回滚

```powershell
# 发版前
python -m pytest tests/ -q            # 以 0 failed 为准（或与基线一致）
python tools/audit_consistency.py     # 必须 ERROR 0
# 改 VERSION + CHANGELOG.md 顶部加一段，然后
git tag -a v2026.10.17 -m "2026.10.17"
```

- 回滚**代码**：`git checkout v<上一个tag>`；
- 回滚**数据**：`backup_cli.py restore <停服后选择一份>`（回代码不自动回数据，两者要分别处理）；
- 数据库无迁移框架 ⇒ 回滚到旧版本代码前，**必须**确认旧代码能读当前表结构（否则先用备份恢复到同版本）。

## 7. 环境变量（常用的几个）

| 变量 | 默认 | 作用 |
|---|---|---|
| `APP_DATA_DIR` | `./data` | 数据根目录（**隔离实例/演练必须改它**） |
| `APP_PORT` | `8001` | 监听端口 |
| `APP_COOKIE_SECURE` | 未设 | 本地 HTTP 必须设 `0` |
| `APP_SESSION_TTL_SECONDS` | `28800` | 会话有效期 |
| `APP_BACKUP_KEEP` | `14` | 备份保留份数 |
| `APP_BACKUP_INTERVAL_HOURS` | `24` | 自动备份间隔（小时） |
