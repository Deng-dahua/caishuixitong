# 服务常驻：开机自启（三个「进不去/出错」问题的根治记录）

- 日期：2026-10-14
- 用户三问：①服务器进不去 ②关闭电脑后服务就进不去 ③点任何模块都出错
- 结论提交：`autostart`（scripts/autostart_server.bat + Startup 指针）

---

## 一、诊断（硬证据）

| 检查 | 结果 |
|---|---|
| 8001 监听 / python 进程 | **无**（服务没在跑） |
| 系统上次开机 | 10-08 16:13（**没有重启过电脑**）⇒ 是**服务窗口被关**，不是电脑没开机 |
| access.jsonl 时间线 | 21:57 还有 `admin` 登录态成功请求（200）⇒ 服务当时正常，随后窗口被关 |
| `/api/accounts` 404 ×29 | 全部发生于 10-08 ~ 今晨 07:27；**当前前端活代码已无此调用**（core.js 只剩说明注释）⇒ 旧时期遗留日志 |
| `/risks` `/reports` `/projects` 页面 404 | 全部集中在 10-13 ~ 今天 17:17 的**旧进程时段**（即此前「侧边栏少 8 项」事故）；17:17 后**再无一条页面 404** |

**⇒ 三个问题一个根**：服务不是常驻的 —— 窗口一关/电脑一关就没了（问题 1、2）；
服务没了或跑着旧进程时，点模块自然报错（问题 3 的两种形态：
「无法连接」＝服务没跑；「404 Not Found」＝旧进程。后者已由
`/healthz` 版本横幅机制化防护——页面顶部会提示"代码已更新需重启"）。

## 二、根治：登录即自启

| 文件 | 作用 |
|---|---|
| `scripts/autostart_server.bat`（入库） | 自启唯一权威：最小化窗口调起 `start8001.bat`（端口已占用则直接开浏览器，不冲突） |
| `启动文件夹\caishuixitong-server.bat` | 固定指针，登录 Windows 即触发上一行 |
  （`C:\Users\Administrator\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\`） | |

**行为**：每次登录 Windows ⇒ 服务自动以最小化窗口启动 ⇒ 约 7 秒后浏览器自动打开
`http://127.0.0.1:8001`。**关闭那个最小化窗口仍是停止服务**；下次登录自动回来。
**停用自启**：删除启动文件夹里的 `caishuixitong-server.bat` 一个文件即可。

## 三、验证（模拟开机实测）

执行启动文件夹脚本 ⇒ 服务起 ⇒ `/`、`/login`、`/documents`、`/analysis`、
`/risks`、`/reports` **全部 200**（含此前 404 的页面）。
两个 bat 均为 **纯 ASCII + CRLF**（nonascii=0、bareLF=0，遵守 bat 行尾铁律）。

## 四、遗留说明

- 「点击模块出错」若在服务**运行中**再次出现：页面顶部会先出现黄色
  「版本落后」横幅（旧进程防护，Batch-3 机制化）——按横幅提示重启服务即可；
  若无横幅仍报错，把报错截图发我，`data/logs/server8001.combined.log` 里一定有记录。
- `start8001.bat` 的端口占用检测保证：自启已在跑时，手动再双击只会打开浏览器，不会报错。
