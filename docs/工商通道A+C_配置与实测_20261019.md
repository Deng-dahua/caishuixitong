# 工商信息通道 A + C：配置与实测（2026-10-19）

> 本文回答「工商通道怎么配、配完能取到什么、取不到时系统会怎么说」。
> 全部结论对应代码与配置的**唯一权威**，可逐条复核。
> 前序核实（为什么不用 B/D、六源实测 HTTP 码）见 `docs/核实_工商渠道与五类报告_20261019.md`。

## 一、用户裁定

工商通道走 **A + C**：

| 路线 | 实现 | 定位 | 是否免费 | 是否需人工 |
|---|---|---|---|---|
| **A** | `manual_cookie`（人工过验证码后配置 cookie） | 免费基线 | 免费 | 配置时需人工一次 |
| **C** | `paid_api`（付费数据服务 token） | 覆盖率兜底 | 按量计费 | 否 |

**不采用**（已登记在配置 `channel_plan.retired`，不再是"待办"）：
- **B** 地方市监/税务公开数据逐省适配 —— 30+ 省市各一套页面，维护成本与覆盖缺口不成比例；
- **D** 搜索引擎兜底 —— 只能给"线索"，**不能作为工商登记字段来源**；仅保留在
  `engine/external_verifier` 作旁证，**不进本通道链**。

通道顺序（配置 `providers` 即唯一顺序权威）：
`local_db`（离线）→ `manual_cookie`（A，免费）→ `paid_api`（C，付费）。

## 二、配置权威：`config/business_info.json`

代码里**没有任何** URL / token / 环境变量名 / 超时字面量，改行为只改这个文件。

```jsonc
"providers": ["local_db", "manual_cookie", "paid_api"],

"channel_plan": {
  "routes": { "A": "manual_cookie", "C": "paid_api" },
  "retired": { "B": "…", "D": "…" }
},

"manual_cookie": {           // A 通道
  "search_url": "https://www.gsxt.gov.cn/corp-query-search-1.html",
  "cookie_env": "GSXT_COOKIE",     // 只从环境变量读，不落盘
  "cookie_required": true,
  "min_cookie_len": 12,
  "anti_bot_markers": ["验证码", "滑动验证", "…"]   // 命中即判"被风控"，如实失败
},

"paid_api": {                // C 通道
  "token_env":     "BUSINESS_API_TOKEN",       // Bearer token
  "provider_env":  "BUSINESS_API_PROVIDER",    // 服务商标识（tianyancha / qichacha / …）
  "base_url_env":  "BUSINESS_API_BASE_URL",    // 查询接口地址（按服务商文档填）
  "insecure_tls_env": "BUSINESS_API_INSECURE_TLS",
  "timeout_sec": 6.0
},

"source_confidence": {       // 各通道置信度（唯一权威，代码不写死）
  "local_db": 0.95, "manual_cookie": 0.85, "paid_api": 0.9, "default": 0.7
}
```

## 三、A 通道怎么配（免费）

1. 用浏览器打开 `manual_cookie.search_url`，**人工通过验证码/滑块**；
2. 复制该站请求头里的 `Cookie`；
3. 写入环境变量 `GSXT_COOKIE`（Windows：`setx GSXT_COOKIE "…"`，然后**重开服务**）；
4. 访问 `GET /api/v1/business/channels` 确认 `manual_cookie.available = true`。

配置后该 cookie 可**无人值守复用至失效**；失效时系统会返回
`HTTP 521（公示系统风控拒绝）⇒ Cookie 可能已失效：请重新按【A 通道】人工过验证码后更新 GSXT_COOKIE`。

**未配置时不发请求**：直接如实失败并给出上面这段可执行步骤（不浪费一次注定被拦的请求，
也不让用户看到"不知道怎么办"的失败）。

## 四、C 通道怎么配（付费）

```bash
# 三个变量，缺一不可
export BUSINESS_API_TOKEN="…"                      # 服务商控制台签发的 token
export BUSINESS_API_BASE_URL="https://…/query"     # 该服务商的查询接口（不在代码里写死）
export BUSINESS_API_PROVIDER="tianyancha"          # 或 qichacha / 服务商标识
```

- 请求形态：`GET {BASE_URL}?keyword=<企业全称>&provider=<PROVIDER>`，头 `Authorization: Bearer <token>`；
- 响应字段经 `engine.business_info.dto` **统一清洗**（别名表已覆盖 `entname/oper_name/regcap/
  esdate/reg_status/dom/enttype/opscope` 等常见服务商字段名与中文标签）⇒ **不在通道内另立字段口径**；
- 未配置 token 或地址 ⇒ 如实失败并**列出缺哪个变量**，不假装已对接、不静默降级。

> ★ 本仓 `engine/external_verifier.TianyanchaVerifier/QichachaVerifier` 是**另一条链**
> （一键分析报告的外部核验章），当前**如实标注 `not_integrated`** —— 即使配了
> `TYC_TOKEN` 也用不了（缺接口实现与法务确认）。要真取数请走本节的 C 通道。

## 五、`local_db` 的真相（必须说清，否则会误判）

`local_db` 是**唯一 100% 可用**的通道，也是"自动查填"在未配 A/C 时**唯一**的数据来源。
但它**不是外网来源**：数据来自 `companies` 表 —— 用户建稽查项目时自己填进去的
（`engine/project_service.py` 建项目时写入）。`local_db` 只是把它读回来。

⇒ 对**新企业**（本地库没有）它**不产生任何新数据**。这也是识别"自动查填到底有没有生效"的关键：
前端现在会在来源为 `local_db` 时明确标注
**「取自本系统已有档案（非外网核验；新建企业请配 A/C 通道）」**。

## 六、怎么确认"现在哪条通道真能用"

`GET /api/v1/business/channels`（需 `project.write` 权限，只读、不触发外网、**不回显密钥值**）：

```json
{"providers": ["local_db","manual_cookie","paid_api"],
 "plan": {"routes": {"A":"manual_cookie","C":"paid_api"}},
 "items": [
   {"provider":"local_db","available":true,"note":"…离线读本系统已有数据…"},
   {"provider":"manual_cookie","route":"manual_cookie","configured":false,"available":false,
    "note":"未配置环境变量 GSXT_COOKIE ⇒ 实测公示系统返回 HTTP 521（风控），取不到登记字段…"},
   {"provider":"paid_api","route":"paid_api","configured":false,"available":false,
    "note":"未配置 BUSINESS_API_TOKEN / BUSINESS_API_BASE_URL ⇒ C 通道未启用…"}]}
```

界面与文档都应**从这里取事实**，而不是写"4 通道工商数据验证"这类能力声称。

## 八、本轮修掉的真实缺陷（验收抓出来的）

**A 通道解析器把标签当值**：旧写法
`val = ln.split("：", 1)[-1].split(":", 1)[-1].strip()` 在**行内没有冒号**时会**原样返回整行**
⇒ `<td>统一社会信用代码</td><td>9144…</td>` 这种公示系统真实结构下，
`tax_id` 被存成「统一社会信用代码」这个**标签**。

它比缺字段更危险：`raw` 看着有值，后续清洗会报"格式不合 18 位"，读者会以为页面结构变了。
现按三种形态分别取值（冒号 / 空白 / 行恰好等于标签→取下一行），并加「**绝不把标签本身当值**」兜底。

---

## 九、仍然做不到的（如实）

- **无人值守 + 免费 + 完整登记字段**：三者当前**不可兼得**。A 要人工过验证码，C 要付费。
- 公示系统风控策略会变，"今天 521"不等于"永远 521"；cookie 也会失效，需重配。
- 付费服务需要**商务账号 + 法务确认调用范围** —— 这不是代码能解决的事，代码侧只保证
  "配了就能用、没配就如实说"。
