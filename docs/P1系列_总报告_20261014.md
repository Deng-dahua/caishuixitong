## 二、贯穿一致的实施纪律（每个子任务都遵守）

### 2.1 唯一权威 + 薄转发
每个能力的判据点只有一处；调用方只薄转发，不复制逻辑。
- `parse_enhance`：行数上限登记 + 顺序游标 + 截断回执
- `ocr_engine`：引擎登记 + 可用性状态 + 运行留痕 + 置信度阈值
- `extract_validate`：`RULES` 即规则清单（与 `config/standard_fields.json::_validation` 同集合）
- `risk_review`：5 态状态机 + `bulk_review`
- `template_store`：内置（只读 config）⊕ 台账覆盖
- `rule_versions`：`rule_set_version()` 是"当前生效版本"的**唯一判读点**

### 2.2 缺失 ≠ 0
- `safe_nrows`：取不到行数返回 0 并如实标注，不伪造；
- `truncation_note`：`total` 未知 ⇒ **不产回执**；
- `diff`：缺快照 ⇒ `comparable=false` + 原因，**不返回空差异**；
- `review_stats`：「从未处置」与「超期」**分开计**（前者没有起点）；
- 模板 / 版本查不到 ⇒ `None` + 原因，**不返回空对象**。

### 2.3 零行号漂移
`main.py` **15156 行不变**（所有接线与薄转发都在**同一行内**完成）；
`tools/audit_consistency.py` 的 D1 锁定行 **11542 / 12008 / 12948 / 12951 零漂移**。

## 三、新增 6 条常驻闸门

全部在 `run_checks()` 末尾**同行内**挂接（保 D1 锁定行零漂移）：

| 闸门 | 锁住什么 |
|---|---|
| `check_row_cap_manifest` | ① 上限登记表 ↔ `main.py` 实测集合一致（双向）；② `_get_row_values` 必须走顺序游标（**防 O(n²) 回归**）；③ `nrows` 必须经 `safe_nrows`（**含防"局部绕过"判据**） |
| `check_ocr_engine_single_source` | ① 不得有裸 `return "\n".join(chunks)`（防绕过治理层）；② 三引擎必须登记；③ 接线完整 |
| `check_extract_rules_sync` | ① `RULES` ↔ 配置说明表同集合；② 规则数 ≥ 12；③ 每条必须有中文名 |
| `check_review_flow_wiring` | ① 能力存在；② 三个端点存在；③ **路由顺序**（字面量段早于 `{risk_id}`）；④ 审计动作已登记 |
| `check_template_manage_wiring` | ① 能力存在；② **内置集合 == config 集合**；③ 接线完整 |
| `check_rule_version_manage_wiring` | ① 能力存在；② **未发布时生效版本 == 配置基线**；③ 审计动作；④ 接线 + 路由顺序 |

## 五、未完成 / 风险（汇总，各子任务细节见各自报告）

**P1-1**：单文件 10 万行仍受既有 5000 行/表上限约束（**未改**，因属既有设计）；
上限值仍是 `main.py` 30+ 处裸字面量（本轮只做"登记 + 闸门"）。

**P1-2**：未做结果缓存（同一扫描件重复解析会重复 OCR）；留痕仅存进程内（重启清空，已在接口声明）；
置信度仅统计不拦截（"宁可给可疑文本 + 标注，也不静默丢字"，需业务确认）。

**P1-3**：12 条规则**全部常开**（未做规则开关）；`severity` 未分级细化（统一 warning）。

**P1-4**：勾选不跨页；超期只提示不阻断；批量不支持"每条形参不同"。

**P1-5**：模板与行业 `industry_params` 的映射仍走 config（未做在线映射编辑）；无模板预览。

**P1-6**：发布不校验"规则内容真的变了"；**回滚不自动恢复 config**（只改生效标记与台账）——
这是当前设计的边界；快照是"版本标记"而非"规则内容"。
