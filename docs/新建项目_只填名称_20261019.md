# 新建项目：只填企业名称 → 保存时自动加载（2026-10-19）

> 用户原话：
> 「新建项目我只要填写企业名称，然后按保存，其余信息在按保存按钮时自动加载！！！
>   且新建项目页面的内容仅是工商登记信息，唯一需要注意的是行业信息可能在分析资料后
>   与工商信息不一致，则以分析资料后确定的行业为准！！！」

---

## 一、你会看到什么

点「新建项目」，弹窗里**只有一个可填的框**：

```
企业工商登记信息
只需填写企业名称，点「保存」时系统会自动加载其余工商登记信息
  企业名称 *   [ 深圳海更数字传媒有限公司        ]   ← 唯一可编辑
  统一社会信用代码 [                    ]（灰）自动加载
  法定代表人       [                    ]（灰）自动加载
  注册资本         [                    ]（灰）自动加载
  成立日期         [                    ]（灰）自动加载
  登记状态         [                    ]（灰）自动加载
  公司类型         [                    ]（灰）自动加载
  注册地址         [                    ]（灰）自动加载
  经营范围         [                    ]（灰）自动加载
```

- **稽查要素整块不在新建页上**（行业/地区/期间/税种/备注）——新建页面内容仅是工商登记信息；
- 填名称 → 点「保存」→ 系统**先**去查工商信息、填进上面那些灰框，**再**提交建项目；
- 保存后的提示会如实告诉你**到底加载到了什么**：
  - 成功：`项目已创建：已自动加载 6 项工商信息（来源：本地账套库（companies））`
  - 失败：`项目已创建（仅企业名称）：工商信息未能自动加载 —— 未配置 Cookie（环境变量 GSXT_COOKIE）…`
    （逐通道原因来自后端，不是一句"查询超时"）

**编辑项目**仍然全字段可编辑、稽查要素可见——自动加载错了要能改。

---

## 二、为什么这样改（不是"少画几个框"）

### 2.1 旧实现与用户要求**直接冲突**

旧 `saveForm()` 的校验：

```js
if (tid.length !== 18) { showFormError("统一社会信用代码必须为 18 位"); return; }
var lack = []; if (!industry) lack.push("行业"); ... if (!scopes.length) lack.push("税种范围");
if (lack.length) { showFormError("请补全稽查要素（第 2 步）：" + lack.join("、")); return; }
```

⇒ **五个字段全部必填**，只填名称根本保存不了。

而**后端一直是允许的**（`project_service.create_project` 注释写明）：

> 「**项目自持企业身份** —— 新建只收「公司名称 + 统一社会信用代码」两项；
>   行业/地区/期间等信息由**自动分析确定**」
> 「税号缺失 ≠ 税号填错 …… 缺失则留空，由 `profile_missing` 如实标注「待补全」」

⇒ 这是**前端比后端严**的不一致：用户被前端挡住了后端本来就允许的操作。

### 2.2 改法（三处，各司其职）

| 位置 | 改动 |
|---|---|
| `static/projects.html` | 稽查要素整块包进 `<div id="sect-audit" hidden>`；工商字段去掉必填星号、占位改为「自动加载」 |
| `projects.js::_applyFormMode` | **形态唯一切换点**：新建态藏稽查要素 + 工商字段 `disabled`；编辑态全部复位 |
| `projects.js::saveForm` | 新建态**先** `await fetchBizInfo({force:true})`，**再**提交；校验只留「名称必填 + 税号填了才校验18位 + 期间不倒置」 |
| `projects.js::bind` | 新建态**不再边打字边查**（用户要的是"按保存时"）；编辑态保留即时查 |

`fetchBizInfo` 同步改造：
- 返回值从"什么都不返回"改为**结构化结果** `{ok, filled, kept, missing, source_detail, …}` —— 保存流程要据它决定提示；
- 新增 `opts.force`（保存时绕开"同名已查过"去重）与 `&refresh=1`（绕开缓存）。

## 三、行业：以**分析资料后确定的**为准

### 3.1 三个来源，优先级是固定的

| 序 | 来源 | 说明 |
|---|---|---|
| ① | 分析资料后算出 `_industry_resolved` | **最高**（用户裁定） |
| ② | 经营范围/企业名称推断（工商口径） | 次之 |
| ③ | 人工填写 | 新建时不再要求填；编辑时可改 |

落地链：分析完成 → `main._persist_one_click_result`
→ `project_profile_fill.analysis_values`
→ `project_service.sync_profile_from_analysis`（**有出入即写** `projects.industry`）。

### 3.2 实测（工商口径「五金零售」vs 资料口径「文化传媒」）

```
行业 = 文化传媒 ｜ 来源 = 分析结果（发票品名+经营范围）
note = 工商登记口径与资料不一致，采用资料口径
```

### 3.3 容易踩反的一点（已加闸门）

本仓对 **稽查期间 / 税种范围** 是"**只在项目未设时才补**"（那是人定的工作边界），
很容易被**错误地复制到行业上** —— 一旦给 industry 加"已存在就不覆盖"守卫，
用户裁定就被静默推翻，而**页面看起来一切正常**。

⇒ 新增闸门 `check_analysis_industry_overrides_registered()`：
- 行为级：构造"工商口径 vs 资料口径冲突"，断言取资料口径；
- 源码级：`sync_profile_from_analysis` 里**任何** `if ... r.get("industry") ...: continue` 的守卫 ⇒ ERROR。

## 四、验收（结果级 + 反向）

```bash
.venv/Scripts/python.exe scripts/_verify_new_project_name_only.py
```

**32 项全部通过**：

| 组 | 判据 |
|---|---|
| ① 静态形态 | 稽查要素整块在 `hidden` 容器内；隐藏块内无 `*` 必填标记 |
| ② 编辑态 | `_applyFormMode` 切换正确；禁用清单 8 项且**不含企业名称**；新建态输入/失焦不触发查询 |
| ③ **保存顺序** | Node 桩真跑 `saveForm()`，调用序列必须是 `['查询', …, '建项目', …]`，且查询带 `refresh=1` |
| ④ 只填名称能建成 | `POST /api/v1/projects` 仅传 `{name}` ⇒ **201**，税号留空，`profile_missing` 如实列出 5 项 |
| ⑤ 行业以分析为准 | 冲突用例取「文化传媒」；表单上写明该口径 |
| ⑥⑦⑧ 反向 | 改回"稽查要素可见" / 改成"先 POST 后查询" / 给 industry 加守卫 ⇒ **均必须变红**（已验证） |

## 五、本轮修掉的**判据/桩自身缺陷**（5 处）

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | 判据只扫 `_applyFormMode` 函数体，而 `BIZ_INPUT_IDS` 定义在**函数外** | 报"清单不足 8 项"（假红） | 取常量声明段 |
| 2 | 桩缺 `Headers` | `api()` 在发请求前就抛错 ⇒ "保存时什么请求都没发"（假红） | 补 `Headers` |
| 3 | 桩缺 `RBAC` | `bizAllowed()` 恒 false ⇒ 不查工商（假红） | 注入权限桩 `{loaded:true, permissions:{'project.write':true}}` |
| 4 | 桩的 `value` 是普通属性，可被赋成 number | 自动加载写入 1000（number）⇒ 保存时 `.trim()` 抛错（假红） | `Object.defineProperty` 让 `value` 永远返回字符串（**与真实 DOM 一致**） |
| 5 | 闸门只认 `if not ...r.get("industry")` 一种写法 | 漏掉 `if key=="industry" and ...: continue`（同样挡住覆盖） | 按语义匹配任意 `if … r.get("industry") …: continue` |

> ★ 共性教训：**桩越接近真实浏览器，越不容易把产品判成错**；
>   `input.value` 恒字符串、`Headers`/`RBAC` 必存在 —— 这三条都真踩过。

另有一处**测试锚点随需求失效**：`test_project_profile_autofill.py` 的反向验证锚点写死了
`统一社会信用代码 *`（带星号），本轮星号移除后锚点失效、该反向验证变成空转。
已改用唯一不变的锚点（`id="pf-tid"` 标签开头），判据本身未动。

## 六、仍然做不到的（如实）

1. **工商信息取不到时项目照样能建成** —— 这是刻意的（否则通道故障就彻底用不了系统），
   代价是"只有名称的项目"会带着 `profile_missing` 待补；补资料分析后由回写链补齐。
2. 新企业的完整登记字段仍取决于工商通道：`local_db` 只回读本系统已有档案，
   外网需 A（`GSXT_COOKIE`）或 C（付费 token）—— 见 `docs/工商通道A+C_配置与实测_20261019.md`。
3. 稽查要素在新建页**不可见**，所以「用户在这里纠正系统推导的行业」这条路被取消了；
   纠正入口统一在**编辑页**（打开即按分析结果补全并逐项说明来源）。
