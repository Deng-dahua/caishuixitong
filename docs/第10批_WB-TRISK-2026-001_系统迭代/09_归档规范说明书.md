# 09 · 归档规范说明书

> 指令：WB-TRISK-2026-001 §3.3（归档规范性）
> 唯一权威：`config/archive_spec.json`（规范数据表）+ `engine/numbering.py`（编号服务）

---

## 一、为什么必须有这一份

基准样本（Word 导出件）实测的归档缺陷：

| 缺陷 | 实测证据 |
|---|---|
| 无底稿编号 | 全文无 `WB-TR-*` 形态编号 |
| 无风险编号 | 16 项风险事项全部只有 `seq`，无 `WB-R-*` |
| 无证据编号 | 报告内无 `evidence_chain.elements`，证据以角色名承载 |
| 无页眉页脚页码 | 导出物内未见「第 N 页 / 共 N 页」；`static/` 全域无 `@page` 页眉页脚、无 `counter(page)` |
| 无七类索引 | 只有文本型「附件二：资料与回执索引」 |
| 复核签署不全 | `signature_block` 缺「批准人」 |
| 无审计轨迹 | 有版本台账 `data/report_versions.jsonl`，但**缺"谁"**；正文编辑无落盘 |
| 无归档导出包 | 导出包接口返回内存 JSON，非可下载包 |
| **死链与交互残留** | 文档内残留 5 个 `HYPERLINK "http://127.0.0.1:8001/" \l "#company-*"` 锚点；「点击展开」「下载 CSV」在导出物中不可用 |

## 二、底稿编号规则

```
总底稿：  WB-TR-<企业代码>-<期间>-<版本>         例：WB-TR-91440300MA5H824G7M-202601-01
分项底稿：WB-R-<企业代码>-<期间>-<序号>         例：WB-R-91440300MA5H824G7M-202601-007
证据：    WB-EV-<企业代码>-<期间>-<序号>
资料缺口：WB-GAP-<企业代码>-<期间>-<序号>
法规：    WB-LAW-<税种代码>-<序号>               例：WB-LAW-VAT-003（法规为全局对象，不含企业与期间）
附件：    WB-ATT-<企业代码>-<期间>-<序号>
索引：    WB-IDX-<企业代码>-<期间>-<序号>
整改台账：WB-RC-<企业代码>-<期间>-<序号>
```

- 企业代码优先取**统一社会信用代码**，回退 `company_id`；为空记 `NA`。
- 期间格式 `YYYYMM`；取不到时回退 `000000`（并应在门禁报错，不得静默）。
- **连续性约束**：起点 1，逐项 +1，不跳号、不重号，`max(seq) == 项数`。

## 三、页眉页脚

| 区域 | 必需 | 内容 | 渲染式 |
|---|---|---|---|
| 页眉 | 是 | 企业名称 / 统一社会信用代码 / 检查期间 / 底稿编号 | `{company_name}｜统一社会信用代码：{uscc}｜检查期间：{period}｜底稿编号：{wp_no}` |
| 页脚 | 是 | 页码 / 总页数 / 密级 / 版本 / 生成日期 | `第 {page_no} 页 / 共 {total_pages} 页｜密级：{level}｜版本：{v}｜生成日期：{date}` |

密级档：内部 / 商业秘密 / 机密（默认 `商业秘密`）。
字段缺失时以「未提供」占位并在门禁记 ERROR，**不得留空**。

> ⚠ **现状**：页眉页脚与页码**未实现**（C6 报 SKIP）。实现方式已在
> `config/archive_spec.json → render_layer.page_css` 登记为要求：`@page` + `counter(page)/counter(pages)`。

## 四、七类索引

| 索引 | 编号规则 | 必需 | 字段 |
|---|---|---|---|
| 风险索引 | `WB-R` | ✔ | risk_no / title / risk_level / conclusion_grade / closure |
| 证据索引 | `WB-EV` | ✔ | evidence_no / risk_no / role / name / status / source_file / sha256 |
| 资料缺口索引 | `WB-GAP` | ✔ | gap_no / material_name / impact / remedy / alternative |
| 法规索引 | `WB-LAW` | ✔ | law_no / tax_code / title / clause / version_status |
| 金额索引 | — | ✔ | fact_id / label / value / scope / tax_inclusive / period / source / derivation |
| 附件索引 | `WB-ATT` | ✔ | attachment_no / name / pages / source_file / sha256 |
| 整改台账索引 | `WB-RC` | ✔ | rectify_no / risk_no / action / owner / due / deliverable / status |

**金额索引**直接由 `engine/fact_store.py::amount_index_rows()` 产出（与事实库同源）。

## 五、复核签署

| 角色 | 中文名 | 日期字段 |
|---|---|---|
| `prepared_by` | 编制人 | `prepared_date` |
| `reviewed_by` | 复核人 | `reviewed_date` |
| `approved_by` | 批准人 | `approved_date` |

附加：复核意见 / 修改记录 / 版本号。任一缺失记 ERROR。
**实测**：基准样本 `signature_block` 缺「批准人」⇒ C7 报红。

## 六、审计轨迹

- **追加写**（append-only），四要素缺一不可：**谁 / 何时 / 改了什么 / 为什么改**。
- 每条记录字段：`at / operator / action / target / before / after / reason /
  source_data_version / rule_version / template_version / skill_version`。
- `operator` 必须是**可识别主体**，不得用角色名顶替。
- **现状缺口**：`report_compliance.record_version()` 有 `generated_at/change_note/version/reviewed/redaction_role/generator`，
  **无 `operator`（谁）**；前端正文编辑无落盘。

## 七、归档导出包

```
WB-TR-<企业>-<期间>-<版本>_package_<ver>/
├── manifest.json          # 清单（成员 + 哈希 + 版本）
├── 01_正式版.pdf
├── 02_可编辑版.docx
├── 03_数据包.xlsx
├── 04_证据附件包.zip
├── 05_索引.json
└── 06_版本对比.md
```

命名：`{workpaper_no}_package_{version}`；清单字段 `manifest.json`。
**现状缺口**：`/api/agi/report/export?format=package` 返回内存 JSON dict，非可下载文件包。

## 八、渲染层降级（本轮新发现的硬伤来源）

基准样本是**本系统报告页经 WPS 导出为 Word** 的产物（文档内残留
`http://127.0.0.1:8001/` 锚点 5 个）。HTML 交互元素被原样搬进交付物：

| HTML 里的东西 | 在交付物里变成 | 对应门禁判据 |
|---|---|---|
| 5 个页面内导航锚点（在 Word 里是**连不到本机服务的死链**） | 5 个导航标签被压成**一整行连排的"目录"**，无换行、无页码 | D10（目录须由正文标题生成） |
| 折叠面板「点击展开」 | 2 张**表头为空、68 行/26 行全空**的表格，且点不开 | D9（空表策略） |
| 「下载 CSV」按钮 | 正文出现 `下载 CSV` 文字（2 处），无链接 | D1（UI 残留） |
| 内联样式 / Markdown | `**同时出现**`、`**已查明的风险**` 等 **`**` ×53** 直接进入正文 | D4（Markdown 残留） |

**降级规则**（`archive_spec.render_layer`）：
1. **目录**必须由**正文标题**生成（单一来源），需页码；禁另写一份目录文案。
2. **空表**：折叠面板要么展开为完整表格，要么整段省略；**不得输出空表头或全空行**。
3. **禁止出现在导出物中的词**：下载 CSV / 点击展开 / 导出 / 复制 / 展开 / `127.0.0.1` / `localhost`。
4. **Markdown 标记**必须转为真实排版（加粗/斜体）。
5. **内网锚点**必须剔除或转为书签。

> 这条同时解释了基准样本「目录括注与正文标题不一致」的机制：
> **目录文本来自 HTML 导航锚点标签，章节标题文本来自另一处** —— 与"缺什么资料被算三遍"
> 同属**同一概念多头维护**。故规则 1 要求目录必须以正文标题为单一来源。
