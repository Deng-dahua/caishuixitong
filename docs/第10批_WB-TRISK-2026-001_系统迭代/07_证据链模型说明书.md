# 07 · 证据链模型说明书

> 指令：WB-TRISK-2026-001 §3.1（证据链闭合度）
> 唯一权威：`engine/evidence_chain.py`（链与闭合度）+ `engine/constituent_checkpoint.py`（要件级）+
> `engine/conclusion_grade.py`（结论分级与一票否决，本批新增）

---

## 一、模型

```
风险事项（finding / redline）
  └─ 构成要件（constituent，1..N）
        └─ 证据角色（element.role）
              └─ 证据状态（element.status）
                    └─ 结论（verdict / conclusion_grade）
```

映射到数据：`report_data.enterprise_readable_report.confirmed_problems[]`
——每项即一个「风险事项」，其 `evidence_chain.elements[]` 为证据角色列表。

## 二、证据角色（指令要求 5 类）

| 指令要求 | 现状 | 落点 |
|---|---|---|
| 直接证据 | ✅ 已有 | `evidence_chain._ROLE_WEIGHT["直接证据"] = 3` |
| 间接证据 | ✅ 已有 | `_ROLE_WEIGHT["间接证据"] = 2` |
| 资金证据 | ✅ 已有 | `_ROLE_WEIGHT["资金证据"] = 2` |
| 反证 | ✅ 已有 | `_ROLE_WEIGHT["反证"] = 1`（不计入分母） |
| **替代证据** | ⚠ **未建** | 本批以 `config/alternative_evidence.json` 登记「缺 A 可补 B/C/D」；**作为角色枚举入链为 P1** |

**缺口说明**：替代证据目前以"补救建议"形态存在（`missing_material_names` + 替代库），
尚未成为 `elements[]` 的一个角色，因此不参与权重与闭合度计算。这是本批诚实记录的未达标项。

## 三、证据状态（指令要求 5 类）

唯一权威 = `engine/data_source_status.py::STATUSES_ALL`

| 指令要求 | 现词表值 | 说明 |
|---|---|---|
| 已取得 | `已有` | 参与闭合度分子 |
| 待核对 | `须核对` | 按 0 计（不计入分子） |
| 缺失 | `缺失` | 触发一票否决 V3 若为直接证据 |
| 待企业提交 | `待企业提交` | 反证专用态 |
| 不适用 | `本业态不适用` | 业态剔除；不进 elements |

> ⚠ 注意：`evidence_chain` 内部的元素级状态只用了三态（`已有/待核/缺失`），
> 与 `data_source_status` 的五态通过 `_material_status()` 转发对齐。**这不是两套词表**，
> 但存在"三态→五态"的映射层，需在改动时同步（已登记为 A6 判据：表外词一律 ERROR）。

## 四、闭合度计算（唯一权威）

```
need      = Σ weight(role ≠ 反证)
got       = Σ weight(role ≠ 反证 且 status == 已有)
closure   = round(min(1, got / need), 2)
```

- 落点：`engine/evidence_chain.py`
- 冗余字段：`evidence_have`（= got 的角色数）、`evidence_need`（= need 的角色数）
- **自洽要求（B9）**：`closure == round(evidence_have / evidence_need, 2)`，容差 0.02。
  基准样本 **4 项不自洽**（如项4 `closure=0.38` 但 `1/4=0.25`）—— 说明闭合度存在"两处各算一遍"，
  本批以 B9 锁死。

### 阈值与结论的绑定

| 条件 | 允许的最高结论 | 判据 |
|---|---|---|
| `closure = 0` 或 `evidence_have = 0` | L2 待核线索 | A1（一票否决 V1/V5） |
| `closure < 0.80` | L2 待核线索 | A9（V2） |
| `closure ≥ 0.80` 且无直接证据缺失 | 可达 L3 风险事项成立 | A2（L3 门槛） |
| 直接证据缺失 | 禁定性词 | A3（V3） |
| 未登记 `conclusion_grade` | — | A4（ERROR） |

## 五、关键证据一票否决（本批新建）

判据表：`config/conclusion_grades.json → veto_rules`

| ID | 触发条件 | 含义 |
|---|---|---|
| V1 | `closure == 0` 或 `evidence_have == 0` | 无任何证据被取得 |
| V2 | `closure < min_closure (0.80)` | 证据链未闭合 |
| V3 | `direct_missing` 为真 | 直接证据缺失 |
| V4 | `missing_material_names` 非空且未登记替代资料 | 关键资料缺失且无替代程序 |
| V5 | `closure`/`evidence_have` 未登记 | 等级无证据支撑 |
| V6 | `conclusion_grade` 缺失 | 结论等级未登记 |

**否决后处置**（`on_veto`）：`risk_level ≤ 待核验`；`conclusion_grade → L2`；
追加「（关键证据缺失，本项不作认定）」；门禁严重度 ERROR。
实现：`engine/conclusion_grade.apply_veto()`（不改入参，返回新 dict；旧口径存 `conclusion_grade_legacy`）。

**与禁词表的耦合**（本次关键修复）：
原实现只有全局禁词（`text_guardrails`），**不区分本项证据是否缺失**——即"证据缺失"只降 verdict，
不触发文本层拦截。本批把 `determinative_words` 与 veto 触发**代码级耦合**：
命中 veto 且正文含定性词 ⇒ A3 报 ERROR。
（基准样本 16/16 项命中，因为 16 项的 `verdict` 都含「已查明」。）

## 六、结论四级分级（本批新建）

唯一权威：`config/conclusion_grades.json` + `engine/conclusion_grade.py`

| 级 | 名称 | 判据 | 允许等级 | 系统可输出 |
|---|---|---|---|---|
| L1 | 风险指标命中 | 仅触发条件命中，未做要件核对 | 信息 / 待核验 | ✅ |
| L2 | 待核线索 | 有信号但要件未逐条成立，或关键证据缺失 | 待核验 / 低风险 | ✅ |
| L3 | 风险事项成立 | 要件成立 且 `closure ≥ 0.80` 且无直接证据缺失 | 低/中/高/极高风险 | ✅ |
| L4 | 违法认定 | 行政机关依法定性 | — | ❌ **引擎遇 L4 一律降为 L3 并标注** |

### 与既有裁决词的映射（双向校验）

`engine/argumentation.py` 的 9 个常量全部登记到 `verdict_mapping`，
由 `verdict_vocab_consistency()` 断言"一个都不能漏"。
**实测抓到的漂移**：本模块首版 config 键写「（资料齐全，可**初步**判断）」，
而常量是「（资料齐全，**可作**初步判断）」——差一个「作」字，整条映射失效。

## 七、替代程序库（本批新建）

文件：`config/alternative_evidence.json`；键 = `engine/material_names.CATEGORIES` 的 **14 类权威类别名**（禁自造）。

示例：

| 缺失资料 | 可替代取得的等价资料 | 替代的边界（不能证明什么） |
|---|---|---|
| 合同文件 | 订单/委托单、结算单/对账单、验收单/交付确认单、往来邮件或即时通讯记录、付款银行流水、立项/报价与中标文件 | 可印证业务真实发生与交易要素，但不直接证明合同条款（账期、定价机制） |
| 企业所得税申报表 | 汇算清缴纳税调整底稿、纳税调整项目明细表、弥补亏损明细表（A106000）、完税凭证、申报表主表及附表 | 可核对纳税调整与亏损弥补，但缺主表时无法确认申报口径与应纳税所得额 |
| 资产负债表 | 科目余额表、净资产计算表及底稿、审计报告、银行询证函回函、往来明细账及账龄 | 可推导资产负债结构与净资产，但无法替代审计意见与口径调整 |

门禁 A7：`missing_material_names` 非空时必须给出本库登记的具体替代资料名（当前 WARN；P1 升 ERROR）。
