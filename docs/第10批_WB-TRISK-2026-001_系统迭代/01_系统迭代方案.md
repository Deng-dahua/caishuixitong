## 五、设计要点（为什么这么做）

### 5.1 扫描域必须白名单化
`report_data` 里混着**上传的原始文件内容**（一份 HTML 含 `<script>`、CSS、`{"p":"link"}`）、
内部质量自检告警与 pipeline 轨迹。把这些当"报告正文"扫 ⇒ 海量假红。
故设 `config/quality_gates.json → scan_domain`（`mode: allowlist`），并且**默认白名单**（新增键不会被自动纳入扫描）。

### 5.2 SKIP ≠ PASS
`policy.skip_is_not_pass: true`。取不到数据必须报 SKIP 并写明原因，SKIP 计入未通过。
理由：本轮基准样本的 `release_status=草稿_待人工复核`、`_quality_gate.gate_passed=False`
——**系统其实早就在报"没通过"，但外部看到的是"分析已完成"**。SKIP 必须显性化。

### 5.3 判据表与实现的双向约束
- `config/quality_gates.json` 是判据**唯一权威**（38 条）。
- 实现侧用 `check_id` 字符串落地；口径锁 `test_every_check_id_has_entry_point` 断言
  **每条判据都能在实现里找到报出点**（防"表里有、代码没做"）。
- 反向：`test_veto_triggers_all_implemented` 断言 veto 触发项全覆盖。

### 5.4 与既有唯一权威的全部接口（不新造第二套）
| 本批用到 | 复用自 |
|---|---|
| 数值解析 / 缺失≠0 | `engine/numparse.to_number_checked` |
| 等级归一 / 标度 | `engine/risk_levels.normalize/SEVERITY/LEGAL_LEVELS` |
| 证据状态五态 | `engine/data_source_status.STATUSES_ALL` |
| 资料 14 类 | `engine/material_names.CATEGORIES` |
| 裁决词 | `engine/argumentation._VERDICT_* / GRADE_*` |
| 模糊措辞 | `engine/report_wording.FORBIDDEN_VAGUE_TERMS` |
| 会话摘要字段 | `engine/snapshot_invariance.DIGEST_FIELDS` |

## 六、P1/P2 计划

### P1 · 全行业全企业适配
1. 事实库接入产出链：报告组装处对每个进入正文的金额 `declare()`，使 B1 由 SKIP 变可判定。
2. 风险等级五维加权算法：把 `RISK_LEVEL_BASIS` 扩为可配权重表（行业可覆盖）。
3. 税种包：新建 `config/tax_packs.json`（键=税种代码），配 `validate()`，套 `industry_params` 范式。
4. 行业包扩字段：资料清单 / 风险指标 / 证据要求 / 模板 / 法规库 五个子表。
5. 渲染层：导出模板加 `@page` 页眉页脚 + `counter(page)/counter(pages)`；目录改由正文标题生成。
6. 原生 docx 导出：补 `HTML→docx` 适配层 + 降级（剥 `**`/UI 词/空表）。
7. 报告受众分版：老板摘要版（≤8 页）/ 财务执行版 / 税务顾问版。

### P2 · Skill 固化
1. 把四道门禁登记为 `TaxRiskScan.Workpaper.Generator` 的**步骤 + 门禁**（见 `11_...Skill定义.md`）。
2. 接入 `engine/skill_runtime.run()`（现有 61 Skill / 3 方案已具备编排、日志、灰度、回滚）。
3. 幂等/重跑/回滚/监控：沿用 `skill_runtime.effective_version` + `data/skill_runs/SR-*.json`。
4. 闭包 `closure` 进 `DIGEST_FIELDS`，使闭合度跨轮可比。
