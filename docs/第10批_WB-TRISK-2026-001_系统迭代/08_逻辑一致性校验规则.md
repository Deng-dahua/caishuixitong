# 08 · 逻辑一致性校验规则

> 指令：WB-TRISK-2026-001 §3.2（逻辑一致性）
> 唯一权威：`config/quality_gates.json → gates[B]`（判据表）+ `engine/quality_gates.py`（实现）

---

## 一、最重要的一条设计结论（本轮实测得出）

> **靠文本正则去判「同一事实多值」必然高误报，不可作为 ERROR 判据。**

实测数据（基准样本 16 项）：

| 候选判据 | 命中 | 判定 |
|---|---|---|
| 同标签多值（前置/后置标签抽取） | **0 组** | 报告并不存在"同标签两个金额" |
| 同项内数值近似但不等（相对差<1%） | 11 对 | **10 对是逐笔明细的正常差异**（20,000 vs 20,090 等）⇒ 误报 |
| 同项内同量词多值（人/笔/张/户） | 7 组 | 几乎全部误报（同一项内不同语境本来就有多个笔数） |

⇒ **正确形态是"结构化字段级比对（零误报）＋正向口径登记（未登记不得进报告）"**，
而不是事后 NLP。本门禁据此设计。

## 二、判据清单（门禁 B，共 9 条）

| 判据 | 规则 | 严重度 | 层 |
|---|---|---|---|
| B1 | 同一标签在同一期间出现 ≥2 个不同值，且未并列声明口径与差异原因 | ERROR | data |
| B2 | 编号必须从 1 连续递增、不跳号、不重号，且 `max(seq) == 项数`；每条风险必须有序号 | ERROR | data |
| B3 | 结论等级 L1/L2 的事项不得带 高风险/极高风险 | ERROR | data |
| B4 | 同一事项内不得并存『高风险』与『可能性低』（除非声明按潜在影响定级） | ERROR | data |
| B5 | 同一事项内不得并存『未认定』与『已查明』 | ERROR | data |
| B6 | 计数类结论单一来源：声明值 == 实际盘点 | ERROR | data |
| B7 | 同一事实在报告多处出现必须同值（跨章节逐值比对） | ERROR | both |
| B8 | 企业名称/统一社会信用代码/检查期间/税种名称全文一致 | WARN | data |
| B9 | `closure == round(evidence_have/evidence_need, 2)`（容差 0.02） | ERROR | data |

## 三、B1 金额口径登记表（正向要求）

口径登记由 `engine/fact_store.py` 承担（本批新建）。每个金额进报告前必须登记六要素：

| 要素 | 字段 | 例 |
|---|---|---|
| 口径 | `scope` | `full` 全口径 / `adjusted` 剔除口径 |
| 含税性 | `tax_inclusive` | true / false / None（未登记） |
| 期间 | `period` | `202601` |
| 来源 | `source` | 表3 / 银行流水 / 序征账 |
| 计算过程 | `derivation` | `4,513,064.91 − 2,751,129.23 − 0.00 − 263,243.00` |
| 口径分组 | `related` + `scope_note` | 同组多值 = 已声明，不判冲突 |

**判定规则**：
- 同 `(kind, label, period, scope)` 同值 ⇒ 幂等，不报。
- 同键不同值 ⇒ 记 `FactConflict`（**保留被覆盖的历史值**，不静默顶掉）⇒ B1 ERROR。
- 同键多值但**每个都声明了同一个 `related`** ⇒ 视为已声明的多口径，**不判冲突**
  （例：银行差异 1,734,859.35 全口径 / 227,659.35 剔除后 —— 报告已写明关系，不属缺陷）。

**检验（实测）**：`1,734,859.35` 与 `227,659.35` 并列且已声明"剔除明显非销售流入后"
⇒ **判为非缺陷**。若强行判冲突，即为假红。此条已写入验收脚本第 12 行用例。

## 四、B2 编号连续性（`engine/numbering.py`）

```
编号 = <前缀>-<企业代码>-<期间>-<序号>      # 法规例外：WB-LAW-<税种>-<序号>
```
- 起点 = 1，逐项 +1，**不得跳号、不得重号**，且 `max(seq) == 项数`。
- 任一风险无编号 ⇒ `MISSING_NUMBER`。
- 中文数字（`办理顺序` 字段）由调用方先转阿拉伯数字；编号服务**不**接受中文数字。

**基准样本实测**：13/16 有编号；缺号 `[8, 10, 12, 16, 17]`；末值「十八」> 项数 16；3 项无编号 ⇒ B2 报 5 处问题。

## 五、B6 声明计数单一来源（本轮抓到的最大一处）

规则：报告层声明的计数必须等于对 `confirmed_problems` 的实际盘点。

实测（基准样本）：

| 字段 | 声明 | 实际 | 结论 |
|---|---|---|---|
| `total_risks` | **153** | **16** | ERROR |
| `high_risk` | 1 | **2** | ERROR |
| `mid_risk` | 13 | **9** | ERROR（1+13+3=17≠16） |
| `low_risk` | 3 | 3 | OK |
| `overall_level` | `已核定2项/待核151项` | 实际 16 项全部 `待核` | ERROR |
| `resolution_ledger.total` | 71 | 16 | ERROR |
| `resolution_ledger.ironclad/self_provable/pending` | 11/141/1（合153） | 16 | ERROR |

⇒ **合计 11 处不一致**。这类判据可完全复算、零误报，应作为 P0。

## 六、B7 跨章节相反断言（结构化）

实现方式：对登记的对象词做「已/未 + 动作」的相反断言检测。
对象词表当前为：

```
从业人数 / 资产总额 / 应纳税所得额 / 利润总额 / 工资薪金总额    ×    动作：取得、验证
```

实测命中 1 处：

| 对象 | 正向 | 负向 |
|---|---|---|
| 资产总额 | 「资产总额/账面净利润三项**均已取得**」（疑点5 的 tax_impact 说明） | 「**未取得**从业人数、资产总额」（报告级 tax_impact_summary 注释） |

⇒ 同一份报告对同一事实给出**完全相反**的表述。这是"单一事实源"缺位的直接证据。

> **扩展说明**：对象词表当前是代码内常量，应迁到 `config/` 成为可配表（P1）。

## 七、B9 闭合度自洽

`closure` 与 `evidence_have/evidence_need` 必须同源。实测 4 项不自洽：

| 项 | closure | have/need | 复算 |
|---|---|---|---|
| 4 | 0.38 | 1/4 | 0.25 |
| 5 | 0.50 | 1/3 | 0.33 |
| 15 | 0.33 | 1/5 | 0.20 |
| 16 | 0.38 | 1/4 | 0.25 |

⇒ 闭合度被两处各算一遍（或 have/need 语义不同）。**修法：闭合度只由一处算，另一处只引用。**

## 九、SKIP ≠ PASS

取不到数据必须报 SKIP 并写明原因（`policy.skip_is_not_pass = true`），SKIP 计入未通过。
本批基准样本有 6 处 SKIP，例如「事实库未挂载（B1 事实级冲突未执行）」、
「未提供导出物文本（C6 页眉页脚未执行）」——**这些必须显性化，不能当通过。**
