## 2 风险等级规则引擎（§3.2 五维加权）

P0 实现为**可配置词表 + 硬约束 + 一票否决**三件套；五维加权算法为 P1（见 01 迭代方案）。

### 2.1 合法等级词表（唯一权威 `engine/risk_levels.LEGAL_LEVELS`）

| 等级 | 轻重标度 | 呈现序 | 类型 |
|---|---|---|---|
| 极高风险 | 5 | 0 | 风险档 |
| 高风险 | 4 | 1 | 风险档 |
| 中风险 | 3 | 2 | 风险档 |
| 低风险 | 1 | 3 | 风险档 |
| 待核验 | 2 | 4 | 证据状态 |
| 信息 | 0 | 4 | 风险档 |

### 2.2 硬约束（同一事项内，违反即 ERROR）

| 约束 | 判据 | 出处 |
|---|---|---|
| 等级词表 | 风险等级必须属于合法词表；表外词归一后仍非法即报错 | A5 |
| 无证据不得定级 | closure=0 或 evidence_have=0 ⇒ 等级不得高于『待核验』 | A1 / 一票否决 V1·V5 |
| 未闭合不得定中高 | closure < 0.80 ⇒ 等级不得为 中风险及以上 | A9 / V2 |
| 等级与结论挂钩 | 结论等级 L1/L2 ⇒ 不得带 高风险/极高风险 | B3 |
| 高等级与低可能性不并存 | 同项同时出现『高风险』与『可能性低』且未声明定级依据 ⇒ ERROR | B4 |
| 未认定与已查明不并存 | 同项并存『未认定』与『已查明』⇒ ERROR | B5 |

### 2.3 一票否决触发条件（`config/conclusion_grades.json → veto_rules`）

| ID | 条件 | 触发含义 |
|---|---|---|
| V1 | `closure == 0 或 evidence_have == 0` | 无任何证据被取得 |
| V2 | `closure < min_closure(0.8)` | 证据链未闭合 |
| V3 | `direct_missing 为真` | 直接证据缺失 |
| V4 | `missing_material_names 非空且未全部登记替代资料` | 关键资料缺失且无替代程序 |
| V5 | `存在风险等级但无 closure 字段` | 等级无证据支撑（无闭合度即无依据） |
| V6 | `conclusion_grade 缺失或为占位` | 结论等级未登记 |

否决后处置：risk_level ≤ **待核验**；conclusion_grade 降至 **L2**；追加声明「（关键证据缺失，本项不作认定）」；门禁严重度 ERROR。

### 2.4 定性词禁用表（`veto_rules.determinative_words`）

`已查明`　`已认定`　`认定成立`　`构成偷税`　`认定为偷税`　`定性成立`　`已触碰`　`违法行为`　`逃税`　`虚开成立`　`确认虚开`　`确定违法`

## 3 四道门禁判据清单（38 条）

### 门禁A · 证据链闭合度门禁（§3.1）

| 判据 | 层 | 严重度 | 规则 | 修复建议 |
|---|---|---|---|---|
| A1 | data | ERROR | closure==0 或 evidence_have==0 的事项不得带 高/中/低/极高 风险等级（关键证据一票否决） | 将风险等级降为『待核』并追加『（关键证据缺失，本项不作认定）』 |
| A2 | data | ERROR | closure < min_closure(0.8) 的事项其结论等级不得为 L3 风险事项成立 | 结论等级降为 L2 待核线索，并在正文声明证据不足 |
| A3 | data | ERROR | 存在直接证据缺失（direct_missing 为真）时，本项不得出现定性词（已查明/已认定/构成偷税…） | 剔除定性词，改写为『账内已读到与该项风险指向一致的信号，待补充资料后判断』 |
| A4 | data | ERROR | 每条风险事项必须登记 conclusion_grade，不得缺失或为空 | 按 config/conclusion_grades.json 规则补登结论等级 |
| A5 | data | ERROR | 风险等级词必须属于合法词表（极高风险/高风险/中风险/低风险/待核验/信息，权威=engine/risk_levels.LEGAL_LEVELS） | 表外词一律用 risk_levels.normalize 归一；归一后仍非法的映射到最近合法档并记录原词 |
| A6 | data | ERROR | 证据状态词必须属于五态词表（已有/缺失/须核对/待企业提交/本业态不适用） | 按 engine/data_source_status.STATUSES 归一 |
| A7 | data | WARN | missing_material_names 非空时，必须给出 config/alternative_evidence.json 登记的具体替代资料名 | 从替代程序库取具体替代资料名写入『补救要求』列，禁止只写通用套话 |
| A8 | data | WARN | closure 必须进入会话摘要（跨轮可比） | 把 closure 加入 snapshot_invariance.DIGEST_FIELDS |
| A9 | data | ERROR | closure 已登记但低于 min_closure(0.8) 的事项不得带 中风险及以上等级（证据链未闭合却定中高等级） | 降为『待核验』或补足证据后重新定级 |

### 门禁B · 逻辑一致性门禁（§3.2）

| 判据 | 层 | 严重度 | 规则 | 修复建议 |
|---|---|---|---|---|
| B1 | data | ERROR | 同一标签在同一期间出现 ≥2 个不同金额/人数/笔数，且未并列声明口径与差异原因（金额口径登记表） | 补登口径（全口径/剔除口径、含税/不含税、期间、来源、计算过程）并说明两者关系；或统一为一个权威值 |
| B2 | data | ERROR | 编号必须从 1 连续递增、不跳号、不重号，且 max(seq)==项数；每条风险必须有序号 | 由 engine/numbering.py 重新生成连续编号 |
| B3 | data | ERROR | 结论等级为 L1/L2 的事项不得带 高风险/极高风险（等级与结论脱钩） | 降级风险等级，或补足证据链至 L3 后再定高等级 |
| B4 | data | ERROR | 同一事项内不得并存『高风险』与『可能性低』（除非明确声明按潜在影响定级） | 统一口径：二者只能留其一，或补写定级依据说明 |
| B5 | data | ERROR | 同一事项内不得并存『未认定』与『已查明』（定性冲突） | 按 A3 改写，全项统一为『未认定 + 已读到信号』 |
| B6 | data | ERROR | 计数类结论必须单一来源：分项之和 == 合计 == 权威值 | 由唯一权威重算并回填 |
| B7 | both | ERROR | 同一事实在报告多处出现必须同值（跨章节逐值比对） | 以事实库 fact_id 引用替代重复手写 |
| B8 | data | WARN | 企业名称/统一社会信用代码/检查期间/税种名称全文一致 | 统一取 enterprise_profile 权威值 |
| B9 | data | ERROR | closure 必须与 evidence_have/evidence_need 自洽（closure == round(have/need,2)，容差 0.02） | 闭合度由唯一权威按 have/need 重算，禁止两处各算一遍 |
