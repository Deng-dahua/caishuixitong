三、核验出的 7 个真缺口（按根因修，不打补丁）

1. verdict 被去重误伤（最严重）
现状`report_pipeline.TEXT_KEYS` 原把 `verdict`/`suggestion`/`confidence_formula` 当「展示文本」参与去重，理由是「16 项完全相同 ⇒ 真冗余」。实测 14/16 项的 verdict 被替换为跨项引用（R3 的结论变成「见疑点R2」、R7 甚至出现自引用「见疑点R7」）—— 读者完全看不到本项定性状态。旧注释称「安全性由下游闸门过滤保证」，那只解决扫描器不误判，没解决读者看到错误引用。
修法撤回该「例外」：逐项结论字段一律进 `SKIP_KEYS`；去重只动纯展示叙述段落。
2. 去重只判『整体』，同章节/同一事实不阻断
现状产物链 `dedup_pipeline.duplicate_rate` 只算整体重复率；而离线 `scripts/_phase1_diagnose.py` 另有一份三项完整实现 ⇒ 同一判据两处实现，且产出链的阻断依据残缺。
修法收敛为唯一权威三项（整体≤10% / 同章节≤5% / 同一事实≤1 次），离线脚本改薄转发；并补句子级跨事项事实去重（`dedup_sentences_cross`）。
3. 引用编号整体偏移 1
现状`report_pipeline` 里 `where = f"R{_seq + 1}"` —— `seq` 本就从 1 起（同类事故此前已在 `enterprise_report` 修过一处，此处漏改）⇒ 去重引用语给出错误编号。
修法改为 `_seq if _seq >= 1 else idx`；闸门 C3 禁止 `seq + 1` 形态。
4. 样本库从未真正入库 + 提炼源错
现状`main.py` 调 `update_knowledge()` 没传 `case` ⇒ `record_case` 从不执行；且 `problems` 读的是离线 `baseline/阶段1/问题诊断.json`（上一次离线诊断的静态结果），与本次报告无关。
修法新增唯一权威 `problems_from_report()` / `case_from_report()`，从本次报告的问题信号归一；调用处补 `case=`。闸门 C5 锁定。
5. 缺条款指定声明
现状报告原有「不具有行政执法文书效力」，语义等价但未点明法定程序认定。
修法抽成唯一权威函数 `_administrative_boundary_statement()`（可运行时断言），并同步前端兜底文案（两处一致）。
6. 报告级通用口径被逐项重复（重复率假不达标）
现状`risk_level_basis`（11 项相同）与 `confidence_formula`（13 项相同）是每项都适用的方法说明，却被逐项重复 ⇒ 整体重复率 16.89%、同章节超阈 10（剔除这 27 行即降到 6.67%/0）。
修法上提为**报告级声明一次**：唯一实现 `report_pipeline.merge_report_level_notes` + `enterprise_report._report_level_notes_statement`（共用常量表，逐项位置改引用，避免悬空）。
7. 结论术语被通俗化层改写（术语漂移）
现状`plain_language` 把「待核」通俗化为「须核对」 ⇒ 权威术语「待核事项」在报告里变成「须核对事项」，与术语权威表漂移；且模糊词判据会把该术语误判为禁用词。
修法术语占位保护（`report_wording._authoritative_terms`）+ 判据统一走 `vague_hits`（豁免权威术语）；新增闸门 C8 做**行为级**断言（术语经两层清洗必须原样返回）。
