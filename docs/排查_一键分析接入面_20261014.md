## 四、四项确凿的「未接入」发现

### 4.1 P1-5 报告模板管理**空转**（改了模板不影响报告）

**证据链**：

1. 模板**读取唯一路径** = `engine/industry_params.py:299` → 直读 `config/report_compliance.json::templates[tid]`；
2. `engine/report_template.py:157` 也读 `templates`，但那段是 `validate_templates()`（**校验**，非读取）；
3. `template_store`（P1-5 的「有效模板 = 内置 ⊕ 台账覆盖」）**全仓只有 `templates_api.py` 引用**；
4. 实测：`report_template.py + industry_params.py` 中 `template_store` 出现次数 = **0**。

⇒ 模板管理页新建/覆盖/停用模板，**不会影响实际生成的报告章节顺序**。

### 4.2 解析与标准化的产出**未被分析链消费**

**证据**：`extracted_fields`（解析页人工校正后的结构化数据）全仓 18 处引用，**全部在 `engine/extract_service.py` / `engine/extract_store.py`（解析模块自己的存储层）**，`engine/pipeline.py` / `main.py` 分析链**零引用**。

⇒ 在解析页人工校正的数据，一键分析**不会使用**；分析另走自己的原始资料解析路径。

### 4.3 P2-3 AI 辅助、P2-4 多税种模型是**孤岛页**

**证据**：`static/ai_assist.html`、`static/tax_models.html` 文件存在、页面路由已注册（`main.py:631` include_router 含二者），但 **`static/index.html` 侧边栏无任何入口链接**，全仓 grep 仅命中其自身 js（`ai_assist.js` / `tax_models.js`）。⇒ 只能靠手输 URL 访问。

### 4.4 侧边栏「菜单项」≠「接入分析」

侧边栏 17 项里，「项目管理」7 项中除「一键稽查分析任务」外，其余（项目/资料/解析/规则/风险/报告）多为**查看产物**或**前序步骤**，本身不是分析链的一部分。
