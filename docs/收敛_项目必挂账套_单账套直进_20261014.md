# 入口归一：建项目必挂账套（企业身份单一权威）+ 单账套登录直进

- 日期：2026-10-14
- 触发：用户指出「选择账套（新建账套）与稽查项目（新增项目）重复」——核实属实：
  `projects` 表的 `name/taxpayer_id/industry` 与账套 `companies` 的
  `name/uscc/industry` 是**同一事实的两份存储**，且 `company_id` 可空，
  同一企业两处信息可不一致（数据模型层的多头维护）。
- 方案：A 档收敛（不动租户边界，只收口录入与存储权威）

---

## 一、后端（`engine/project_service.py`，企业身份的单一权威落地）

1. **`create_project`**：
   - `company_id` **必填**（显式传入或会话选中，皆无 ⇒ 400「请先选择所属账套」）；
   - 账套必须存在（不存在 ⇒ 400）；
   - **`name / taxpayer_id(=uscc) / industry` 一律从 `companies` 表回填、忽略前端传值**
     （name 为空 ⇒ 400「请先补全账套信息」）；既有的跨租户 403 校验不变。
2. **`update_project`**：
   - 项目挂有账套 ⇒ 三件套**以账套为准覆盖** payload 手填值（编辑改名改不掉企业身份）；
   - 历史无账套项目 ⇒ 保持原值、不阻塞编辑（用户补选账套后自动归一）。

## 二、前端

1. **`/projects` 新增/编辑表单**（`projects.html` + `projects.js`）：
   - 顶部新增「**所属账套 \***」下拉（数据源 `GET /api/companies`，按登录用户授权过滤）；
   - 「企业名称 / 纳税人识别号 / 行业」变**只读**，选账套即自动带出（`onchange` 联动）；
   - 无可用账套时提示并给「选择账套」页链接；历史未挂账套项目保留原显示值，
     选定账套后覆盖；提交 payload 带 `company_id`。
2. **登录页**（`login.html`）：**单账套自动直进** —— 登录成功后若授权账套恰好 1 个，
   自动 `POST /api/auth/select-company` 后直进 `/`；多账套仍进选择页；
   任何异常回落选择页，绝不阻塞登录。
