> 需求来源：用户一句话 —— 「**设置登录后直接显示首页总览页面，按返回主界面也是显示

## 二、为什么之前做不到（根因链，三处同源缺陷）

三条需求里，**① 登录进首页** 与 **③ 刷新留当前页** 天然冲突：两者都经
`GET /` 落地，**唯一的差别是"这次进入是有人主动导航，还是一次刷新"**。
改之前系统里**没有任何信号能区分这两者**，于是必然牺牲一条。

具体三处缺陷：

1. **`GET /` 一律读 `lastPage`**（`core.js::enterApp` 原第 485 行：
   `localStorage.getItem('lastPage') || 'home'`）
   ⇒ 你登录后**永远回到上次停留的内页** ⇒ 需求①根本不生效。
   同理「返回主界面」也走 `href="/"` ⇒ 也回上次内页 ⇒ 需求②不生效。

2. **8 个独立页的「返回主界面」写的是 `href="/index"`，而系统没有 `/index` 路由**
   ⇒ 实测**坏链接**（无会话 302→/login；带会话 404）。用户点了直接看到 404：
   `ai_assist / dashboard / industry_indicators / legal_library / legal_materials /
   legal_topics / tax_models`（+ `backup/consent/recycle` 文案为「返回首页」，同问题）。

3. **管理员登录后被迫先看「角色设置」页**（`login.html`：`role === "admin" ? "/roles" : "/"`）
   ⇒ 管理员登录后也看不到首页总览。

## 三、怎么实现（单一权威）

### 3.1 一次性「主动导航」信号 `?page=<内页键>`

| 进入方式 | 地址 | 落地页 |
|---|---|---|
| 登录成功 | `/?page=home` | 首页总览 |
| 内页「返回主界面」 | `/?page=home` | 首页总览 |
| 按 F5 / 重开 | `/`（无参数） | `localStorage.lastPage` = 当前页 |
| 首次访问 | `/`（无参数、无 lastPage） | 首页总览 |

`core.js` 新增落点解析（**唯一权威**）：

```js
var _allowedPages = ['home', 'tax-doc-analysis', 'methodology'];  // 唯一权威（模块级）
var _DEFAULT_PAGE = 'home';
function _resolveLandingPage() {
  var explicit = _readLandingParam();          // ① 主动导航信号（一次性）
  if (explicit) { _consumeLandingParam(); return explicit; }
  var saved = localStorage.getItem('lastPage'); // ② 刷新 → 上次停留页
  if (saved && _allowedPages.indexOf(saved) !== -1) { return saved; }
  return _DEFAULT_PAGE;                         // ③ 首次 → 首页总览
}
```

**为什么必须"一次性"**：读到信号后立刻 `history.replaceState` 抹掉该参数。
否则 F5 时 URL 仍带 `?page=home` ⇒ 刷新也被强制回首页 ⇒ 需求③形同虚设。
抹掉后 URL 是干净的 `/`，F5 走 `lastPage`（`navigateTo` 每切一页都写它）。

**为什么用 URL 参数而不是"另一个 localStorage 标志位"**：标志位在整页跳转与
**多标签页**下会串味（一个标签主动导航会污染另一个的刷新行为）。URL 参数天然
只作用于发起它的那次导航，是这个问题的最小正确信号。

**非法值一律视为"没给"**：`?page=xxx` 不在白名单 ⇒ `_readLandingParam()` 返回
`null`，走 `lastPage`。**绝不静默改成别的页**（猜错用户意图比不管更糟）。

### 3.2 返回链接（21 处，单一权威 `scripts/_wire_home_links.py`）

| 页数 | 原写法 | 现写法 |
|---|---|---|
| 8 | `href="/index"`（**404 死链**） | `href="/?page=home"` |
| 13 | `href="/"`（回上次内页） | `href="/?page=home"` |

用幂等注入器逐页替换（只认"文字含『返回主界面/返回首页』且 href 是 `/` 或
`/index` 家族"这一种形态，绝不误伤 `/select-company`、`/login` 等其它链接）。

### 3.3 `/index` 兼容路由（`main.py`）

`GET /index`、`GET /index.html` → 302 `/?page=home`。前端已全部改净，这是
**兼容兜底**：遗留书签、外部引用、以及将来可能漏改的一处，都不再 404。

### 3.4 强制改密仍然优先

登录跳转保留 `must_change_password ? "/change-password" : "/?page=home"`。
**留着初始密码就直接进系统，等于把安全策略静默废除** —— 这条不能让位于"进首页"。

## 五、本轮顺带修正的两处既有缺陷（自查发现）

### 5.1 `tests/test_home_overview.py::test_default_page_is_home` 曾是**假绿**

它原来直接对源码正则 `localStorage.getItem('lastPage') \|\| 'home'`。
本轮把该表达式从代码里移除（改为经 `_resolveLandingPage()` 解析），但**注释里
仍引用了这句旧写法** ⇒ 判据匹配到了**注释文本、一直绿**，而真实代码早已不含它。

这正是本仓明载的假判据形态（"把渲染代码删掉、注释里还留着字段名照样通过"）。
**已修**：剥注释后再断言唯一权威 `_DEFAULT_PAGE`，并加"必须经
`_resolveLandingPage()`"两条。**并做了反向验证**（注入
`_DEFAULT_PAGE = 'tax-doc-analysis'` ⇒ 两组判据均变红）。

### 5.2 4 个页面存在**遗留的静态资源版本号失配**

跑 `tools/sync_asset_versions.py` 时顺带发现 `analysis.html / documents.html /
projects.html / rules.html` 引用的 JS 版本号与文件内容 sha1 不一致
（上一轮改了 JS 但没同步版本号）。已一并同步，现全站 **27 页 / 119 处引用全一致**。

> 若不修，浏览器会继续用缓存的旧 JS —— 属"改了等于没改"。

## 七、遗留（未做，如实登记）

1. **`README`/外部文档里可能仍有 `/index` 写法** —— 路由已加兼容，不会再 404，
   但文案层面未逐份订正（属"文本一致性"，不影响功能）。
2. **`roles.html` 的「进入系统主页 →」按钮指向 `/`** —— 语义上它应等于"进首页"。
   实测行为：因登录前已带过 `?page=home`、`lastPage` 此时通常为 `home`，
   落到首页的概率高，但**严格说应显式带信号**才与其它入口一致。本轮**未改**
   （避免扩大改动面），登记为待办。
3. **多标签页场景**：标签 A 主动导航到首页不影响标签 B 的刷新行为（这是选
   URL 参数而非标志位的理由），但**未做实测**，仅在设计上成立。
