## 四、核心实现说明

### 4.1 单一判读点（**这是本轮最关键的设计**）

```
rule_versions.rule_set_version()
    = 台账里最后一次 publish/rollback 的目标版本
    ？ 否则回落 config/rule_versions.json::rule_set_version
```

- **只有一处**判读"当前生效版本"，`rule_version_admin` **不另存一份**；
- **台账为空 ⇒ 与配置基线完全一致** ⇒ 既有报告溯源（`stamp()` 写入 finding 的
  `rule_set_version`）**零行为变化**；闸门 `check_rule_version_manage_wiring` 断言这一点。

### 4.2 发布：唯一路径是"新版本号"

- 版本号必须形如 `YYYY.NN`（`^\d{4}\.(0[1-9]|1[0-2])$`）；
- 与当前生效版本**相同** ⇒ 400（那不是"发布"，是误操作）；
- **已在历史中** ⇒ 400 并提示"要改回该版本请用**回滚**"；
- 发布时把 `{rule_id: version}` 全量写快照 `data/rule_version_snapshots/{version}.json`。

### 4.3 差异：**无快照 ≠ 两版相同**

`diff(from, to)` 基于快照比对，输出 `added / removed / changed`。
任一侧缺快照 ⇒ `comparable=False` + 明确原因，**不返回空差异**
（空差异会被误读为"两版完全相同"）。截断时 `truncated=true`（上游可据此提示）。

### 4.4 接口

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/v1/rule-versions/meta` | `report.view` |
| GET | `/api/v1/rule-versions/diff?from=&to=` | `report.view` |
| GET | `/api/v1/rule-versions` | `report.view` |
| GET | `/api/v1/rule-versions/{version}` | `report.view` |
| POST | `/api/v1/rule-versions/publish` | `ruleversion.manage` |
| POST | `/api/v1/rule-versions/rollback` | `ruleversion.manage` |

★ 字面量段（`meta` / `diff` / `publish` / `rollback`）注册在 `{version}` **之前**
（闸门用出现位置比较锁住）。

### 单元/集成判据要点（含**反向**判据）

- 未发布 ⇒ `published_version()` 为空且 `current_version() == config 基线`；
- 发布 ⇒ 生效版本切换、快照含 **176** 条规则；
- **反向**：手工篡改快照里一条规则的版本 ⇒ `diff` 必须报 `changed=1` 且 `to="9.9.9"`；
- 回滚 ⇒ 生效版本回到指定历史版本；清单里当前版本**唯一**标记；
- 非法输入（`2026` / `26.1` / `2026.13` / `2026.00` / 空 / `None` / `v2026.10`）⇒ 一律 400；
- 回滚到不存在版本 ⇒ 400 且**提示历史版本列表**；
- 无 CSRF / 无 `ruleversion.manage` ⇒ 403；读 `report.view` 正常放行。

## 六、未完成 / 风险

1. **发布不校验"规则内容真的变了"**：允许"规则没动但版本号进了一位"（这是有意的 ——
   版本号也可以表达"复核确认无变化"）。若业务要求强校验，可加"快照与上一版完全相同 ⇒ 提示"。
2. **回滚不自动恢复 config**：回滚只改"生效版本"标记与台账，`config/rule_versions.json`
   的逐条版本**不动**（它代表出厂登记）。若某条规则在运行期被改过，回滚不会撤销该改动 ——
   **这是当前设计的边界，需业务确认**。
3. **快照是"版本标记"而非"规则内容"**：快照记录 `{rule_id: version}`，不含规则正文；
   要"还原某个版本的规则正文"，需要把规则正文也纳入版本控制（更大改造，未做）。
4. **版本号是手填的**：没有"下一版建议号"生成器。
