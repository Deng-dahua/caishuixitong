## 9. 已有规则引擎能力与规则清单

### 9.1 ★ 规则宇宙的真实口径（本轮重要勘误）

**实测结论：四类规则并非互斥叠加的「四层」，而是「2 层规则 + 2 类检测器实现」。**

| 类别 | 权威实现 | 条数 | 与 91 条红线的关系（实测） |
|---|---|---|---|
| 红线规则 | `engine/tax_redlines.py::REDLINES` | **91** | 全集的基准 |
| 已验证规则 | `engine/verified_rule_engine.py::VERIFIED_RULE_CATALOG` | **85** | 独立体系（VR-*），与 RL 不重叠 |
| 专项红线探测 | `engine/special_redline_detectors.py::SPECS` | **25** | **`id` 100% 落在 91 条红线内** |
| 缺口风险探测 | `engine/gap_risk_detectors.py::DETECTORS` | **10** | **`redline_id` 100% 落在 91 条红线内** |
| 缺口税种探测 | `engine/gap_tax_obligations.py::SPECS` | **14** | **`redline_id` 100% 落在 91 条红线内** |

**验证证据**：
- 专项 25 条 `id`、缺口 10 条 `redline_id`、缺口税种 14 条 `redline_id` ∈ 91 条红线 ID 集合 → **全部成立**
- 缺口税种 14 条 id：`RL-SPT-014~021`、`RL-OTH-007~011`、`RL-VAT-013`

## 12. 主要风险、技术债、重复实现、冲突设计

### 12.1 架构风险（高）

1. **超大单体文件**：`main.py` **742 KB / 149 路由**、`tax_risk.py` **643 KB**、`database.py` **113 KB**。单文件承载路由+业务+编排，**改动易误伤**（历史已多次发生「编辑行号漂移导致文档引用失配」）。
2. **SQLite 双库无迁移体系**：建表依赖运行时 DDL，**无 Alembic / 版本化 migration**，schema 变更不可回滚、不可审计。
3. **无容器化 / 无 CI**：部署靠 `start8001.bat` 手工双击；回归全靠人工跑 `pytest` + 两个审计脚本。

### 12.2 数据 / 口径风险（高）

4. **★ 规则条数口径虚高（本轮新发现，已处置）**：既有文档「四层合计 211 条」为**重复计数**（专项 25 / 缺口 10 / 缺口税种 14 已是 91 条红线的检测器实现）。**规则主体 = 176**。已建唯一权威 + 门禁 + 修正 7 份文件。
5. **缺口探测条数两口径**：运行时实测 **14**，既有文档记 **10**。
6. **91 条 placeholder 规则**：判据未定义却已入库，**存在「出现伪结论」风险**（用户已确认需转人工复核底稿）。
7. **47 条 missing 规则**：候选库已登记但系统未实现；覆盖率标称 **91/91/0/0**（**缺口层与专项层覆盖为 0**），易被误读为「全覆盖」。
8. **地区参数缺失**：契税税率 / 土增税预征率 / 海南负面清单 / 高新收入分档**无集中参数表**，存在硬编码或缺失风险。
9. **README「1720 条规则库」无可复现口径**：与实测 176（规则）/ 460（候选）均无法对应。

### 12.3 技术债（中）

10. **仓库根目录污染**：根目录散落 **30 个 `_*.py` 一次性脚本** + **57 个 `.pytmp_*.txt` 临时输出**（后者已被 `.gitignore` 忽略），未清理、未归档。
11. **`scripts/` 313 个 py**：大量一次性探针/验收脚本混存，**无目录分级、无索引**，难以判断哪些仍是权威工具。
12. **前后端无类型契约**：原生 JS + Python 靠字段名约定，无 OpenAPI 生成的前端 SDK，**字段漂移无编译期防护**。
13. **文档与实现不符**：README 启动示例用 `py -3.12`（实际 3.13）；README 指向 `start.bat`（**该文件不存在**，实际为 `start8001.bat`）。
14. **`static/js/temp_test.txt`** 疑为测试残留物，混在正式前端资源目录中。

### 12.4 重复实现 / 冲突设计（中，已有治理机制对冲）

15. **多权威风险已建立闸门对冲**：项目已沉淀「唯一权威 + 薄转发 + 闸门反向验证」体系（`tools/audit_consistency.py` + `_verify_authority_gates.py` 45 项），但**历史遗留的同概念多处实现仍在收敛中**（行业剔除 / 金额解析 / 报告名均曾多头）。
16. **同一概念跨链路漏判**：工作记忆记录「社保做了公积金没做」类复发病根，属**结构性风险**。

### 12.5 治理机制（风险对冲，正面项）

- `tools/audit_consistency.py`：全量 ERROR/WARN 总审计
- `_verify_authority_gates.py`：**45 项「改坏-变红」反向验证**（防止闸门是假的）
- `tools/verify_release.py`：发布门禁
- `engine/quality_gates.py` + `config/quality_gates.json`：四道报告质量门禁
