## 一、现状扫描

| 既有资产 | 可聚合的内容 |
|---|---|
| `engine/project_service.list_projects(session, ...)` | 项目（含状态 / 行业 / 账套） |
| `engine/document_service.list_documents(project_id, session, ...)` | 资料（**已直接给分类计数** `category_counts_cn`） |
| `engine/analysis_task.list_for_project(project_id, session, ...)` | 分析任务（含状态） |
| `engine/risk_service.stats(company_id, session)` | 风险（等级 / 税种 / 复核状态 / 金额分档） |
| `engine/audit_trail.list_records(limit, ...)` | 操作留痕（含中文动作名） |

**结论：聚合所需的数据**都在既有 Service 层**，且**都带租户/权限过滤**。
⇒ P2-5 的关键不是"造数据"，而是**不绕过这些 Service**（否则大屏的可见范围会与业务页面不一致）。

## 二、目标

建跨项目聚合统计 + 数据大屏（**纯手写 SVG/CSS 图表，无 CDN、离线可用**）。
硬约束（自我施加，可被闸门验证）：**大屏零 SQL**，全部经既有 Service 层取数。

## 四、核心实现

### 4.1 零 SQL —— 可见范围与业务页面**同源**

```python
def overview(session):
    from engine import project_service as PROJ      # ← 全部经 Service
    ...                                             # 本模块**没有任何 SQL**
```

闸门 `check_dashboard_wiring` 断言：① 5 个 Service 的 **import 语句**必须存在；
② 代码里不得出现 `SELECT`/`INSERT`/`UPDATE`/`DELETE`。
（首版判据只查裸模块名 ⇒ `metadata()` 的说明字符串里提到 `risk_service.stats` 就假绿，已收严为查 import。）

### 4.2 **口径不混**：`payload_unavailable` ≠ `0 条风险`

风险数来自各账套的风险载荷；**读不到载荷的账套单独计数**，并在 `note` 里写明
「这不是 0 条风险，两者不可混」。页面把它做成**橙色告警卡**（与"0 条"视觉区分）。
反向验证 S5 把该说明删掉 ⇒ 判据**立即变红**。

### 4.3 **不静默截断**

超扫描上限时如实标 `capped=true`，并在页面提示"只汇总前 N 个，未抽样估算"。

### 4.4 前端**不做统计运算**

所有数字取后端，前端只做**条形长度/坐标换算**（`count / max * 100`、SVG 折线坐标）。

## 六、实测结果

| 项目 | 结果 |
|---|---|
| 空实例 | 各计数 0、`activity.available=true`、无异常 |
| 带数据（2 项目 / 2 账套） | `projects.total=2`、`by_status` 求和 = 2、`per_project` 长度 = 2 |
| 风险口径 | 无载荷账套 ⇒ `payload_unavailable=1`、`payload_available=0`、原因「该账套尚未生成报告载荷」 |
| **可见范围** | 受限用户（仅账套 2）⇒ 只看到"乙账套项目"；管理员 ⇒ 2 个（**两侧都断，防"恒空"假绿**） |
| `pytest tests/test_dashboard_p25.py` | **5 passed / 0 failed** |
| 闸门 `check_dashboard_wiring` | **ERROR 0** |
| 反向验证 | **7 / 7 通过**（含"口径混同""无视可见范围"） |
| 零风险 | `main.py` **15156** 不变；D1 锁定行零漂移 |

## 七、未完成 / 风险

- 聚合是**逐项目遍历**（上限 200 项目）：项目数很大时接口会变慢 —— 已在 `capped` 里如实标注；
  如需支撑更大规模，应改为**一条聚合 SQL**（但那样会绕过 Service 的可见性口径，需另行设计）。
- 留痕按日计数基于**扫描上限 2000 条**（`capped` 会标出），不是全量历史。
- 图表为**手写 SVG**（无图表库）：只做了条形图与单折线，无交互钻取、无导出。
- 风险分布只覆盖**有载荷的账套**，覆盖度由 `payload_available / scanned_companies` 体现。
- 未做：时间范围筛选、按行业/人员维度下钻、大屏自动刷新与投屏模式。
