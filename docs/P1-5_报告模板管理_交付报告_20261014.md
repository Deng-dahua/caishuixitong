## 二、目标

1. **模板可管**（补 M-1）：清单 / 详情 / 新建 / 覆盖 / 停用 五类操作有接口与页面。
2. **变更可追溯**（补 M-2）：每次写入落 append-only 台账（含版本号与操作人）。
3. **可回到出厂**（补 M-3）：覆盖内置模板后可**停用覆盖** ⇒ 回到内置出厂值。
4. **不破坏既有装配**：`report_template.section_order()` 等既有函数**一字未改**；
   章节白名单**不放松**（`sections` 必须在 `BASE_SECTIONS` 内）。

## 四、核心实现说明

### 4.1 有效模板 = 内置 ⊕ 覆盖（**内置仍是单一来源**）

```
effective_templates() = builtin_templates()（来自 report_compliance）
                        ⊕ _custom_templates()（来自台账折叠）
```

- `builtin_templates()` **只读** `config/report_compliance.json`，**不复制、不改写**；
- 台账 `data/report_templates.jsonl`（append-only）只存**自定义/覆盖**；
- 闸门断言"`builtin_templates()` 的键集合 == config 的键集合"。

### 4.2 停用语义（**不是一律删除**）

| 情形 | 结果 |
|---|---|
| 停用**覆盖内置**的模板 | **回到内置出厂值**（内置仍在有效集合里）—— 这就是"改坏了能回去"的路径 |
| 停用**纯自定义**模板 | 从有效集合移除 |
| 停用**未被覆盖的内置**模板 | **400 + 说明**（内置没有"删除"入口，直接停用会让用户无从恢复） |

> ★ 这条是**测试抓出来的真实缺陷**：首版写成"停用一律 pop"，导致覆盖被停用后模板**直接消失**
> 而不是回到出厂值（测试 `assert eff3[tgt]["scope"] == "builtin"` 报 `KeyError`）。

### 4.3 校验（不放松）

- `sections` 不能为空（空模板会产出"没有章节的报告"）；
- `sections` 每项必须在 `report_template.BASE_SECTIONS` 内，否则 400 **并把合法值列出来**；
- 模板编码必须匹配 `^[a-z][a-z0-9_]{1,48}$`（防注入与路径穿越）；
- 覆盖内置**允许**，但 `report_compliance.json` **一字不改**。

### 4.4 接口

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/v1/report-templates/meta` | `report.view` |
| GET | `/api/v1/report-templates`（`?include_disabled=`） | `report.view` |
| GET | `/api/v1/report-templates/{id}` | `report.view` |
| GET | `/api/v1/report-templates/{id}/versions` | `report.view` |
| POST | `/api/v1/report-templates/{id}` | `template.manage` |
| POST | `/api/v1/report-templates/{id}/disable` | `template.manage` |

★ `meta` 注册在 `{id}` **之前**（否则被路径参数吃掉 ⇒ 静默 404）。

## 六、未完成 / 风险

1. **模板与行业 `industry_params` 的映射仍走 config**：本轮只做"模板本身"的管理，
   没做"行业→模板"的在线映射编辑（那属于行业参数管理，另一条链路）。
2. **未做模板预览**：没有"按此模板生成一份样例报告骨架"的能力。
3. **台账无清理策略**：停用/覆盖事件永久保留（append-only 的设计使然，量很小）。
4. **模板不影响风险事项**：只改**呈现**（章节顺序与侧重）—— 这是 `report_template` 的既有铁律，
   本轮**未放松**（`snapshot_invariance` 指纹断言仍生效）。
