## 二、目标

1. **批量复核**（补 R-1）：一次动作多条，**逐条独立执行、逐条如实回报**。

## 四、核心实现说明

### 4.1 批量复核：**部分成功可见**（不做静默回滚）

```python
bulk_review(risk_nos, action, session, *, company_id, note, request, limit=BULK_LIMIT)
  → {total, ok, noop, failed, dup_removed, items[{risk_no,status,code,message,state}]}
```

**为什么不做"全成功才提交"**：那需要事务性回滚，而处置流水是 **append-only 台账**
（`risk_reviews.jsonl`）—— 强行回滚会破坏"留痕不可改写"这条铁律。
故采用**部分成功可见**语义，逐条给出 `ok / noop / failed` 三态 + 原因。

其他口径：
- **重复编号自动去重**，去重条数记入 `dup_removed`（**如实告知，不静默**）；
- **空列表 / 超过 200 条 ⇒ 400**（不静默截断，提示"请分批提交"）；
- 逐条失败的 `code` 保留 Service 层语义码（400/404），不吞成 500；
- 汇总再写一条 `risk.bulk_review` 审计（逐条的 `risk.review` 仍各自留痕）。

### 4.2 处置历史

`history(risk_no, company_id)` 返回 `events`（处置事件流）+ `comments`（批注，**单列**）
+ `reviewed` / `manual_required` / `rectification_no` / `updated_by`。

★ 口径澄清（本轮实测发现并写进代码注释与测试）：
`_collapse` 对 `event=comment` 走 `continue`，**批注不混入 `events`** ——
两者是**互补关系**（一个是状态变更流，一个是意见流），不是同一列表。

### 4.3 看板与超期

`review_stats(company_id, *, risk_nos=None, stale_days=3)` 返回各态计数、
`done_ratio`、`overdue[]`、`never_reviewed[]`。

★ 关键口径（**缺失 ≠ 0**）：
- **「从未处置」与「超期」分开计** —— 前者**没有起点**（不能算超期），后者自最近一次处置起算；
- `_days_since()` 无法解析时间 ⇒ 返回 `None`（**不猜**），归入 `never_reviewed`。

### 4.4 路由顺序（一个容易静默出错的点）

`/risks/review-board` 与 `/risks/bulk-review` 必须注册在 `/risks/{risk_id}`
**之前** —— 否则会被路径参数吃成"风险编号 = review-board"（**静默 404**）。
闸门 `check_review_flow_wiring` 用**出现位置比较**把这条锁住。

### 单元/集成判据要点

- **部分成功可见**：2 条成功 → `ok=2`；重复执行 → `noop=2`；缺理由的 `exclude` → **逐条 failed**（不是整批 500）；非法动作 → 逐条 failed 且 `code=400`；`["T-3","T-3","T-3"]` → `total=1, dup_removed=2`；空/超限 → 400。
- **不改定性回归**：复核后记录里**不得出现** `risk_level / level / conclusion_grade / severity`（含事件流水），否则测试失败。
- **不泄露存在性**：`GET /risks/NO-SUCH-RISK/history` ⇒ **404**（与 P0-6 同口径）。
- **CSRF**：无 `X-CSRF-Token` 的批量复核 ⇒ **403**（不静默放行）。
- **看板** 缺 `company_id`/`project_id` ⇒ **400**（不静默给全量）。

## 六、未完成 / 风险

1. **勾选不跨页**：`PICKED` 只记本页勾选，翻页后上一页的勾选仍在内存里但不可见。
   若要"跨页全选"，应改由后端按筛选条件生成任务（属于 P2）。
2. **超期仅"提示"不"阻断"**：无自动升级 / 通知机制。
3. **批量不支持"每条形参不同"**：同一批只能同一动作 + 同一理由。
4. **审计是"逐条 + 一条汇总"**：超大批次（200 条）会产生 201 条留痕，检索时需注意。
