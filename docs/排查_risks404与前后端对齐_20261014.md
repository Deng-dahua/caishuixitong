# 排查报告：`/risks` 返回 `{"detail":"Not Found"}` + 前后端对齐核实

> **时间**：2026-10-14（CST）｜**方式**：只读取证 + 隔离实例实测（真实 Chrome）
> **结论一句话**：**不是代码不对齐**。`/risks` 路由在代码里存在；你看到的 404 是因为
> **`:8001` 上跑的是 2026-10-13 10:58 启动的旧进程**，那版代码里**一个业务页面路由都没有**。
> 本轮**未修改任何代码/规则/数据库**。

## 一、现象

访问 `http://127.0.0.1:8001/risks` ⇒ 页面显示 `{"detail":"Not Found"}`。

这是 **FastAPI 的默认 404 JSON**（`HTTPException(404)` 的默认响应体），含义是：
**该路径在当前运行的应用里没有注册任何路由**。（应用自定义的 HTML 错误页/兜底页都没命中。）

## 四、顺带发现的真问题（都在**当前代码**上，与旧进程无关）

### 4.1 `/audit-logs` 首访 503（瞬态），且"只读"被归入"忙"

- 实测：`GET /audit-logs` 第一次 **503**（正文 205 字）；随后重试 **200**（正常渲染）。
- 服务日志：`sqlite3.OperationalError: attempt to write a readonly database`。
- 属隔离副本环境的瞬态写失败（DB 由另一进程持有/复制后权限），**非路由问题**。
- **但暴露一个语义问题（待裁）**：Batch-1 新增的 `database.is_db_busy_error()` 把
  「**忙/锁**」（可重试）与「**只读**」（多半**不可**重试：文件权限、挂载只读）**归为同一类**，
  统一回 503「服务繁忙，请重试」。若真因是"只读"，这个提示会**误导用户一直重试**。
  ⇒ 建议拆成两类（`503 可重试` / `500 需运维介入`）。

### 4.2 页面路由出错时返回的是 **JSON**，不是 HTML

`/risks` 这类**页面**路径出错，浏览器会直接把 `{"detail":"Not Found"}` / `{"ok":false,...}` 摊在屏幕上
（本次截图即是）。⇒ 建议为页面路径加 **HTML 错误兜底页**（含"若刚更新代码请重启服务"的提示）。

### 4.3 初始化路径上一处"**近失**"（latent hazard）

`core.js:472` 的 `await loadAllAccounts();` 就位于 `navigateTo(lastPage)` **前一行**，
与 2026-10-07 那次事故（`loadCompanies` 未定义 ⇒ 后面三行全不执行 ⇒ 内容区空白）**同款位置**。
当前靠 `loadAllAccounts` 内部的 `try/catch` 保命 ⇒ **一旦有人去掉那个 catch，或 `api()` 改成抛异常，整页初始化会静默中断**。
建议：把"取数据"与"跳转"解耦（跳转不受取数失败影响），或给该行加显式守卫。

### 4.4 遗留脚本仍在 `index.html` 里被加载

`tax-pipeline-pages.js`、`human-learning-page.js`、`report-modules.js` 仍由 `static/index.html` 引入，
其中的 `/api/tax-assets/*`、`/api/human-learning/*` 已无后端 ⇒ 同属**遗留调用**（当前不在生效路径，因归属函数未被调用）。
