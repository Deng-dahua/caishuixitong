## 二、★ 最重的真缺陷：覆盖率算出来了，却从不显示

### 2.1 事实（真实产物实测，非推断）

后端 `analysis_coverage` 一直有完整账本（`company_1_full.json` 实测）：

```
total 219 ｜ executed 89 ｜ blocked 130 ｜ not_executed 0 ｜ executed_ratio 0.4064
missing_sources: 增值税申报表 16、科目余额表 15、企业所得税申报表 15、
                 销售合同 13、采购合同 10、个税申报表 9
summary_text: 「本轮按『上传了什么资料就查什么资料』执行：应检查 219 项，其中现有资料
              已足以判定 89 项…另有 130 项需与企业补充资料交叉比对后方可判定…」
```

而前端：

| 环节 | 实况 |
|---|---|
| 读 `analysis_coverage` | **一个字段都没读**（审计【1】列为"僵尸字段"） |
| 原想用的 `coverage_closure` | 后端**从未产出**（产物深搜 0 命中） |
| 那个渲染点在哪 | `_renderReportFallback` 里 `if (_isEnterpriseEdition(r)) { … return }` **提前返回之后**的旧版兜底分支 |

**验证"那段是死代码"的硬证据**（本轮实测）：

```
在 coverage_closure 渲染点前插入 throw new Error('REACHED-7093')
⇒ 渲染报错：无；HTML 长度：446,392（不变）
⇒ 该行从未执行
```

同一函数的入口打点 `__p0 = 1`（执行了），中段 `__probe_ac` 与末尾 `__pEND` 均为
`undefined` ⇒ 函数在 `if (_isEnterpriseEdition(r))` 处返回，其后约 1,800 行是死代码。

### 2.2 修法

在企业版正文（`_buildEnterpriseReadableBody`，唯一渲染实现）**第三章之后**（顶层，必执行）
按后端真实字段渲染：
- 后端 `summary_text` 原文（不重写）
- 数量表：应查 219 / 已执行 89 / 待补 130 / 未执行 0 / 执行率 40.6%
- 缺失资料表（`missing_sources`，按涉及项数降序）
- 底气声明：待补事项补齐前**不作违规认定**；"未见异常"**不等于**合规

只展示业务口径，**不列内部规则编号**（报告正文铁律）；不编造后端没有的六分类。

## 三、修掉的 5 类**判据自身缺陷**（工具坏了比缺陷更危险）

| # | 判据 | 错在哪 | 后果 | 修法 |
|---|---|---|---|---|
| 1 | `_audit_frontend_render.js` 加载清单 | 硬编码 `constants/core/tax-doc-analysis`，**漏 `dom-utils.js`** | `escHtml` 未定义 ⇒ 报告 0 字符，把"449KB/0 缺陷"判成"前端根本没产出报告" | 补入清单 + **从 index.html 反查校验**（页面加载但清单没有 ⇒ 告警）+ 自检转义函数可用 |
| 2 | 路由对齐 `APIRouter(prefix=…)` | **从未解析前缀** | `business_api.py` 的后端路径被记成 `/query`，前端 `/api/v1/business/query` 判 404（假红）；也可能掩盖真拼错（假绿） | 先扫 `(\w+)=APIRouter(prefix="…")`，再给 `@router.get` 拼前缀（`@app.` 不拼） |
| 3 | 动态路由 `{param}` | 命中后仍算真断链 | `/api/tax-assets/analysis` 等 3 条被列成 404，实为 `{asset_name}` 接管且白名单含该值 | 命中 `<p>` 后**从 handler 源码解析白名单**（`virtual_assets`/`filenames`），值在白名单 ⇒ 归【A4】不算断链；**值明确不在**才报 404 |
| 4 | 字段审计【2】 | ①`\br\.` 把 `forEach(function(r){r.name})` 当报告字段；②只查 payload 顶层，不查 `enterprise_readable_report`；③未剥注释（`report.generate` 是**权限点名**、`report.export` 是**审计动作名**） | 一次性报 70+ 条"后端未产出"，绝大多数是通用词；而真正存在的 `overall_conclusion` 等被误报 | 只认独立 `report.`；同时查两层；排除方法调用 `report.X(`；先过 `engine.js_source.strip_comments`；`r.X` 单列【2b】标注低置信度 |
| 5 | 覆盖率闸门（我自己新写的第一版） | 用 `_js_code_only` 检查"是否渲染某列名"，而该函数**把字符串内容也换成空格** | 恒报"未渲染"（假红） | 改用 `engine.js_source.strip_comments`（只剥注释、保留字面量） |

> ★ 教训：**存在性断言（"必须渲染某文案"）必须保留字符串；反模式扫描（"不得出现某串"）才用去字符串视图。**
> 两种视图选错方向，判据就必然假红或假绿。
