# 财税稽查系统：从「接近彻底」推到「彻底」的路线图

> 目标：彻底稽查企业是否存在税收违法行为。
> 结论先行：系统能在**数据可触达范围内**近乎彻底地发现违法线索；但「彻底」的最后一环
> （账外经营、私户收款、主观故意定性）依赖**外部数据源 + 人工下户取证**，不在算法能力内。
> 推进的本质 = 给系统装上「企业自报数据之外的独立视角」+ 把人压到取证与定性上。

## 推进三阶

### 第一阶：能力边界显性化（已完成 ✅）
- **做什么**：每份报告注入「能力边界与彻底稽查路线」章节 + report_statement 边界声明。
- **价值**：每次分析自带证据来源局限声明，既回应「彻底」诉求，又不越界替稽查员终裁。
- **依赖**：无（纯内部）。
- **风险**：零。

### 第二阶：接通外部数据源（已交付 ✅，提交 56c5443f）
让系统第一次拥有「企业自报之外的独立视角」，识别账外与隐性收入。

**已落地（零凭证）**：`engine/external_verifier.py` 的免费双通道已接入一键分析主链路与报告——
- 国家企业信用信息公示系统（工商状态异常 / 注销吊销）
- 搜索引擎综合核实（经营异常 / 行政处罚 / 涉诉记录）

外部核验结果写入 `comprehensive.external_verify`，渲染为报告「十一（二）外部工商与风险核验」章节，
每条风险信号带稽查指向（如注销前转移收入、空壳、虚开发票前科），标注属「待证线索」。

**升级位（待用户提供凭证后自动启用）**：

| 优先级 | Connector | 补强的违法盲区 | 接入前提 |
|---|---|---|---|
| P0 | **资金流 / 银行流水比对**（新最高优先级） | 抓未开票收入、私户收款、资金回流闭环——数电票时代真正的违法主通道 | 合规授权流水（银税互动 / 企业网银导出） |
| P0 | **企查查 / 天眼查** | 工商股权穿透、人员重叠、关联企业网状结构（深度） | API Key（付费，配 `QCC_TOKEN`/`TYC_TOKEN` 即启用） |
| P1 | **云帐房 AI 财税** | 原设想补「开票 vs 自报差异」——**数电票下该差异已被票表比对锁死，价值极低**；其真实价值在账套明细与银行流水（同源资金流） | 用户授权账号 / API 凭证 |
| P2 | **威科先行** | 法规时效与定性依据核验 | 机构订阅凭证 |

- **价值**：把「单户自报数据」升级为「自报 + 外部独立源」双视角，账外经营可借上游/下游开票反推暴露。
- **依赖**：用户提供对应 connector 的授权凭证；部分商业服务需付费。
- **风险**：外部数据合规（须基于合法授权与公开/授权数据，不碰隐私爬虫）；凭证安全。

### 第三阶：跨企业关联交易闭环打通主链路（已交付 ✅）
- **做什么**：把已有 `cross_enterprise_graph.py` 接入一键分析主链路，与派生树融合，
  单户疑点 → 供应链网状违法图谱（供应商=客户、资金闭环、突击注销前转移）。
  pipeline 主链路早已调用 `run_cross_enterprise_analysis` 写入 `comprehensive.cross_enterprise`，
  报告层新增 `cross_enterprise_report` 章节（提交 f916ef5e）完成渲染打通。
- **价值**：从「查一户」升级为「查一张网」，虚开/洗票/利润转移类违法暴露率大幅提升。
- **依赖**：企业图谱数据（当前 DB 仅 2 家企业且无发票往来，图谱暂为空；
  真实多企业+发票数据接入后自动生效；也可由第二阶 connector 供给）。
- **风险**：图谱误连需人工复核；不作为终裁依据。

## 责任边界（不可逾越）

1. 系统产出 = 待证线索 + 已验证事实；定性权、执法权、法律责任在稽查员/法制审核/税务机关。
2. 证据不足只列待补证清单，不以模型推测单独认定违法。
3. 账外经营、主观故意定性必须人工下户 + 法定程序。

## 关键认知修正（2026-08-26）

用户指出：数电票 + 申报自动预填 + 一窗式比对下，"已开票未申报"差异已被系统焊死，财务不会、也不敢手动砍已开票收入。经检索官方口径确认属实——

- 新电子税局从「税务数字账户」直接预填销项/进项汇总，企业只审核确认；
- 有开票却零申报被系统拦截；销项填不满发票汇总即「票表比对失败」无法提交。
- 故原路线图把"接云帐房做开票 vs 自报比对"列为 P0 **判断过时，价值已近冗余**。

**差异并未消失，而是迁移**（票表层≈一致，差异活在别处）：

1. 未开票收入栏留空（手补栏，私户收钱不填 → 申报 < 实际）——当前主通道
2. 增值税申报收入 vs 企业所得税申报收入（两税差 >10% 金税四期预警）
3. 私户/个人码收款 vs 申报（资金流与发票交叉比对，银税互动）
4. 虚开发票（票在系统里是真的，票表比对反通过，需资金回流识别）

→ 系统的下一阶重点不是"发票数据"，而是"资金流数据"。

## 建议的下一步决策

- 若只想要「报告自带边界声明 + 内部能力最大化」：**第一阶已交付，无需再动。**
- 若要真正逼近「彻底」：第四阶两条 P0（资金流、两税差异）均已落地，二者互为印证——
  **资金流暴露「账外收款」、两税差异暴露「所得税少计」**，构成数电票时代隐匿收入的两道主线证据。
  下一阶建议补 **P1 进项异常凭证 / 应转出未转出**（进项侧风险），其数据源（进项勾选、异常凭证清单）与现有发票解析同源，落地成本低、性价比高。
- 企查查/天眼查（深度股权穿透）、威科先行（定性依据）仍为有价值的增强，按需接入。
- 第三阶跨企业图谱可在资金流具备后叠加"资金回流"边，虚开识别率再升一档。

> 单靠系统到不了「彻底」；系统（数据勾稽）+ 外部源（独立视角）+ 稽查员（取证与定性）
> 三者合体，才能逼近。本路线图即三者分工的落地计划。**最新修正：差异主战场已转向资金流 + 两税收入口径。**
