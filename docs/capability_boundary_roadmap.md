# 财税稽查系统：从「接近彻底」推到「彻底」的路线图

> 目标：彻底稽查企业是否存在税收违法行为。
> 结论先行：系统能在**数据可触达范围内**近乎彻底地发现违法线索；但「彻底」的最后一环
> （账外经营、私户收款、主观故意定性）依赖**外部数据源 + 人工下户取证**，不在算法能力内。
> 推进的本质 = 给系统装上「企业自报数据之外的独立视角」+ 把人压到取证与定性上。

---

## 当前能力基线（已完成）

| 维度 | 能力 | 形态 |
|---|---|---|
| 无死角扫描 | 54 条可复算规则 VR026–VR054 | 票/税/账/资金四流闭合勾稽 |

| 责任边界 | 报告已带稽查文书式声明 | 待证线索 + 已验证事实，不越界定性 |

## 推进三阶

### 第一阶：能力边界显性化（已完成 ✅）
- **做什么**：每份报告注入「能力边界与彻底稽查路线」章节 + report_statement 边界声明。
- **价值**：每次分析自带证据来源局限声明，既回应「彻底」诉求，又不越界替稽查员终裁。
- **依赖**：无（纯内部）。
- **风险**：零。

### 第二阶：接通外部数据源（待决策 ⏳）
让系统第一次拥有「企业自报之外的独立视角」，识别账外与隐性收入。

| 优先级 | Connector | 补强的违法盲区 | 接入前提 |
|---|---|---|---|
| P0 | **云帐房 AI 财税 / AI 开票** | 企业自报开票与实际开票差异、未申报收入 | 用户授权账号 / API 凭证 |
| P0 | **企查查 / 天眼查** | 工商股权穿透、人员重叠、关联企业网状结构 | API Key（付费） |
| P1 | **威科先行** | 法规时效与定性依据核验 | 机构订阅凭证 |
| P2 | 银行流水类（如可得） | 私户收款、资金回流闭环 | 需合规授权，敏感 |

- **价值**：把「单户自报数据」升级为「自报 + 外部独立源」双视角，账外经营可借上游/下游开票反推暴露。
- **依赖**：用户提供对应 connector 的授权凭证；部分商业服务需付费。
- **风险**：外部数据合规（须基于合法授权与公开/授权数据，不碰隐私爬虫）；凭证安全。

### 第三阶：跨企业关联交易闭环打通主链路（已交付 ✅）
- **做什么**：把已有 `cross_enterprise_graph.py` 接入一键分析主链路，与派生树融合，
  单户疑点 → 供应链网状违法图谱（供应商=客户、资金闭环、突击注销前转移）。
  pipeline 主链路早已调用 `run_cross_enterprise_analysis` 写入 `comprehensive.cross_enterprise`，
  报告层新增 `cross_enterprise_report` 章节（提交 f916ef5e）完成渲染打通。
- **价值**：从「查一户」升级为「查一张网」，虚开/洗票/利润转移类违法暴露率大幅提升。
- **依赖**：企业图谱数据（当前 DB 仅 2 家企业且无发票往来，图谱暂为空；
  真实多企业+发票数据接入后自动生效；也可由第二阶 connector 供给）。
- **风险**：图谱误连需人工复核；不作为终裁依据。

---

## 责任边界（不可逾越）

1. 系统产出 = 待证线索 + 已验证事实；定性权、执法权、法律责任在稽查员/法制审核/税务机关。
2. 证据不足只列待补证清单，不以模型推测单独认定违法。
3. 账外经营、主观故意定性必须人工下户 + 法定程序。

---

## 建议的下一步决策

- 若只想要「报告自带边界声明 + 内部能力最大化」：**第一阶已交付，无需再动。**
- 若要真正逼近「彻底」：**拍板第二阶接哪个 connector**（建议先云帐房 + 企查查），
  我负责写接入层与交叉比对规则，你负责提供凭证。
- 第三阶可在第二阶数据源具备后顺势打通。

> 单靠系统到不了「彻底」；系统（数据勾稽）+ 外部源（独立视角）+ 稽查员（取证与定性）
> 三者合体，才能逼近。本路线图即三者分工的落地计划。
