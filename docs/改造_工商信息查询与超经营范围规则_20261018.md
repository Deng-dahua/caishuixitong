# 工商信息查询 + 超经营范围开票预警（2026-10-18）

> 需求来源：用户《开发并接入工商信息查询功能》任务书（五步 + 四条验收 + 三条约束）。
> 本文按「你会看到什么 → 怎么实现 → 我怎么验的 → 哪些没做到」排列，**不含"我改了什么"式自证**。

---

## 一、你会看到什么

打开 `http://127.0.0.1:8001/projects` → 【新建项目】 → 第 1 步：

1. 「企业名称」输入框右侧多了一个 **【自动查填】** 按钮。
2. 填好企业全称（≥2 字）后点它：
   - **能查到**：统一社会信用代码、法定代表人、注册资本、成立日期、登记状态、注册地址、
     公司类型、经营范围 **自动填进表单**；按钮下方绿字写明「已查填 N 项（来源：…）」，
     还有几项没取到会写「N 项未取得，请手工补齐」。
   - **查不到**：红字「查询超时，请手动填写」，后面跟**逐通道的真实原因**
     （例：`local_db：本地库无该企业（需外部通道）；gsxt：被公示系统风控拦截（命中：验证码）`）。
     表单其余内容不受影响，**项目照样能建**。
3. 若登记状态是「注销 / 吊销 / 撤销 / 清算」，按钮下方弹出**红色警告条**：
   「登记状态异常：该企业登记状态为「吊销」⇒ 主体资格存疑，签订合同/开票/收款均须核验…」
4. 无 `project.write` 权限的账号**看不到这个按钮**（与"新建项目"同一套门控）。
5. 跑了「一键分析」后，报告里多一类疑点：**超经营范围开票预警**——
   列出「销项发票开具「XX、YY」，与工商登记经营范围（…）无对应类目」，
   并给出相似度、核证清单与反证条（真实交易且已依法登记的，不认定为本项）。

数据库里能查到落库的工商档案（验收第 2 条）：

```sql
SELECT name, tax_id, legal_representative, registered_capital, registration_status,
       business_scope, source, fetched_at, project_id
FROM sys_company_info ORDER BY id DESC;
```

## 二、怎么实现的（分层＝单一权威）

| 层 | 文件 | 职责 |
|---|---|---|
| 配置 | `config/business_info.json` | **唯一调参入口**：缓存 TTL、通道顺序、UA、超时、延迟、阈值、同义词组、等级 |
| 清洗 | `engine/business_info/dto.py` | 杂乱输入 → 标准 DTO；数字走 `numparse`，日期/状态/类型归一 |
| 取数 | `engine/business_info/providers.py` | `local_db`（本系统账套/项目库）+ `gsxt`（公示系统页面抓取） |
| 落库 | `engine/business_info/store.py` | `sys_company_info`（一表兼**缓存** + **档案**，按 `name_key` 唯一） |
| 编排 | `engine/business_info/service.py` | 缓存 → 通道 → 清洗 → 落库 → 关联项目；**失败不抛异常** |
| 接口 | `business_api.py` | `GET /api/v1/business/query`、`GET /api/v1/business/cached` |
| 规则 | `engine/business_scope_rule.py` | 品名 × 经营范围相似度 → 发现（`RL-INV-005`） |
| 接线 | `engine/pipeline.py`（封印**之前**） | 与「上传报表勾稽」同一接入点；失败必留 `pipeline_log` |

要点：

- **不碰核心执行逻辑**：解析链、规则执行链一行未改；规则以"数据 + 新模块 + 一处接线"接入，
  红线本体登记在 `tax_redlines._BATCH_REDLINES`、规格在 `_BATCH_SPECS`、归属在
  `redline_detector_attribution.json`（项目规定的三处，缺一即被审计拦下）。
- **缓存**：`TTL 168h`（7 天）内直接命中，**不再发外网请求**（这是反爬的第一道闸）；
  超 TTL 但在 `grace 720h` 内、且外网失败时，回退展示旧数据并**标注 `stale=true`**（不冒充新数据）。
- **免费、无 Key、无代理**：`gsxt` 用 `requests` + `lxml`，UA 随机、请求前随机延迟
  `800~2200ms`、`trust_env=False`（本机 `http_proxy` 会让本地与内网探测静默失败）。
  cookie 只从环境变量 `GSXT_COOKIE` 读（人工过验证码后自配），**不入代码、不落盘**。

### 为什么没引入 `gsxt_crawler` 这类开源库

评估过的项目均依赖**付费打码平台**或已停更（多停在 2022 年前后），且要在代码里塞 Key/账号——
与「免费」「无硬编码 Key」两条约束直接冲突。故按任务书的兜底方案自研，
HTML 解析用 **`lxml`**（已在 `requirements.lock` 内，不新增未验证依赖），未引入 `beautifulsoup4`。

## 三、规则口径（这条必须说清楚，否则会误伤企业）

**「超经营范围开票」本身不当然违法**：企业超范围经营真实业务、依法变更登记后仍可开票。
真正指向的是《发票管理办法》第二十一条——**不得开具与实际经营业务情况不符的发票**（虚开）。

所以本规则的口径是「**预警线索**」，不是定性：

- 只报**明显对不上**的：相似度 < `0.2`；`0.2~0.5` 一律归「不确定」**不报警**（宁缺勿错）；
- 品名按票面惯例拆 `*税收分类*具体名称`，**两者任一命中即视为在范围内**
  （否则「毛巾 × 日用百货」「口红 × 化妆品」这类同义不同字会全被判超范围）；
- 反证条写进红线 `constituents` 第 4 条：**已依法变更登记、或属无需许可的一般项目且交易真实的，不认定为本项**；
- 拿不到经营范围 / 拿不到销项品名 ⇒ **不产发现**，回执写「本项未参与」，
  绝不把"没数据"当成"没问题"。

端到端测试证明的是**行为**，不是"代码里有这行"：

- 未登录 ⇒ **401**；
- 登录后按真实账套名称查询 ⇒ `ok=true`，`tax_id/business_scope` 与本系统账套一致，`source_detail` 含「本地」；
- 同一请求**落库**：`sys_company_info` 多一行，`project_id` 已关联，`fetched_at` 非空；
- 第二次调用 ⇒ `cache_hit=true`（**提供方一次都没被再调用**，用计数断言）；
- 查不到 ⇒ HTTP **200** + `ok=false` + 「请手动填写」+ `attempts` 逐通道原因。

真实账套（`company_id=1`，五金零售）跑一键分析：

```
经营范围：五金产品零售;日用百货销售;针纺织品销售;化妆品零售;包装材料及制品销售;橡胶制品销售;…
销项品名：*设计服务*设计服务费 / *广告服务*广告发布费 / *信息技术服务*信息服务费 / *现代服务*其他现代服务 / *现代服务*策划服务费
判定：5 项全部「不匹配」（相似度 0.00）⇒ 产出 1 条预警，进入报告
```

**这一步抓出了两个真实缺陷（都不是设计时想到的）**：

1. 发票品名带 `*税收分类*` 前缀，整串比对让「设计服务费」凭一个「服」字与「服装」沾上；
2. 字符重合率的分母用了**最短串** ⇒ 单个汉字重合就有 0.33 ⇒ 9 项真实超范围品名**全部落进
   「不确定」档、零报警**（规则等于没上线，而单元测试全绿）。

两处都已修，并固化为 `RealDataRegressionTests`（用真实经营范围与真实品名做回归）。

## 五、没做到 / 有落差的地方（不掩盖）

1. **公示系统实时抓取拿不到数据**。`gsxt.gov.cn` 有验证码/滑块与频率风控，没有免 Key 的公开 API，
   `GsxtProvider` 会**如实失败**并给出命中项（如"验证码"），前端显示「查询超时，请手动填写」。
   这是任务书第 2 步明确要求的降级行为，但**不等于"能查到全国企业"**——
   目前真正可用的通道是 `local_db`（本系统已录过的企业）与被风控放行时的抓取。
2. **报告疑点层等级 = 中风险，发现对象 / 风险列表 = 高风险**。
   原因：报告层对"无对应红线检测的独立事项"统一取「中风险」
   （`engine/enterprise_report.py:5739`，属**规则执行核心**，按你的约束 1 未改）。
   要彻底统一，需要把本规则接进 `redline_detection` 的检测器注册（同样是核心层）。
   → 已登记 **B-08**。
3. **同义词组需要持续扩充**。`毛巾/牙膏 → 日用百货`、`口红 → 化妆品` 这类靠的是
   `*税收分类*` 兜底；若票面没有 `*类别*` 前缀、且字面完全不同，会判"不匹配"。
   扩一个品类只需在 `config/business_info.json::scope_rule.synonym_groups` **加一行数据**，
   不改任何逻辑分支。
4. **未做并发/容量实测**。本次没有对查询接口做压测（超出任务范围），不给"可支撑并发数"这类数字。
