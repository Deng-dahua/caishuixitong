## 0. 执行规则（先读这一节）

### 0.1 五条铁律（违反即返工）

| # | 铁律 | 判据 |
|---|---|---|
| R1 | **只增不改** | 新增走新文件/新键/新端点；改现有须在任务卡"建议修改文件"中**逐个列名**并说明理由 |
| R2 | **不一次性重构** | 禁止拆分 `main.py`/`tax_risk.py`/`database.py`；禁止批量改 import 路径；禁止更换技术栈 |
| R3 | **唯一权威 + 薄转发** | 每概念一个权威；新增同类对象 = **只加一行数据，不改逻辑分支** |
| R4 | **结果级验收** | 每个任务验收都必须能回答"**打开 X，从上到下你会看到**…"；不接受"我改了什么"式答复；判据须**反向验证**（注入缺陷 ⇒ 必须变红） |
| R5 | **缺失≠0** | 取不到数据一律 `None` + 状态字段，禁用默认值静默顶替 |

### 0.2 每个任务完成后必跑（**固定收尾**，不单列工时）

```bash
.venv/Scripts/python.exe -m pytest tests/ -q      # 全量，不得中断（中断会留损坏文档）
.venv/Scripts/python.exe tools/audit_consistency.py   # 须 ERROR 0 / WARN 0

.venv/Scripts/python.exe scripts/_verify_baseline_numbers.py  # 基线数字未被改坏（21 项）
```

> ⚠ **全量测试绝不可中途终止**（历史事故：被 SIGTERM 杀后文档留脏数据；另会误删执行回执 `data/logs/pytest_last_run.json`）。
> ⚠ 改了被 D1 文档锁定的数字（如 `passed`）⇒ 须**同步全部文档**，否则 D1 报 ERROR。
