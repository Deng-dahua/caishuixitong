# 部署手册

> 适用版本：仓库根 `VERSION` 文件（当前 `2026.10.18`）。
> 与《运维手册》的分工：**本文只管"从零装起来"**（环境、依赖、首次启动、验收、升级、回滚）；
> 日常启停、排障、备份恢复、巡检见 `docs/运维手册.md`。

---

## 1. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11 或 Windows Server 2019+ | 启动脚本是 `.bat`；Linux 下用 §6 的命令行方式 |
| Python | **3.13**（本项目在 3.13.12 上验证） | 装到 `PATH`，`python --version` 可见 |
| 磁盘 | ≥ 20 GB 可用 | `data/backups` 会持续增长（默认保留 14 份） |
| 内存 | ≥ 4 GB | 10 万行 Excel 解析峰值约 1.5 GB |
| 端口 | **8001** 可绑定 | 被占用时改 `start8001.bat` 的 `set PORT=`（同时改 `APP_PORT`） |
| 时区 | 中国标准时间 | 报告时间戳与"超期天数"按本地时间算 |
| 浏览器 | Chrome / Edge 最新版 | 旧版 IE 不支持 |

> **必须用 `127.0.0.1` 访问，不要用 `localhost`**：后者可能解析到 IPv6 `::1`，
> 而服务只绑 IPv4，会得到"连接被拒绝"。

## 2. 安装（首次）

```bat
:: ① 取代码
git clone <仓库地址> caishuixitong
cd caishuixitong

:: ② 建虚拟环境（必须用 .venv 这个目录名，启动脚本按它找解释器）
python -m venv .venv

:: ③ 装依赖
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

**无外网环境**：在有网机器上
`pip download -r requirements.txt -d wheels\`，把 `wheels\` 拷到目标机，再
`pip install --no-index --find-links wheels\ -r requirements.txt`。

## 3. 初始化数据目录

默认数据根是 `./data`，可用环境变量 `APP_DATA_DIR` 指到别处（**推荐在正式环境指到独立盘**）。

```bat
mkdir data
```

首次启动会自动建库、建表、建管理员（见 §4）。**不需要手工执行任何 SQL**。

> 想先做数据隔离演练：设 `APP_DATA_DIR=D:\caishui_sim\data` 再启动，
> 与生产完全分开（本项目用这种方式做验收，不要在同一目录上跑两套实例）。

---

## 4. 首次启动与管理员

```bat
set APP_ADMIN_USERNAME=admin
set APP_ADMIN_PASSWORD=<一个强口令，≥12 位，三类字符>
start8001.bat
```

- 只有**用户表为空**时才会用这两个变量建管理员；已有用户时**不会覆盖**；
- 启动脚本会经 `scripts/serve_supervisor.py` 拉起服务（崩溃自动重启，退避 1/2/5/10/30/60 秒）；
- 服务窗口要保持打开；关闭即停服。

**验收（必须逐条过）**

```bat
:: ① 健康检查 = 200
curl -s -o nul -w "%{http_code}" http://127.0.0.1:8001/healthz

:: ② 能登录（换成你自己的口令）
curl -s -c cookies.txt -X POST http://127.0.0.1:8001/api/auth/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"admin\",\"password\":\"<口令>\"}"

:: ③ 日志已落地且有请求关联 id
type data\logs\app.log
```

浏览器打开 `http://127.0.0.1:8001` → 用管理员登录 → 应自动跳转「数据处理告知」页
（首次）→ 确认后进「首页总览」。

---

## 5. 装完就要做的三件事

1. **改口令**：用临时口令登录后立刻在「修改密码」页改掉；删除 `APP_ADMIN_PASSWORD` 环境变量；
2. **确认备份跑起来了**：侧栏「💾 备份与恢复」→ 应至少有一份；没有就点「立即备份一份」；
3. **配通知（可选）**：既有的 `/api/notifications/config` 可设 webhook；阈值告警
   （`/api/v1/system/alerts`）判定后由它投递。

## 6. Linux / 容器部署（无 `.bat`）

```bash
python3.13 -m venv .venv
.venv/bin/pip install -r requirements.txt
export APP_DATA_DIR=/srv/caishui/data APP_COOKIE_SECURE=0 APP_PORT=8001
.venv/bin/python scripts/serve_supervisor.py
```

要点：
- **必须设 `APP_COOKIE_SECURE=0`**（http 访问）；上 https 反代后改成 `1`；
- 反代时把 `X-Request-ID` 透传（服务会沿用并回传，便于对账排障）；
- **只允许一个实例**：两个进程指向同一个 `security.db` 会出现
  `attempt to write a readonly database`（随机 500）。守护器会拒绝起第二个。

## 7. 升级

```bat
:: ① 升级前先备份（页面点一次，或命令行）
.venv\Scripts\python.exe scripts\backup_cli.py create --note "升级前"

:: ② 停服（关窗口），取新代码
git fetch --tags
git checkout v2026.10.18

:: ③ 依赖可能变化
.venv\Scripts\python.exe -m pip install -r requirements.txt

:: ④ 启动（会自动做表结构增量迁移）
start8001.bat

:: ⑤ 验收：健康检查 200 + 登录成功 + 三个关键页可开
::    /  （首页总览）  /documents（资料）  /legal-library（法规库）
```

**升级后必须做的一致性检查**

```bat
.venv\Scripts\python.exe scripts\ci_check.py --fast
```
期望 4 项全过（资源版本同步 / 前端权限门控 / 审计 ERROR 0 / 版本与变更日志一致）。

## 8. 回滚

代码与数据要**分别**回滚：

```bat
:: 代码回滚
git checkout v2026.10.17
:: 数据回滚（必须先停服）
.venv\Scripts\python.exe scripts\backup_cli.py restore <备份目录名> --yes
.venv\Scripts\python.exe scripts\backup_cli.py list      :: 先看清有哪几份
```

⚠ 数据库**没有迁移框架** ⇒ 回滚到旧版本代码前，必须确认旧代码能读当前表结构；
拿不准就先恢复到"与目标版本同期"的备份（`restore` 前会自动生成 `pre-restore` 后悔药）。

## 9. 常见部署失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 bat 窗口一闪而过 | 缺 `.venv` 或路径含空格 | 用命令行跑 `start8001.bat` 看报错；`.venv` 必须在脚本同级 |
| 浏览器"连接被拒绝" | 用了 `localhost` / 端口不是 8001 | 用 `127.0.0.1:8001`；核对 `start8001.bat` 的 `set PORT=` |
| 登录后立刻跳回登录页 | 没设 `APP_COOKIE_SECURE=0` | 本地 http 必须设；https 环境设 `1` |
| 页面样式/按钮没变化 | 浏览器缓存了旧 JS | 本项目已给所有静态资源加内容哈希 `?v=`；仍有问题就 Ctrl+F5 |
| 随机 500 / `readonly` | 跑了两个实例指向同一 `security.db` | 结束多余进程，只留一个（守护器会拒绝第二个） |
| 启动报找不到 `requirements.txt` | 拿到了不完整的分发包 | 按 §2 重新完整拉取代码 |
