## 五、★ 原「重大范围障碍」已解决（用户裁定：走列表遍历）

### 原障碍
指令要求「横向到边…一个不漏」。实测**检索接口** `search5/search/s` 覆盖不了「法律」与部分
「行政法规」：刑法 / 征管法 / 行政处罚法 / 发票管理办法 / 征管法实施细则**检索命中 0**。
根因：`fgk` 库收录税务总局及财税部门文件，而**该检索接口的字级匹配 + 栏目过滤把它自己库里的
法律/行政法规也排除了**。

⇒ 改走 **E3：栏目列表全量遍历**。反解出列表接口：

```
POST https://www.chinatax.gov.cn/getFileListByCodeId
```

（来源：`/zcfgk/xhtml/js/getManuscript.js`）

### 本轮新增踩坑（均已修）
1. **`flk` 抓取走系统代理 ⇒ `ProxyError` 全失败**：本机有 `http_proxy`，`requests` 默认读环境代理。
   修法 `session.trust_env = False`。⚠ curl 侧此前靠 `--noproxy '*'` 才通，脚本漏了 ⇒ 抓取静默全失败。
2. **清单筛选词 ≠ 检索词**：检索词（精准）用于向数据源提问；在全量库里**圈定专题范围**要用稍宽的
   `inventory_keywords`，否则大幅漏项（实测 TOPIC-001 仅用检索词命中 16 条，宽词命中 293 条）。
   ⇒ 两者分开登记（数据驱动）。
