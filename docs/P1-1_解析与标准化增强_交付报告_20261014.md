1. 把 §5-② 的 **O(n²) 修成 O(n)**，且**解析结果逐元素不变**（性能不得以正确性为代价）。
2. 把 §5-③ 的**静默截断**改成**显式回执**。
3. 把 §5-④ 的**崩溃**改成**安全回退**（不猜）。
4. 标准字段从 35 扩到 **49**（补充凭证/发票/银行/申报/薪酬域的高频列），**不新增必填**（向后兼容）。
5. 提供解析能力字典与字段覆盖度体检接口。

## 四、核心实现说明

### 4.1 O(n²) → O(n)：顺序游标 + 增量消费

**根因**：openpyxl 在 `read_only` 模式下，`iter_rows(min_row=X, max_row=Y)` **每次都要从文件头
流式跳过前 X-1 行**（无随机访问索引）。原实现逐行调用 ⇒ 总代价 `ΣO(r) = O(n²)`。

**修法**（`engine/parse_enhance.iter_rows_range`）：

- 在该 sheet 上维持**一个**流式迭代器（顺序游标），**顺序前进时只消费增量** ⇒ 总代价 **O(n)**；
- **跳转/回退**时退回 openpyxl 区间读（与原实现**逐元素等价**，正确性优先）；
- 走区间读前先 `drop_cursor`：read_only 下两个活跃 reader 会互相干扰。

**同口径保证**：返回形状与 `iter_rows(min_row, max_row, values_only=True)` 完全一致
（`list[list[str]]`，`None ⇒ ""`），故 `main._get_row_values` **无需任何其他改动**。

### 4.2 安全行数（修 §5-④）

`main.py` 里 **24 处** `nrows = sheet.nrows if hasattr(sheet,'nrows') else sheet.max_row`
统一改为 `else _PE.safe_nrows(<sheet>)`；`_detect_header_row` 处的
`min(max_scan + 1, nrows)` 改为 `min(max_scan + 1, _PE.safe_nrows(sheet, nrows))`。

`safe_nrows` 的三级回退：给值 ⇒ 用之；否则 `sheet.max_row`；再不行 ⇒ **0**（不猜，不伪造）。

### 4.3 上限登记 + 截断回执（修 §5-③）

- `ROW_CAPS`：**12 档**上限值登记表（5000 / 3000 / 2000 / 1000 / 500 / 200 / 120 / 50 / 30 / 15 / 12 / 4），
  与 `main.py` 源码实测集合**完全一致**（闸门断言，双向）。
- **`main.py` 的既有字面量一个未动**（"不修改已有功能"）⇒ 由闸门保证"登记表不漂移"。
- `truncation_note(total, cap, label)`：只有 `total` 与 `cap` **都是已知正整数且确实超限**才产回执
  （`total` 未知 ⇒ 返回空串，**缺失 ≠ 0**）。

## 五、结果级验收（可复现）

### 5.1 性能

| 单文件行数 | 修复前 | **修复后** | 倍数 |
|---|---|---|---|
| 1,000 | 11.56s | **0.12s** | ×96 |
| 5,000 | 277.6s | **0.55s** | **×505** |

复杂度判据（`t(5000)/t(1000)`）：线性期望 ≈5、平方期望 ≈25 ⇒ 实测 **4.6**（阈值 12）。

### 5.2 等价性（性能修复的**正确性前提**）

| 判据 | 结果 |
|---|---|
| ① 逐行顺序 `main._get_row_values(r)` vs openpyxl 原生全量读第 r 行 | **401/401 逐元素相等** |
| ② 随机乱序访问（150 次，覆盖**回退路径**） | **全部相等** |
| ③ 直接区间读 `[5,20]` / `[1,1]` | **与原生切片相等** |
| ④ 解析结果级：引擎认出行数 == 原生数据行数 | **相等** |

### 5.3 测试与闸门

| 项目 | 结果 |
|---|---|
| `pytest tests/test_parse_enhance.py` | **7 passed** |
| `_verify_p11_reverse.py`（闸门反向验证） | **5/5 通过**（S2/S3/S4 注入均报 ERROR；S5 恢复**逐字节一致**） |
| `main.py` 行数 | **15156 不变** |
| `tools/audit_consistency.py` D1 锁定行 | **11542 / 12008 / 12948 / 12951 零漂移** |

### 5.4 反向验证的**两处自我纠错**（如实记录）

1. **S4 首轮未变红**：闸门原判据只查"`_PE.safe_nrows(` 是否存在"，而注入只替换**单参数**形式，
   双参数形式仍留在文件里 ⇒ **假绿**。修正：①判据增加"不得存在绕过路径 `else {sheet,s}.max_row`"；
   ②注入改宽正则。修正后 S4 **ERRORS=2**。
2. **S5 首轮"恢复后不一致"是假红**：用 `Path.write_text` 恢复时，Windows 会把 `\n` 规范成
   `\r\n` ⇒ md5 变化。修正：备份/注入/恢复**一律走 bytes**。修正后 S5 逐字节一致。

> 这两处正是项目铁律"反向验证必须能变红、假绿与假红都要当真"的现场案例。
