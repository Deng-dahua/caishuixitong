## 一、先扫描现状（改动前）

既有校验唯一权威：`engine/extract_validate.py`，**6 条规则**（与
`config/standard_fields.json::_validation` 一一对应，**键即规则名**）：

`required_missing`（必填缺失）｜`amount_format`（金额格式错误）｜`period_mismatch`（期间错配）｜
`duplicate`（重复数据）｜`debit_credit_unbalanced`（借贷不平衡）｜`cross_check`（报表勾稽异常）

两条既有设计口径（本轮**沿用不变**）：
- **只报不修**：校验函数不下结论、不改数据，只产出 `{rule, severity, message, detail}`；
- **不确定就不报**：取不到参与计算的量 ⇒ **跳过该规则**，报"无法判定"而非伪装"通过"。

**扫描发现的覆盖缺口**（六条规则都只覆盖"结构级"校验，**没有数据质量类**）：

| 缺口 | 说明 |
|---|---|
| 值域 | 没有"金额异常负值"检查（资产为负、收入为负） |
| 完整度 | 只有"全空"（`required_missing`），**没有"半空"**（列名未被识别导致半数取不到） |
| 时间 | 没有"日期离谱"检查（1990 年、2099 年的笔误） |
| 编码 | 没有"科目编码格式"检查（混入文本的编码会让科目树构建失败） |
| 税率 | 没有"税率档位"检查（7%、8% 之类非法档位） |
| 票据 | 只有整行重复，**没有"发票号码重复"**（重复导入的典型特征） |

## 二、目标

在**不改既有 6 条**的前提下，新增 **6 条数据质量类规则**（6 → 12），全部：
- 适用所有行业/所有企业（不含任何特例白名单）；
- `severity = warning`（不阻断，只提示）；
- 遵守既有两条口径（只报不修 / 不确定就不报）。

## 四、新增 6 条规则（判定口径）

| # | 规则名 | 中文名 | 判据 | 为什么不会误报 |
|---|---|---|---|---|
| ⑦ | `amount_negative` | 金额异常负值 | **仅报表类**字段（资产总计/负债合计/所有者权益/营业收入/营业成本）出现负值 | 借贷列的负值可能是**红字冲销**⇒ 故意不报（测试有反向判据） |
| ⑧ | `null_rate` | 关键列缺失率过高 | 填充率 ∈ (0, 50%) | **全空**由 `required_missing` 报，两者**不重叠**（命中 0 不报） |
| ⑨ | `date_out_of_range` | 日期超出合理范围 | 归一后早于 `2000-01-01` 或晚于"次年年底" | **解析失败的不重复报**（那是 `amount_format` 类问题的地盘） |
| ⑩ | `account_code_format` | 科目编码格式异常 | 非 4~12 位纯数字 | 空值不报（缺失≠错格式） |
| ⑪ | `tax_rate_validity` | 税率非标准档位 | `rate_to_percent` 归一后不在 0/1/1.5/3/5/6/9/10/11/13/16/17 % | **无法解析的单列标注**"无法解析为税率"，不与"档位非法"混为一谈 |
| ⑫ | `duplicate_invoice_no` | 发票号码重复 | 同一表内发票号重复 | **只看号码**；整行重复由 `duplicate` 报，两者不重叠 |

`rate_to_percent(value)`：`"13%"` ⇒ 13.0；`"0.13"` ⇒ 13.0；`13` ⇒ 13.0；`"免税"` ⇒ `None`（**不猜**）。

### 报告中的"可触发"与"反敏感"判据（防空转）

- **可触发**：6 条新规则各自被针对性样例**真的触发**（不是"写了代码但从不生效"）；
  且**反向**断言"借贷列负值不得被判为报表负值"、"空行不得触发新规则"。
- **反敏感**：把 `STD_TAX_RATES` 改为 `(7.0,)` ⇒ `tax_rate_validity` **不再触发**；
  把 `_FILL_FLOOR` 置 `0.0` ⇒ `null_rate` **不再触发** ⇒ 证明判据**真的在读这些常量**。

### 本轮修掉的一处**真实缺陷**（自查发现）

⑧ 首版写成 `for n in (names or [])` ⇒ **`names` 为空时一条都不遍历**，规则**永不触发**。
测试用例 `[{"购方名称":"A"},{"购方名称":""},{"购方名称":""}]` 首轮即为 `[]`（被测试抓到）。
已修为 `fill_names = list(names) or [全部标准字段]`，并加注释记录该坑。

## 六、未完成 / 风险

1. **未做规则开关**：12 条规则**全部常开**。若某企业数据本就稀疏（如新建企业无上年数据），
   `null_rate` 可能有噪声。后续可考虑在 `standard_fields.json` 为每条规则加 `enabled` 开关。
2. **`severity` 未分级细化**：6 条新规则统一 `warning`。若业务侧希望某些（如"发票号重复"）
   升级为 `error`，改 `_issue(..., "error")` 一处即可（尚未改，等业务裁定）。
3. **未做规则命中率统计**：目前只有"每表异常清单"，没有"跨项目规则命中排行"。
4. `tax_rate_validity` 的法定档位表**未接税法版本管理**（P1-6 可考虑接入）。
