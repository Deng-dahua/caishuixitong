# 删除「分析报告」页签工具条 + 修全站可见文案的 markdown 记号泄漏（2026-10-19 第三批）

> 需求来源：用户贴回 `/reports`「分析报告」页签的一段界面元素清单，末尾写 **「删除」**。
>
> 本文按「**你会看到什么** → 为什么之前做不到 → 怎么实现 → 我怎么验的 → 遗留」排列。

---

## 一、你会看到什么

### ① `/reports`「分析报告」页签
页面顶部那一块（**【导出PDF】【缓存】【删除报告】** 三个按钮 + 一段
「本页签展示…资料的上传/分类请前往…」的说明文案）**整块消失了**。

现在该页签**只有报告正文**，层级干净：页面标题「📄 报告生成与导出」→ 页签 → 报告信息卡 → 正文。

> **为什么那段说明文案可以删**：报告正文自身已带完整封面（报告编号/被审企业/报告日期/资料数量）
> 与全部章节；而「资料上传/发起分析」的引导在侧边栏与首页总览里都有。
> 更关键的是：**【删除报告】与「报告列表」页签的【删除选中】是两个删除入口**，
> 并存容易误用 —— 现在只留后者（它带勾选、有确认、逐条回报）。

### ② ★ 顺带修掉：页面上到处可见的 `**星号**`

你贴回的那段文字里 **「展示`**最近一次**`一键稽查分析」** —— 那两个星号是**真的被你看到了**。
这是**全站级**的问题，本轮共修掉 **6 类来源、20+ 处**：

| 来源 | 例子 | 修法 |
|---|---|---|
| HTML 静态文案 | `/reports`「同一份底稿的`**`范围/粒度`**`」 | 改 `<b>`（4 处，涉及 3 个页面） |
| JS 拼 HTML | `/legal-topics`「该规则`**`无可确证条款`**`」 | 改 `<b>`（4 处） |
| JS 的 `confirm()` 对话框 | 删除确认里的 `**`交付物登记与落盘文件`**` | 改**纯文本**（`confirm` 不解析任何标记，写 `<b>` 会显示尖括号） |
| 后端下发 + `innerHTML` | `/dashboard`「大屏`**`不抽样、不估算`**`」 | 改 `<b>` |
| 后端下发 + `textContent` | `/industry-indicators`「该区间在`**`未匹配到行业`**`时使用」 | 改**纯文本** |
| 后端下发 + `esc()` 转义 | `/rule-versions`、`/consent`、`/rules` 等 | 改**纯文本**（`<b>` 会被转义成字面量，**比星号更难看**） |

**实测结果**：21 个页面全扫，只剩 `/audit-logs` 的**历史留痕**里还留着一条 —— 那是
**append-only 审计记录**（当时源码里的文案），改源码不回改历史行。用一条**新**动作验证：
新记录已无星号（`新兴 note 含 ** = False`）。

## 二、为什么之前会这样（根因）

**语境混用**：写文案时沿用了 markdown 习惯（`**强调**`），但
- `.html` 里 → 浏览器把 `**` 当普通字符**原样显示**；
- `textContent` → 同样原样显示；
- `confirm()/alert()` → 对话框不解析任何标记，`**` 和 `<b>` 都原样显示；
- `esc()` 转义后再 `innerHTML` → `<b>` 会被转义成字面量 `<b>...</b>`。

⇒ **同一个"想加粗"的意图，在四种渲染语境下有四种正确写法**，而之前没有任何判据拦截。

## 三、怎么实现

### 3.1 删工具条（只删界面入口，不删实现）
`reports.html` 删掉整个 `<div class="card">…</div>`（3 按钮 + 说明文案）。

**JS 函数本体保留**（`exportTaxDocReportPdf` / `showCacheInfo` / `deleteTaxDocReport`）——
审计闸门 `check_report_consistency` 的**行为级判据**依赖 `exportTaxDocReportPdf` 的函数体
（必须走服务端渲染端点 `/api/tax-risk-docs/export`、禁 `window.print`、须读
`X-Report-Watermark` 回执）。这条口径是本仓既有铁律：**「界面入口下线」≠「实现删除」**。

### 3.2 新增审计闸门 `check_no_markdown_leak_in_html`
静态扫描两类文件，已注册进 `run_checks`：

| 覆盖 | 判据 |
|---|---|
| `static/*.html` | 剥 HTML/CSS 注释、剥 `<style>`/`<script>` 块、去标签 ⇒ 剩余可见文本里不得有成对 `**` |
| `static/js/*.js` | **逐行剥注释**后取**字符串字面量**，含中文且含成对 `**` ⇒ 报错 |

★ 两处关键口径（都是踩坑后定的）：
- **必须逐行剥注释再做字面量匹配**：首版先整段剥注释再跑跨行正则 ⇒ 行尾注释里的
  `**已发出**` 被卷进某个字面量 ⇒ **误报**；
- **只认含中文的字面量**：类名 `[class*="x"]`、正则 `.*?` 等纯 ASCII 场景不误报。

### 3.3 新增可跑验收脚本 `scripts/_verify_visible_text.py`
审计闸门做不到的事：**它不能起浏览器**。而"后端下发的文案会不会显示"**只有渲染才知道**。
该脚本用真 Chrome 逐页扫 21 个页面，判据两条：
① 可见文本含成对 `**`；② 可见文本含**未渲染的 HTML 标记字面量**（`<b>`/`<strong>` 等）。

★ 排除 `script`/`style` 节点 —— 首版把内联 `<script>` 的源码当"可见文本"，
对 `/users` 误报 1 处。

## 五、本轮踩的坑（判据自身，3 处）

| 问题 | 现象 | 修法 |
|---|---|---|
| 闸门先整段剥注释再跑跨行正则 | 行尾注释里的 `**已发出**` 被卷进字面量 ⇒ **误报** | 改为**逐行剥注释**后再匹配字面量 |
| 扫描脚本没排除 `script`/`style` | 内联脚本源码被当"可见文本" ⇒ `/users` **误报** | 加节点类型排除 |
| 「用 `<b>` 就对了」的直觉 | `/consent` 是 `esc(it.body)` 渲染 ⇒ `<b>` 变成**字面量 `<b>`**，比星号更难看 | 按**渲染语境**选写法（4 种语境 4 种写法） |

★ 另一处**非缺陷但需说明**：`/audit-logs` 的历史留痕里还有星号 —— 审计日志是
**append-only**，改源码不回改历史行。已用"新动作产生的新记录无星号"证明**源码已修**。

   docstring / 内部说明（**不会渲染**）。本轮只修了**实测能渲染**的那些
