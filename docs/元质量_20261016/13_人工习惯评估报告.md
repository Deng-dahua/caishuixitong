## 三、优化建议

| 编号 | 问题 | 类型 | 影响面 | 修复成本 |
|---|---|---|---|---|
| **H-01** | **记忆机制：17/21 模块不记住上次选择**（只有首页/资料/解析/报告页用了 localStorage）。用户每次进页都要重选项目与筛选条件 —— 这是最高频的重复劳动。 | 效率型 | 17 个模块 | 低：把「上次选的项目/筛选」写 localStorage，进页时回填（项目下拉已存在） |
| **H-02** | **键盘操作：11 个模块完全无快捷键，10 个仅有零散 Enter/Esc**，无系统化快捷键。风险复核这类高频逐条操作只能鼠标点击。 | 效率型 | 21 个模块 | 低：先加 3 个通用键（Esc 关详情 / Enter 提交 / Ctrl+Enter 提交并下一条） |
| **H-03** | **确认机制：6 个非只读模块的破坏性操作前无二次确认**（资料解析删字段、风险批量处置、报告生成覆盖、用户/角色删除、AI 辅助提交）。 | 数据错误型 | 6 个模块 | 低：统一 `confirm()` 或既有弹窗组件，仅在破坏性动作前调用 |
| **H-04** | **撤销机制：7 个模块无撤销/回收站入口**。后端其实已有 `move_to_trash`（可恢复），但前端没有「回收站」页面 —— 能力存在、用户摸不到。 | 数据错误型 | 7 个模块 | 中：加一个只读「回收站」页（列出 trash 目录 + 一键还原） |
| **H-05** | **批量操作：10 个模块只能逐条操作**（风险复核、资料解析、报告模板、规则版本、用户管理最痛）。风险复核 20+ 条要一条条点。 | 效率型 | 10 个模块 | 中：风险复核已有 `bulk_review` 后端（BULK_LIMIT），前端补全选+批量 |

> 只读页面（仪表盘/法规库/专题/材料/行业指标/规则库/审计日志/多税种模型）不需要批量、确认与撤销 —— 报告中已标「无需」，**未计入缺口**。

## 四、判定口径

| 维度 | 判据 |
|---|---|
| 操作顺序 | 主流程步骤序（复用 S1~S4 真跑记录）是否自然；只读页无此问题 |
| 信息分组 | 页面内 `section-card`/`fieldset`/`.card`/`panel` 分组数 ≥2 |
| 默认值 | `<option selected>` 或 `<input value=…>` 预填 |
| 快捷操作 | `批量`/`bulk` 类入口 |
| 错误提示 | 具体提示（请…/格式/必填/不存在）÷ 笼统提示（操作失败/保存失败） |
| 确认机制 | `confirm()` 或「确定要/确认删除」 |
| 撤销机制 | 撤销/回收站/还原/恢复/重开/reopen/回滚 |
| 记忆机制 | `localStorage`/`sessionStorage` |
| 批量操作 | 全选 + 批量执行 |
| 键盘操作 | `keydown/keypress` + `.key` 判定 + 快捷键文案 |

> ⚠ 判据只认**代码里真实存在的字样**（已抹注释与 docstring），不认「注释里说支持」。逐项证据（含行号）在 JSON 里。
