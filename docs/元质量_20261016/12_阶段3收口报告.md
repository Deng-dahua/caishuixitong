## 三、P0 建议落实（本轮完成）

### P0-1｜登录会话每请求写库导致随机 500 → **已修复**

**现象**：阶段 3 采集时 3/19 模块出现接口 500；根因是 `/api/auth/me` 在**每个请求**上
执行 `DELETE FROM sessions WHERE expires_at<=?` + `UPDATE sessions SET last_seen=?`
（两次写事务），在 WAL + 多连接下抛 `attempt to write a readonly database`。

**两层根因，都已修**：

| 层 | 修法 | 判据 |
|---|---|---|
| ① 每请求两次写 | `get_session` 改**只读主路径**：过期判定移到 SQL（`AND s.expires_at > ?`）；清理改**每 60s 一次**；`last_seen` **每会话每 60s 一次**；写库失败**不阻断读取**（有日志 + 计数，可观测） | 10 次连续读取 → 写语句 ≤2 次（修前 20 次） |
| ② 每连接切 `journal_mode` | `_connect()` **不再**执行 `PRAGMA journal_mode=WAL`（改在 `init_security_db()` 设一次）+ `busy_timeout=10000` | `_connect` 内不得出现 `journal_mode`（AST 判据） |

**⚠ 修 ① 时必须同时补 `expires_at` 显式判定**：原实现靠"每请求 DELETE"淘汰过期会话，
把 DELETE 改成低频后，若不在 SQL 里比较 `expires_at`，**清理周期内的过期会话会被放行** ——
那是安全回归。本项专门有测试锁定（并做了注入验证：去掉该条件 → 用例精确变红）。

**实测（T1）**：
- 并发 **180 次** `/api/auth/me` → **180 × 200**，0 次 500；
- 19 个页面并发访问 → **19 × 200**；
- 服务端日志 500 = **0**、readonly = **0**、会话告警 = **0**；
- 19 个模块浏览器控制台错误合计 **0**（修前 3 个模块有 500）。

### P0-2｜首页无任何总览内容 → **已修复**

**修前**：正文 0.4 KB、说明性文案 **0 字**、无反馈区；且 `init()` 默认落点是
`tax-doc-analysis`，登录后**立刻被切走**，用户看不到任何导航上下文。

**修后**：
- 四块 KPI：**待处理风险 / 超期未处置 / 本项目资料 / 上次分析**（全部复用既有只读接口，**未新增后端**）；
- 最近更新项目表（首行即"数据来源"）；
- **口径说明**（写明指标取自最近更新的项目、超期与从未处置分开计、缺失 ≠ 0、首页只展示不判定）；
- 5 个快捷入口（按 `data-perm` 门控，审计员实测看不到「新建项目/一键分析」）；
- 默认落点改**首页**（仅首次访问；老用户仍回上次页面），侧栏新增「🏠 首页总览」。

**效果**：首页均分 **3.38 → 4.25**；说明性文案 **0 → 624 字**；正文 **0.4 → 0.8 KB**；
满意度 **4.42 → 5.00**；高评分占比 **87.5% → 91.4%**。

**三个隐蔽坑（都已写进守护测试）**：
1. 容器 id 必须是 `page-home`（`core.js` 只隐藏 `[id^="page-"]`，否则与内页**同时显示**）；
2. `navigateTo` 有**内页白名单**，不加 `home` 会被**静默改回** `tax-doc-analysis`（本轮实测踩过）；
3. `analysis-jobs` 的返回键是 `jobs`、参数是 `limit`（按 `items`+`page_size` 写会永远取空 ⇒
   首页错误显示"未分析"，而项目其实已成功）。
