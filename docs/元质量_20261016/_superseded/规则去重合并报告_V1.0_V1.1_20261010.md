**A. 同一判据合并**（去重，不新增条数）：见 §3 的三处；合并后各自**保留双向输出**（A→B 与 B→A 是两种风险提示）。

**B. `VR035` 印花税"其他税目漏报" → 逐税目**：现为总括式，候选 `SD-007/008/010` 要求逐税目 ⇒ 合并为**按税目名逐项输出**（税目清单登记在 `params.SD-007.contract_types`）。

**C. ★ `FIN-017` 方向相反，必须双分支**：候选判"应收账款周转率**偏低**（<行业×0.7）"，系统 `financial_analyzer` 判"**过快**（>20 次）"。二者指向不同风险（前者=收入不实/回款停滞，后者=虚增收入/突击开票）。**若只取一方会漏报**，合并后须同时输出两种情形，阈值分别登记。

**D. `INV-009/010` 三流一致**：系统已有发票流↔资金流（`VR025/VR028`），合同流侧较薄（`RL-CIT-001` 购销闭环）。合并方案＝在既有"发票↔资金"检测器上**加一条"发票对手方 ↔ 合同对手方"比对**（数据源 `contracts` / `contract_payments`）。

**E. 消费税六条并入 `RL-SPT-002` 家族**：系统对消费税只有一条红线，候选细分为税目/依据/自产自用/委托加工/进口/成品油/白酒 ⇒ 合并为 `RL-SPT-002` 下的**多分支判据**（不新增红线，避免条数绑定被破坏）。

**F. `TAXINC-001` 补齐"申报侧勾稽"**：系统已能判"优惠条件是否符合"，缺"不符合却仍按优惠申报" ⇒ 合并需**新增申报表侧证据**（当前账套无优惠申报表 ⇒ 先置疑）。
