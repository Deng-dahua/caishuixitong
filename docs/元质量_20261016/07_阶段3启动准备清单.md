## 一、阶段 3 目标

## 二、评估维度

| # | 维度 | 评估问题 |
|---|---|---|
| 1 | 可发现性 | 用户能找到这个功能吗？ |
| 2 | 可理解性 | 用户能理解这个功能吗？ |
| 3 | 可操作性 | 用户能顺利完成操作吗？ |
| 4 | 可反馈性 | 用户知道操作结果吗？ |
| 5 | 可恢复性 | 用户操作错了能恢复吗？ |
| 6 | 可学习性 | 用户第二次能用得更快吗？ |
| 7 | 效率 | 用户能用更少步骤完成吗？ |
| 8 | 满意度 | 用户会用得舒服吗？ |

## 五、评估方法

1. **每个功能逐项评估**（不抽样；以侧边栏可见项 + 页面内主流程为清单）。
2. **每个维度打分 + 问题**：建议 5 分制（1 差 / 3 中 / 5 好），并逐条写"给分理由 + 具体问题"。
3. **真浏览器取证**（沿用阶段 2 的方法与隔离实例）：每项至少一次真实路径操作；
   评分须有**可回读证据**（页面文本 / 请求状态 / 截图），不接受"看代码觉得应该行"。
4. **输出优化建议**：每条建议标注类型（阻断型/体验型/效率型…）+ 影响面 + 修复成本。
5. **负向纪律**（沿用阶段 2 教训）：测试驱动自身问题（选择器、时序、对话框）**不得计为产品问题**。
