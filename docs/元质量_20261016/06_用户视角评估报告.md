## 二、评分方法（可复核）

**评分规则是固定的档位判据，不是逐项拍脑袋** —— 同一份证据跑两次必得同一结果（实现：`scripts/_score_ux.py` 的 `RULES` 区）。

| 维度 | 判据 |
|---|---|
| 可发现性 | 侧栏全可见 + 顶栏横向入口数 |
| 可理解性 | 说明性文案字数：≥200→5 / 50~199→4 / 1~49→3 / **0→2** |
| 可操作性 | 可用控件数 ≥5 且无禁用→5；有禁用→4；控件 <5→3 |
| 可反馈性 | 反馈载体 ≥2→5 / 1→4 / **0→2** |
| 可恢复性 | 恢复类入口 ≥2→5 / 1→4 / 0→3（只读页不扣重） |
| 可学习性 | 占位示例+帮助入口 ≥3→5 / 1~2→4 / 仅 title→3 / 全无→2 |
| 效率 | 主流程实测步数 + 首屏耗时（S1 真跑数据） |
| 满意度 | 控制台错误 0→5 / **≥1→2**；正文过少且无说明→3 |

> ⚠ **口径边界（必须知道）**：上述多为「**存在性**」判据（有没有、有多少），并不等于「**好用**」。流程是否顺畅的结论来自阶段 2 的 S1~S4 真跑（S1 全链路 12/12、S2 7/7、S3 8/8、S4 5/5）。本报告不把「有反馈区」夸大为「反馈清晰」。

## 四、优化建议清单

| 编号 | 问题 | 类型 | 影响面 | 处置 / 修复成本 |
|---|---|---|---|---|
| **P0-1** | **会话读取时写库导致随机 500**：`/api/auth/me` 实测 7 次 500（跨 3/19 模块随机出现），根因是 `security.py::get_session` 每次请求都执行 `DELETE FROM sessions WHERE expires_at<=?` 与 `UPDATE sessions SET last_seen=?`，在 WAL + 多连接下抛 `sqlite3.OperationalError: attempt to write a readonly database`。前端门控据此从严隐藏（现已有退避重试自愈，但用户仍可能看到按钮短暂消失）。 | 稳定性 | 全站（19/19 模块每次加载都会调它） | **已落实 ✅**：①`get_session` 改**只读主路径**：过期判定移到 SQL（`expires_at > now`），清理每 60s 一次、`last_seen` 每会话每 60s 一次，写失败不阻断读取（有日志）；②`_connect` 不再每连接切 `journal_mode`（改初始化设一次）+ `busy_timeout`；③实测：并发 180 次 `/api/auth/me` 全 200、19 页全 200、服务端 **0 次 500** |
| **P0-2** | **首页无任何总览内容**：正文仅 0.4 KB、说明性文案 0 字、反馈载体 0 处，登录后只有一个侧栏，用户不知道「该先做什么」。这是本报告唯一均分低于 3.5 的模块（3.38）。 | 体验型 | 所有用户（尤其首次使用） | **已落实 ✅**：首页四块 KPI（待处理风险 / 超期未处置 / 本项目资料 / 上次分析）+ 最近项目表 + 口径说明 + 5 个按权限门控的快捷入口；默认落点改首页（首次访问）、侧栏加「🏠 首页总览」；均分 **3.38 → 4.25** |
| **P1-1** | **可学习性为全站最低维度（3.79）**：5 个模块既无占位示例、也无示例/帮助入口 —— 首页（title 0）、一键分析（占位 0）、角色管理（占位 0）、数据大屏（占位 0）、法规专题（占位 1）。用户「第二次使用」仍需重新摸索。 | 效率型 | 5 个模块 | **低**：给主输入框补 `placeholder`、给每页加一行「怎么做」的灰字提示 |
| **P1-2** | **数据大屏只有 2 个控件**（纯展示、无筛选）：想看某个项目/某个期间的大屏，只能回其它页面切换上下文。可操作性 3 分（全站最低档）。 | 效率型 | 数据大屏 | **低**：加「项目 / 期间」两个下拉，复用既有查询参数 |
| **P1-3** | **说明文案与控件数量失配**：稽查项目（说明 9 字 / 16 控件）、资料上传与管理（说明 15 字 / **80 控件**）。控件越多越需要分层与解释，现在信息层级偏平，新用户难定位主操作。 | 体验型 | 2 个高频模块 | **中**：给「主操作」加视觉层级 + 一行用途说明（不改功能） |
| **P1-4** | **一键分析未解释 8 个步骤的含义**：只显示步骤名与进度，用户看不出「第 4 步在做什么、要等多久」。 | 体验型 | 一键分析 | **低**：步骤区每步加一行说明（已有步骤元数据） |
| **P2-1** | 导航冗余：侧栏 **DOM 21 项 / 可见 21 项**，而实际业务模块 19 项 —— 「修改密码」「AI 辅助」与业务模块同级，稀释了主路径。 | 体验型 | 全站导航 | **低**：把工具类（改密）收起到底部或用户菜单 |

**为何 P0 只有两条**：其余缺口都属「能做得更好」，不影响「能不能用」；而 P0-1 会让用户在**任意页面**遇到数据不全，P0-2 让**每个新用户**第一次登录就没有方向 —— 这两条才是真正的用户视角阻断。
