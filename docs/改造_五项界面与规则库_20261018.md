## 一、你会看到什么

### 1. 稽查项目管理：勾选 + 删除选中
打开 `/projects`，表格最左多一列勾选框，表头有全选框；工具栏多一个红色
**【删除选中（N）】**（不勾选时**不显示**）。

- 勾 1 行 → 按钮出现并显示 `删除选中（1）`；全选 → 显示本页全部条数。
- 点它 → 弹确认框列出**将删除的项目名与编号**；项目下有资料时**逐条**问
  「是否连同资料一起删除？」（资料进回收站，可还原）。
- 完成后提示 `删除完成：成功 N 个（其中 M 个含资料已移入回收站），跳过 N 个，失败 N 个`。
- 翻页/搜索/刷新会**清空勾选** —— 不会删掉你没看到的项目。

### 2. 资料上传与管理：去掉「项目管理」按钮
顶栏只剩【返回主界面】，不再有跳去项目页的按钮。

### 3. 解析与校正并入资料页
打开 `/documents`：

- 上传区的提示变成「每个文件上传成功后**立即解析**，无需再单独点『开始解析』」；
  拖文件进去，队列里每个文件直接显示 **已完成（已解析）**（失败则显示
  `已上传（解析未成功：原因）`，**上传本身不失败**）。
- 新增 **【批量解析】** 卡片（范围：待解析/失败 或 全部；本次最多 50 份）。
- 新增 **【解析能力】** 面板（标准字段数 / 校验规则数 / 行数上限档位 / OCR 引擎状态）。
- 列表行内「解析结果」仍可看标准字段、校验异常并**人工校正**。
- 侧边栏的 **「资料解析与校正」条目已消失**，`/extract` 地址不再可用。

### 4. 一键分析任务「查看」按钮
点历史列表里的【查看】后：**那一行会高亮**，页面**平滑滚到「当前任务」卡片**
并短暂描边，卡片里显示作业号/进度/步骤。

### 5. 规则库与风险发现
打开 `/rules`：

- **层下拉全部中文**：`税务红线库` / `专项红线检测器` / `已验证原子规则` /
  `权威事实核查规则` / `缺口风险检测器` / `缺口纳税义务项` /
  `外部候选清单 v1.0 / v1.1 / v1.2`（鼠标悬停显示原值与说明）。
- 表格列：**严重度**（高/中/低风险）、**版本**（已登记 / `沿用 VR026 v1.0.0` / `V1.2（未发布）`）、

| 闸门 | `tools/audit_consistency.py::check_rule_layer_labels` | 层/严重度/候选状态**未登记中文名即 ERROR**；台账处置计数之和必须=候选总数 |

`extract.js`）；`extract_api.py` 的**全部 API 端点一字未动** —— 资料页的自动解析、
批量解析、字段校正、异常处理都用同一套接口，**零后端改动**。

## 四、本轮**实测抓出的真缺陷**（都不是需求里说的）

### 1. `hidden` 属性在 flex 容器里失效 —— 按钮"该藏却一直显示"

`.toolbar { display: flex }` 会**覆盖**浏览器默认的 `[hidden] { display: none }`
（后者优先级更低）。实测 `#btn-del-selected` 带着 `hidden` 属性，`getComputedStyle`
仍是 `display: flex`、`offsetWidth > 0` —— **看得见**。

修法：显式 `[hidden] { display: none !important; }`。

**这个 bug 在「资料上传与管理」页的「删除选中」按钮上早已存在**（同样是 flex 工具栏
+ `hidden` 属性），一直没被发现。两页一起修好了。

> 教训：**"属性设了" ≠ "样式生效"**。此后验收可见性必须读 `getComputedStyle` 或
> `offsetWidth`，不能用 `hasAttribute('hidden')`。

### 2. 「查看」按钮"没反应"的真因不是没绑定

按钮其实一直能工作（`selectJob` 有定义、DOM 里有 `onclick`、点击后**上方卡片内容确实变了**）。
问题是「当前任务」卡片在**任务历史表格的上方** —— 用户盯着表格里那一行，点完屏幕
**可见区域什么都没动**，主观上就是"没反应"。

修法：行内高亮 + 平滑滚动到卡片 + 短暂描边；同时把内联 `onclick` 换成
**事件委托**（内联属性一旦被 CSP/编码问题破坏就是彻底静默，委托至少能留痕）。

### 3. 候选清单 `status` 是过期快照

12 条标着"未入库（missing）"，但 `by` 字段里写着「VR075（本批落地）」——
系统**早就实现了**。台账现在自动核对"`by` 指向的规则号是否真实存在"，
过期项单列为「清单状态过期」，避免出现"清单说没入库、系统其实早就有"的自相矛盾。

## 五、没做到 / 有落差（不掩盖）

1. **候选清单不能"全部入库"**。460 条里**真正可执行只有 2 条**：其余 448 条缺
   **538 个字段的取数口径**（`config/rule_dsl_scope.json::var_map` 只登记了 73 个字段）。
   把没有取数口径的规则硬"入库"，只会得到一堆永远不触发、或触发即错的判据 —— 那比
   不入库更危险。所以本轮的交付是**逐条给出处置结论**（哪 131 条已覆盖、哪 141 条可并入、
   哪 85 条卡在数据源、哪 91 条待定口径），而不是伪造一个"已全部入库"的数字。
   → 已登记 **B-11**（补字段取数口径，分批推进）。
2. **12 条"清单状态过期"未订正清单文件**。订正 `config/rulelist_v1.json` 的
   `status` 字段会改动规则数据源，属另一批变更；本轮先在台账/页面**如实标出**。
   → 已登记 **B-12**。
3. **审计 ERROR 未归零**：16 项中 12 项是既有报告产物级问题（子项未登记、模板句重复），
   另 2 项（`缺料三态不自洽`、`正文暴露内部文件名`）经 **stash 往返对照确认在基线同样存在**，
   非本轮引入。→ 仍按上轮登记的 **B-05/B-06** 处理。
4. **未做并发/容量实测**，不给"可支撑多少并发"这类数字。
