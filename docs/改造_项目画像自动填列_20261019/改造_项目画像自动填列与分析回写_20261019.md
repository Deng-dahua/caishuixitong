## 二、问题一：分析报告用的模板，和「报告模板」模块是同一个吗？

**不是同一套 —— 同一个 `/reports` 页面里有两个页签，走两套文档模型。**

| 页签 | 文档模型 | 是否套用「报告模板」模块 | 实测证据 |
|---|---|---|---|
| **分析报告** | 一键分析链（`tax-doc-analysis.js::renderTaxDocReport`） | **是**。`report_template_meta` 由 `engine/report_template.apply_template` 产出，模板来自 `config/report_compliance.json::templates`，行业→模板映射来自 `engine/industry_params.json`（即「报告模板」模块管理的那 4 个模板） | 报告顶部实测文字：**「报告模板：服务型行业模板（轻资产）（行业：广告传媒）　·　章节顺序：报告定位与合规声明 → 风险事项 → 行业指标对标 → 证据现状与需补资料 → 结论与建议 → 签名与版本记录」** |
| **生成报告 / 导出** | 导出链（`engine/report_service.build_document`） | **否**。`_industry_template_meta()` 返回 `applied=False`，并给出原因 | 代码与声明一致：`meta["reason"]` = 「本导出件按 12 节通用结构装配，行业模板的 9 章重排只适用于「一键分析」报告」 |

**为什么故意不统一**：两条链服务不同目的 —— 「分析报告」是给人**读**的（按行业侧重组织章节、可读性优先）；「生成报告」是**交付物**（固定 12 节，便于跨企业横向比对与归档）。统一成一套会牺牲其中一方。系统在报告里**明说了这件事**，不是悄悄两套。

### ★ 但核实过程中发现一处「声称 > 实际」（如实登记）

分析报告顶部声明「章节顺序：报告定位与合规声明 → 风险事项 → 行业指标对标 → …」（6 章），
而**正文实际是固定的 5 章文书式**（一、检查情况总述与总体结论／二、本轮风险检查确认的具体问题／
三、覆盖范围声明／四、整改验收与下一轮复查标准／五、报告性质和使用说明）。

原因：`engine/report_template.apply_template()` 的实际行为只是**写 `report_template_meta`**
（`out = dict(report); out["report_template_meta"] = meta`），**并未重排任何章节**。
⇒ 报告顶部那句"章节顺序"是**声明**，不是**事实**。

- 本轮**未改**它：改渲染结构属于报告正文级改造，风险远大于收益，且不属于用户本次的四条诉求；
- 已登记为遗留项，建议二选一：① 让 `apply_template` 真的重排章节；② 把声明文案改为
  「本模板适用范围：一键分析的结构化视图（当前文书式正文按固定 5 章呈现）」。
  **按本仓铁律，不允许"声明与实现不一致"长期并存。**

## 三、问题二：为什么报告能显示行业、项目列表却不显示？（含"是不是脱离"）

**不是脱离。** 分析一直在**读** `projects` / `companies` / `sys_company_info`；
缺的是**反向的那一步：回写**。

根因链（三处同源）：

1. 分析完成后，行业只写进 `companies.industry_resolved`
   （`main._write_resolved_industry`，供「选择账套」页显示"本次按什么行业在分析"）；
2. **从未写回 `projects.industry`** —— 而稽查项目管理列表读的正是 `projects.industry`；
3. 于是同一个事实在库里存了两个地方，只有一处被更新 ⇒ 报告有、列表没有。

实测数据（改造前）：

```
projects.id=42   industry=''  region=''  period_start=''  period_end=''  tax_scopes='[]'
                 legal_representative=None  registered_capital=None  established_date=None
同一次分析的 target_entity  industry='广告传媒'  legal_representative='张晓冬'
                            period='2025-01 至 2025-12'  business_scope='五金产品零售;…'
```

**修法（补上断掉的链，不新建第二套口径）**：

- `engine/project_profile_fill.py`（**新增，字段派生的唯一权威**）：
  行业走 `industry_resolver`（不另写推断）、地区三级确定性推导（注册地址 → 企业名称行政区划 →
  信用代码登记机关行政区划码）、期间由报告期间解析、税种由申报表推导；
  **取不到就留空 + 写明原因**，绝不编造。
- `engine/project_service.sync_profile_from_analysis()`（**新增，`projects` 表写入的唯一入口**）：
  空值永不覆盖 / 无出入不写 / 逐条留痕（`project.profile_sync`）/ 不碰状态机 /
  **稽查期间只在项目未设时补**（期间是人定的工作边界，不是分析能替人改的）。
- 接线到 `main._persist_one_click_result`（分析完成即回写，失败只 warning 不吞结果）。
- 历史数据用 `scripts/_backfill_project_profile.py` 补一次（默认 dry-run，**幂等**：
  补完再跑显示 0 项）。

**实测回写结果**（海更，9 个字段）：

```
industry                ''            → '广告传媒'        [分析结果（销项发票品名推断）]
region                  ''            → '广东省深圳市'      [企业名称行政区划 + 登记机关行政区划码]
legal_representative    ''            → '张晓冬'          [工商档案]
registered_capital      ''            → '1000.0'         [工商档案]
established_date        ''            → '2022-03-03'      [工商档案]
business_scope          ''            → '五金产品零售;…'    [工商档案]
period_start            ''            → '2025-01-01'      [分析结果（报告期间）]
period_end              ''            → '2025-12-31'      [分析结果（报告期间）]
tax_scopes              '[]'          → '["增值税"]'       [分析结果（已上传申报表）]
```

## 四、问题三：进入分析报告页要显示页面顶端

**改前**：`tax-doc-analysis.js::renderTaxDocReport` 末尾无条件 `area.scrollIntoView(...)`。
那在它作为**独立内页**时是合理行为；内嵌进 `/reports` 后，用户一进来就被滚到报告区
（实测 `scrollY=119`），看不到页面标题与页签。

**改法（两道，互为兜底）**：

1. **声明式标记**：`reports.html` 的 `<body class="embed-report">`；
   `renderTaxDocReport` 见到该 class 就**不自动滚动**。
   为什么用 HTML 标记而不是全局变量：`tax-doc-analysis.js` 是 `defer` 加载，
   `reports.js` 先执行 —— 若用变量，后初始化的 `var` 会把值覆盖回去（脚本顺序陷阱）。
2. **主动归位**：`reports.js::_scrollPageTop()` 在「首屏渲染完 / 切页签」时都把视口归零。

**反向验证**（证明不是空转）：同时移除这两道 ⇒ 实测复现 **`scrollY=119`**（正是改前的值）。

## 五、问题四：编辑项目页"所有信息自动获取自动填列"，不要任何自动按钮

### 5.1 按钮的演进（用户连着提了三次，一次比一次彻底）

| 轮次 | 形态 | 用户反馈 |
|---|---|---|
| 2026-10-18 | `<button>自动查填</button>`，点击才查 | 「工商信息是自动添加，而不是手动的」 |
| 2026-10-19 第一批 | 改为 `role="status"` 状态徽标（不可点击，但仍像个按钮） | 「而不是**甚至一个自动按钮**！！！」 |
| **本轮** | **整个删除** | —— |

现状：`#btn-fetch-bizinfo` **不存在**；`config/frontend_perms.json` 的对应条目同步删除
（否则前端权限闸门会报「元素不存在」）。

### 5.2 权限怎么判（删了元素之后）

改为直接问 `window.RBAC`（服务端下发 `permissions` 是唯一权威，**不推断角色**）：
- 权限点 `project.write`；无权限 ⇒ **完全不发请求**（不是"查了再隐藏"）；
- **未就绪时不丢触发**：注册一次 `RBAC.ready()`，就绪后若名称已填则补查一次。
  ⚠ 就绪标志是 `RBAC.state.loaded`。**首版写成 `state.ready`（该字段不存在）⇒
  自动查填从未触发**，是真机验收抓出来的（不是靠读代码发现的）。

### 5.3 自动填列的覆盖面

| 触发点 | 自动填什么 | 来源标注 |
|---|---|---|
| 输入企业全称（防抖 700ms）+ 失焦兜底 | 统一社会信用代码 + 工商 7 项 + **行业 + 地区** | 提示区写明「来源：本地账套库（companies），命中缓存」+ 逐项推导来源 |
| 打开「编辑项目」 | 再按**最近一次分析结果**补齐期间/税种/行业/地区/工商 7 项（共 13 字段） | 提示区逐项写：「行业保持已填」「未自动填：登记状态：工商信息与资料中均未取得登记状态」 |

**两条硬规矩不变**：① 只填**空**字段（自动触发下绝不覆盖人工输入）；
② 查询失败只是提示，不阻断保存。

### 5.4 「工商信息有出入 ⇒ 以分析所得为准」

- 分析完成时由 `sync_profile_from_analysis` **写入分析所得的值**（有出入即覆盖）；
- 比较用 `_norm()` 归一化：`1000` / `1000.0` / `"1000.00"` 视为同一值
  —— 首版只做 `str()`，导致回写后再读变成"有出入"，每次打开编辑页都提示假差异（已修）；
- **例外**：稽查期间只在未设时补（人定的工作边界不替人改）。

## 八、遗留（如实登记）

1. **报告模板"声明 ≠ 实际"**：`apply_template` 只写 meta、不重排章节，而报告顶部声称了章节顺序
   （见第二节）。建议按 `apply_template` 真实化或改声明文案。
2. **地区只到"省+市"**：未细化到区县（工商登记信息本身不含地区字段，只能由住址推导）；
   若用户需要区县级，需要一张完整的行政区划码表（约 3000 行），当前刻意不硬编码。
3. **新建项目时行业是"经营范围推断"（置信度低）**：实测海更为「文化传媒」，
   而分析后按销项品名推断为「广告传媒」—— 这正是"有出入按分析所得更新"的适用场景，
   但不是缺陷：创建时只有工商数据可用，能推到这个粒度已属如实。
4. **`tax_scopes` 只从"已上传申报表"推**：未上传申报表的项目仍为空（并写明原因），不猜税种。
