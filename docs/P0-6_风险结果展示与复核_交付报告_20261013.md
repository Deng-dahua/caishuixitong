## 3. 核心实现说明

### 3.1 状态机（唯一权威，3 条纪律）

```
        ┌──────────────────── pending（待处理）────────────────────┐
        │  confirm → 已确认      exclude → 已排除   false_positive → 误报 │
        └──────────────────────────────────────────────────────────┘
             已确认 ──rectify──→ 已整改（并登记整改台账 WB-RC-…）
             已确认 ──exclude──→ 已排除
             已确认 ──reopen───→ 待处理
             已排除/已整改/误报 ──reopen──→ 待处理
             to_manual：**不改状态**，仅打「需人工介入」标记
```

| 纪律 | 做法 |
|---|---|
| ① **复核不改定性** | 本模块只写 `state`/`comments`/`history`；**任何动作都不触碰** `risk_level` / `conclusion_grade`（等级唯一权威 `engine/risk_levels.py`） |
| ② **不生成无理由的处置** | `exclude` / `false_positive` / `rectify` / `reopen` **必填说明**，否则 400 |
| ③ **不抹痕迹** | 事件 append-only；`reopen` 只改状态，**历史与批注保留**；重复同动作 ⇒ **幂等 `noop`**（不重复写历史） |

★ **"未确认不能整改"**：`pending → rectified` 被拒（须先 `confirm`）—— 语义上"已整改"以"已确认存在"为前提。
★ **终态可重开**：4 个终态都有回 `pending` 的出口（纠错渠道），但**不允许终态之间互跳**。

### 3.2 不产生第三份事实（★ 本轮收敛一处重复实现）

| 数据 | 唯一来源 |
|---|---|
| 风险发现 | 真实产物载荷 `offline_reports/company_{id}_full.json` 的 `confirmed_problems`，经 `rule_executor.collect_from_report()` 归一（P0-5 建立） |
| 复核态 | `data/risk_reviews.jsonl`（append-only 折叠） |
| 金额 | `risk_scoring.amount_of()`（**后端给出，前端不再求和**） |
| 等级 | `engine/risk_levels.py`（本模块不写） |
| 编号 | `engine/numbering.NumberingService`（整改台账 `WB-RC-…`） |
| 留痕 | `engine/audit_trail.record` |

**收敛动作 ①（取载荷）**：P0-5 的 `rules_api._findings_payload()` 自己实现了一份读盘；本轮把
**读载荷的唯一实现**收到 `risk_service.load_payload()`，`rules_api` 改为薄转发
⇒ 规则库页与风险工作台**同一取数口径**，不会各自漂移（`_mtime` 死代码一并删除）。

**收敛动作 ②（JSONL 落盘）**：审计闸门报出 6 组跨模块同名，逐组核查后发现
`engine/analysis_jobs._append_row` 与 `engine/risk_review._append_row` **字节级完全相同**
（只有"取哪个文件路径"不同）—— 这是**真重复**，不是"同名单异语义"。
⇒ 在**落盘唯一权威 `runtime_storage`** 新增 `append_jsonl()` / `read_jsonl()`，
两个模块改为薄转发（留痕文案仍各留在各自模块，因为那是各模块的语境）。
**剩余 4 组**（`_collapse` / `last_errors` / `_now` / `_amount`）经逐组核查确属"同名单、异语义"
⇒ 按判据要求登记到 `_DIVERGENCE_OK`（**同行内追加**，`audit_consistency.py` 行数 18267 不变、
D1 门禁行 11542/12008/12948/12951 **零漂移**）。

### 3.3 编号即身份（含越权防护）

`GET /api/v1/risks/{riskId}` 的 `riskId` 取**风险编号** `WB-R-{统一社会信用代码}-{期间}-{序号}`
（跨报告轮次稳定），而非易变的数字 `seq`。

★ **安全要点**：编号里**含统一社会信用代码** ⇒ 若只按编号取数，同一编号可能被用来越界读他账套。
故本模块**强制校验编号归属**（编号的 USCC 必须等于所声明账套的 USCC；不符 ⇒ **404**），
并有专门用例覆盖（`RiskPermissionTests`）。

### 3.5 前端

`/risks` 四个页签：**风险列表**（KPI + 8 个筛选维度 + 排序 + 分页 + 明细表）·
**风险统计**（等级/复核状态/税种/金额分档 4 张柱状图 + 复核进度条）·
**整改台账** · **逐条执行**（未运行/跳过/异常如实列出）。
点「详情/复核」开**右侧抽屉**：概要 → **人工复核区**（状态链 + 6 个动作按钮 + 理由框 + 提交/仅批注）
→ 批注列表 → 处置历史 → 规则与法规依据（含**占位标记**）→ 计算过程（因子表 + 置信度分项）
→ 证据链 → 证据缺口 → **明细表/叙述段落（原样渲染）** → 触发条件与认定要件 → 自我怀疑清单 → 建议。

★ 全部中文名（状态/动作/等级/排序键）**取后端 `/risks/meta`**，前端不硬编码。
★ 金额列取**后端算好的值**（前端不自行求和）；理由必填由**后端强制**、前端同步提示。
