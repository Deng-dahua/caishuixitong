# 二、改了什么（实现层）

## 数据结构（`engine/project_store.py`）

`projects` 表**只增不改**，新增 7 列（老库自动 `ALTER TABLE ADD COLUMN`，幂等）：

```
legal_representative   TEXT   法定代表人
registered_capital     REAL   注册资本（万元）
established_date       TEXT   成立日期（YYYY-MM-DD）
registration_status    TEXT   登记状态
registered_address     TEXT   注册地址
business_scope         TEXT   经营范围
company_type           TEXT   公司类型
```

## 字段单一权威（`engine/project_service.py`）

```python
PROFILE_FIELDS = ((字段名, 中文名, 最大长度, 类型), ...)   # 7 个工商字段
AUDIT_FIELDS   = ((字段名, 中文名), ...)                 # 5 个稽查要素
```

新增一个画像字段 ⇒ **只加一行**：建表列、写入白名单、详情展示、`profile_missing` 判定、
`/meta` 下发全部自动跟随，不改逻辑分支。

## 字典来源（三处权威，前端零硬编码）

| 字典 | 权威 |
|---|---|
| 行业（10） | `config/industry_params.json` → `industries[].label`（与风险指标/报告模板同一套口径） |
| 税种范围（23） | `engine/levy_nature.tax_scope_options()`（新增公开访问器；与"正向识别涉税"同源） |
| 登记状态 / 公司类型 / 地区 / 资本单位 | `config/project_profile_dicts.json`（本轮新建的数据文件） |

`GET /api/v1/projects/meta` 额外下发 `industries / regions / registration_statuses /
company_types / capital_unit / tax_types / profile_fields / audit_fields`。

## 缺失如实（不补默认值）

`_row_to_project` 返回：

- `profile_missing`：缺哪几项稽查要素（中文名数组），列表据此挂「待补全」；
- `profile_complete`：是否齐全；
- `profile_info_missing`：缺哪几项工商信息。

后端**不硬性阻断**缺项（兼容 API 直建与历史数据），但**绝不**用"未分类"/0/占位日期顶替。
编辑页保存则前端强校验必填。

## 项目 → 内部账套的同步（`ensure_company_for_project`）

项目是工商信息的**录入点（权威）**，内部账套是**派生物**（分析链路以 company 为作用域）：

- 新建账套：7 个工商字段 + `industry_code` 一并写入；
- 复用已有账套：`UPDATE ... COALESCE(现值, 项目值)` ⇒ **只补空、不覆盖**人工维护的数据；
- `industry_code` 由中文行业名反查 `industry_params.json`（如"建筑安装" → `construction`），
  未命中留空，**不猜**。

## 资料页删除入口收敛

- `static/js/documents.js`：删掉行内删除按钮、`askDelete`、`doDelete`、`data-act="del"` 分支；
- `static/documents.html`：删掉 `#m-del` 确认弹窗（无入口的弹窗不留）；
- `config/frontend_perms.json`：同步删掉两条登记（`btn-del-confirm` 与动态入口
  `data-act="del"`）—— 否则会出现"权限配置指着不存在的按钮"的悬挂登记。

# 四、边界与遗留（如实）

1. **历史项目仍是空的**：既有项目（如生产库 `PJ-20261018-0001`）行业/地区/期间原本就空，
   本轮不编造、不批量填默认值，列表标「待补全」，需人工点「编辑」补录一次。
2. **`profile_missing` 只覆盖 5 个稽查要素**；7 个工商信息属"重点但非强制"
   （个体工商户无法定代表人、新设企业无注册资本实缴等），单独由 `profile_info_missing` 标出。
3. **行业下拉是"建议 + 自由填写"**（datalist），不是强枚举：`industry_params.json` 只有 10 个
   行业模型，而实务中"信息技术服务""医药制造"等更细口径需要能录进来。
4. 本轮**未接入"资料解析自动回填画像"**（从营业执照/发票反填法人、注册资本）；
   如需要，属下一轮，且必须显式标注"来源于哪份资料、哪一行"。
