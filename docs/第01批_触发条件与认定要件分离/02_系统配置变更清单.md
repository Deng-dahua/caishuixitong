## 1. 数据模型字段变更

| # | 字段名 | 类型 | 所属表 | 修改前 | 修改后 | 修改原因 |
|---|---|---|---|---|---|---|
| 1 | `trigger_conditions` | `list[{id,desc,auto}]` | 风险指标（`config/risk_conditions.json` → `risks[]`） | **不存在**（触发条件与认定要件混在 `constituents` 一个字段里） | 每条风险指标 ≥1 条，共 **94 条**指标全部具备 | 用户规格：风险指标表增加 `trigger_conditions`，用于"出现什么信号就列为疑点" |
| 2 | `is_precondition` | `bool` | 认定要件（同上 → `determination_criteria[]`） | **不存在**（只能靠文本词表猜"现象/前提条"，疑点 3/4/12 的要件文本里**没有**该字样 ⇒ 全部漏判） | 每条要件一个布尔；实测 `RL-VAT-007.C1 = true` | 用户规格：认定要件表增加 `is_precondition`；**结构化字段**才能可靠判前提条 |
| 3 | `aliases` | `list[str]` | 风险指标（同上 → `risks[]`） | **不存在** | 3 条无红线/规则键控的发现按发现标记名登记（`VR012` / `VR019` / `SYN-MULTI-TAX-PROFILE`） | 修"已列为疑点却查不到触发条件"（实测 3 个疑点走内联兜底） |
| 4 | **`trigger_determination`** | `dict`（8 字段） | **本企业疑点**（`company_1_full.json` → `enterprise_readable_report.confirmed_problems[i]`） | **不存在**（只有报告里的一段话，**没有结构化数据**） | 落盘 **16/16 疑点**，字段 = `risk_code / trigger_conditions / trigger_status / determination_criteria / criterion_status / suspicion_established / risk_established / conclusion` | 用户规格【输出】字段；无结构化数据 ⇒ 前端/门禁/下游无法按字段消费，也无法机检"疑点成立 ⇔ 触发命中" |

**落盘文件路径**：`scripts/four_reports/company_1_full.json`（由 `scripts/run_companies.py 1` 生成）

```bash
# 验证命令（实测）

import json

ps=d['enterprise_readable_report']['confirmed_problems']
print('落盘数 =', sum(1 for p in ps if isinstance(p.get('trigger_determination'),dict)), '/', len(ps))
print(json.dumps(ps[0]['trigger_determination'], ensure_ascii=False)[:300])"
# 实测输出：落盘数 = 16 / 16
```

## 3. 质量门禁规则变更

**门禁函数**：`tools/audit_consistency.py` 第 **11489** 行 `check_trigger_determination_separation()`（**TDS-①~⑨ 全部在本函数内**；实测行号：`grep -n "def check_trigger_determination_separation" tools/audit_consistency.py`）
**调用位置**：第 **12888** 行 `run_checks()` 总链（实测：`grep -n "+ check_trigger_determination_separation()" tools/audit_consistency.py`；本批之后历经多次加固（文档一致性门禁、第一章四段式重构、summary 计数闸门、事实引子闸门、模糊词判据唯一性闸门），行号随之逐次下移，**以现算值为准**）
**新增 5 个文档一致性门禁**：`check_doc_number_authority()` 定义第 **11955** 行、调用第 **12891** 行（D1）；D2~D5 紧随其后（同一区块）

| 规则编号 | 规则描述 | 触发条件（判据） | 阻断行为 |
|---|---|---|---|
| **TDS-①** | 风险指标必须同时定义触发条件与认定要件 | `config/risk_conditions.json` 里某条风险缺 `trigger_conditions` 或 `determination_criteria` ｜ 第1条要件属存在性判据却未标 `is_precondition` | **ERROR** |
| **TDS-②** | 不得"已列为疑点"却"未触发任何触发条件" | 产物中某疑点 `trigger_status.hit_count < 1`（绑定键：红线编号 > 规则编号 > 完整标题） | **ERROR**（走内联兜底时记 WARN 便于追溯） |
| **TDS-③** | 不得出现病句「未涉及任何一条构成要件」 | 产物全文包含该串（与"已列为疑点"自相矛盾） | **ERROR** |
| **TDS-④** | 第1条认定要件（前提条）不得出现「未形成核对结论 / 未单独核对」 | 产物中第 1 条要件结论含该措辞 | **ERROR** |
| **TDS-⑤**（1.1.0 新增） | 每个疑点必须落结构化块 `trigger_determination` 且 8 字段齐全 | 缺块或缺任一字段 | **ERROR** |
| **TDS-⑥**（1.1.0 新增） | 触发命中 ⇔ 疑点成立（**双向**） | `bool(suspicion_established) != bool(hit_count > 0)` | **ERROR** |
| **TDS-⑦**（1.1.0 新增） | 认定要件与逐条状态必须一一对应 | `determination_criteria[].id` 集合 ≠ `criterion_status` 键集合 | **ERROR** |
| **TDS-⑧**（1.1.0 新增） | 前提条（`is_precondition=true`）结论必须写「符合情形」，且不得同时出现「未形成核对结论/未单独核对」 | 逐条检查 `criterion_status[C?].text` | **ERROR** |
| **TDS-⑨**（本批补做新增） | **产物认定要件条数 == 配置条数**（配置有、产物必须有） | `len(trigger_determination.determination_criteria) != len(determination_criteria_of(risk_code))` 且该风险键已在配置登记 | **ERROR** |

**命令（实测）**：

```bash

# 实测输出：ERROR 0 / WARN 0
```
