### B.3 与 V1.0 的落差（**规范侧依据待补**，此处只记现状缺口）

- **A｜作业本身无落库**：结果与历史已落盘并开机回读；但**作业实体不存在**——
  发起人、开始/结束时间、耗时、是否 `force`、是否增量复用、失败在哪一步，均无任何持久化。
  历史摘要字段见 `main.py:10184-10208`（含 `timestamp / round_no / risk_level / risk_score /
  total_findings / step_timing_total / log_count / error_count` + `snapshot`），**不含发起人**。
  另：`GET /api/tax-risk-docs/trace/{analysis_id}`（`main.py:13161`）只读
  `_last_analysis_cache`，故对 LRU 之外的企业会取不到。
- **B｜角色只有 `admin` / `user`**：`security.py:82`
  `CHECK(role IN ('admin', 'user'))`；授权粒度为**账套级**
  （`security.py:230` `grant_company_to_user` / `:439` `select_company`）。
  无业务角色（项目经理 / 分析员 / 复核人 / 只读），无按功能的权限点。
- **C｜台账记文档，不记作业**：`data/report_versions.jsonl` 字段为
  `doc_no / company_id / doc_name / edition_kind / version / generated_at / generator /
  system_version / reviewed / redaction_role / change_note`，**无 `analysis_id`**，
  报告无法回指"由哪次作业产出"。
- **D｜有签署栏，无流转**：`engine/report_compliance.py:109` 提供
  `review_status_text`、`:115` 提供编制人/复核人/审批人签名栏，但 `reviewed` 仅一个布尔标记，
  无"草稿 → 待复核 → 已复核 → 已签发"的状态机，无驳回，无权限约束。
