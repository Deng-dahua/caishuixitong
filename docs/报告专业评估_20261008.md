## 2. 逻辑通不通 —— 不通的地方（逐条给证）

### 2.1 ★ 同一疑点内自相矛盾（R2，最典型）

同一项里同时出现两句互斥的话：

- （开头）「本企业本项已查明的风险的**可能性低**，且**所需资料已齐备**，可作初步判断。」
- （结论）「本项属**已查明的风险，等级 高风险**。」
- （分类处理章）「重点关注：对 2 项**高风险**事项（**证据相对集中**…）」

**"可能性低"+"资料已齐备" 与 "高风险"+"证据相对集中" 不能同时成立。**
取证：`sed -n '136,160p' output/评估用_报告文本_20261008.txt`

### 2.2 ★ 9 处无谓语残句

固定句式如下（缺主语谓语，语法不成立）：

> 「从本次上传资料来看，**本企业本项已查明的风险；**未认定到构成要件的可能性中等，但能补全尚缺的3项资料来排除此项税务风险嫌疑。」

「本项已查明的风险」是名词短语，后面直接接分号 —— 应当写"本项存在需核实的风险信号"之类。
出现处：`grep -n "本企业本项已查明的风险" output/评估用_报告文本_20261008.txt` → 9 行。

### 2.3 标题里混进引擎内部推理（R9）

R9 的**标题**是：

> 企业所得税贡献率偏低（**对应风险指标：长期亏损仍持续经营：收入或成本不实；本项未认定到该指标的任何一条构成要件，也未就亏损这一前提作出认定**）

括号里那 60 字是引擎的自述，不是标题。老板看到的标题应该只有"企业所得税贡献率偏低"。

### 2.4 标题与依据不符（R3）

- 标题：「**工资表人数与社保参保人数不符**」
- 「为何列入检查」第一条依据：「**社保低基数参保**（该人工资 30000.00 元、缴费基数 6000.00 元，基数占工资 20.00%）」

"低基数"与"人数不符"是两个不同的风险点（报告自己也承认它们属同一风险族的不同子项）。标题只写"人数不符"，依据却先讲"低基数"，读者会错位。

### 2.5 渲染粘连：「办理顺序：第X项」直接粘在标题后

页面上读到的是：

> `疑点1：红字冲销与作废发票比例异常办理顺序：第一项`

标题与"办理顺序"之间**缺分隔符**，读起来像标题叫"异常办理顺序"。

### 2.6 组合项与单项并存（R2 与 R4/R15 事实重叠）

R2「多税种联动稽查风险画像」自述"本项不是独立事实"，其正文把 **R4（银行收款大于申报收入）** 和 **R15（成本列支证据不足）** 的事实**再讲一遍**，且 R2 自身无独立金额（`basis=None`）却评为高风险。而敞口口径声明又写"**各事项间金额可能重叠**……不可逐项相加用于缴款"。

**问题**：既然承认重叠，"组合项 + 单项"是否应同时列为两条疑点、是否各自占一个编号，需要明确规则；现在读者会以为这是两笔独立风险。

### 2.7 做得好的地方（不是只挑毛病）

- **计数是对的**：高风险 2 / 中风险 9 / 低风险 3 / 待核验 2 = 16，与总述、分类处理章三处一致（脚本核对通过）。

## 3. 疑点准不准 —— 含一处可复现的量级错误

### 3.1 ★★ 核心缺陷：增值税"潜在税额"取了含税销售额，高估约 8.7~17 倍

**报告给老板的数字**（第一章）：

> 本轮潜在税额敞口（测算）：**合计约 1,243,745.73 元**（增值税 **1,015,900.00** 元；城建税及教育费附加 121,908.00 元；企业所得税 105,937.73 元）

**这个 1,015,900.00 是什么？** 是 R1 那 13 张红冲发票中**销项侧 4 张的"价税合计"之和**：

```
233,200.00 + 259,000.00 + 420,700.00 + 103,000.00 = 1,015,900.00   ← 含税
```
（明细见报告"红冲/作废发票情形（共13笔）"表第 1~4 行；报告自己在括注里写明"价税合计-233,200.00元"等）

**却被当成"增值税"列示。** 取证（数据层）：

```bash
# R1 的税额明细：rate 是「—」，即"不再乘税率"，直接把 1,015,900 当税额
R1: tax=增值税        rate=—       amount=1015900.0
    tax=城建税及教育费附加 rate=0.1200 amount=121908.0     # = 1,015,900 × 12%
```

**根因已定位**（可复现）：

```bash
python -c "from engine.tax_impact import infer_amount_is_tax, _TAX_AMOUNT_KW; ..."
# R1 infer_amount_is_tax = True
# 命中的关键词: ['销项税额']
#   上下文: 涉嫌通过红冲调节【销项税额】、配合受票方虚开后冲回
```

`_TAX_AMOUNT_KW = ['进项税额','销项税额','可抵扣税额',…]`，判定函数 `infer_amount_is_tax()` 是**在整段叙述里做关键词命中**。
R1 的正文出现"调节**销项税额**"——这是在描述**手法**，不是在说"本项金额本身就是税额"。于是引擎判定"锚定金额即税额"，把**含税的价税合计**当成了增值税额。

**量级误差有多大？**

| 口径 | 增值税 | 附加(12%) | 敞口合计 |
|---|---|---|---|
| 报告现值（错） | 1,015,900.00 | 121,908.00 | **1,243,745.73** |
| 按 6%（广告服务）正确测算 | 57,503.77 | 6,900.45 | ≈ 170,341.95 |
| 按 13% 正确测算 | 116,873.45 | 14,024.81 | ≈ 236,835.99 |

**即：敞口被高估约 5.25~7.30 倍；其中 1,137,808 元（占报告总额 91.5%）来自这一处。**

**并且报告自我矛盾**：其《口径声明》①写明"标注为『价税合计／含税』的，**已按适用税率价税分离为不含税后再测算**"，而实际数字 1,015,900 恰等于价税合计、未做分离；同一段⑤又写"红字冲销／作废发票类按销项全额估算上限"。**①与⑤互斥，且与数字都不符。**

> ⚠ 对老板的直接后果：他会以为"可能要被补 101 万增值税"。这个数**不是税额**，是含税销售额上界。以 13% 计，真正对应增值税约 11.7 万。

### 3.2 12/16 项"未量化"——"值多少钱"基本没答

16 项里只有 4 项给出金额（R1、R5、R13 及合计）。**R2（高风险）、R4（中风险）、R15（成本列支）等影响最大的几项都没有金额。**
对老板而言，"高风险"却"不知道该准备多少钱"，决策价值有限。

### 3.3 疑点本身的质量：多数是"真信号"，值得肯定

以下几项的依据是**账内可复核的硬事实**，属真疑点：
- R1：13 张红冲发票，附**发票号码 + 被冲蓝票号 + 红字信息确认单编号 + 日期 + 金额**（可逐张去电子税务局核）；
- R3：工资表 6 人 vs 社保 5 人，差异人**指名道姓（杨莹，17,000.00 元）**；
- R5：业务招待费 411,111.53 元 / 主营收入 6,636,800.57 元 = 6.19%，对照 5‰ 法定标准（算式与阈值都写全）。

**这三条就是"铁证"该有的样子。** 问题不在"准不准"，而在全报告的表述方式把它们淹没了。

## 4. 能否做到"铁证如山"

按你修正后的口径——**"只要企业资料被分析出涉税风险，就是事实风险"**——我按两层回答：

### 4.1 事实层：**已经"铁"了**

判定"铁证"的三要素，报告现状：

| 要素 | 现状 | 说明 |
|---|---|---|
| 金额可复算 | ✅ | 到分（411,111.53 / 1,015,900.00 / 17,000.00） |
| 对象可指认 | ✅ | 到人（杨莹）、到票号（25952000000096267625）、到日期 |
| 口径可追溯 | ✅ | 有「口径说明」块声明分子分母（10 处） |
| **一键回溯原始行** | ❌ | 报告不给"这数字来自哪张表的第几行"，读者只能信不能核 |
| **外部数据交叉** | ❌ | 报告自述未接入工商/司法/第三方支付 |
| **统一事实编号** | ⚠ | 有 R/要件/事实/资料多套编号，但未串联成一条链 |

**结论：账内事实已达"可复核的铁"**；但"铁"要能自证，还缺"一键回溯"与"外部交叉"这两条腿。

### 4.2 定性层：**刻意不铁，且这是对的**

报告通篇用"涉嫌/不作定性/不予排除/待核事项"，并在第五章明列**四个结论术语**（风险信号 / 待核事项 / 已认定事实 / 违法认定），并声明"违法认定只能由有权机关作出"。

**这是正确的法律边界**（你也不希望一份内部报告被当成执法文书）。问题不是"不该免责"，而是：

> **免责语与事实陈述没有分层。** 老板读到的每一段都被"不作定性/不予排除/资料不足"包裹，导致他**看不出"哪些是已经坐实的事实、哪些只是待核的线索"**。

**建议**（不改法律边界，只改呈现）：
每项疑点开头加一行**事实/定性双标签**，例如：

> **【已核实事实】** 2025 年销项红冲 4 张，价税合计 1,015,900.00 元，均有红字信息确认单编号。
> **【待核事项】** 这些红冲是否有退货/折让等合法事由，尚缺资料，不作定性。

一句话让老板分清"铁"与"不铁"。

### 5.4 ★★ 更严重的：引用**指向了不相干的疑点**（不是"空"，是"错"）

「本项因缺资料未能查完」章（6 项资料缺口）的**四个字段全部写成 `〔见疑点R4〕`**：

而 **R4 是"银行收款大于申报收入"**，与"未收到合同文件"毫无关系。读者若照着点过去，会被引到错误的疑点。

R16 的结论段里还混着 `〔见疑点R16〕`（**自引用**，即"见我自己"）与 `〔见疑点R1〕`×N。

### 5.5 根因（三层，已核）

1. **替换器范围 ⊋ 计数器范围**：计数器 `report_dedup.find_leftover_duplicates` **只统计"可上提标题"**（`is_hoistable_head`）；而替换器 `report_pipeline.dedup_report_data` 对**所有**叙述段一律替换，不区分标题 ⇒ **本项特有的结论段也被当"共性"替换掉**。
2. **句子相似阈值偏低**：`sentence_threshold` 默认 **0.62**，中文套话句式极易达到 ⇒ 连"本项结论"这种特有段落也被判为重复。
3. **引用格式两处各写一套**：生成用方头括号 `〔见疑点R4〕`（为防下游误判子项），而权威判定 `reference.is_reference()` 的正则**只认圆括号/无括号** ⇒ **权威识别不了自己产出的格式**，无法拦截、无法回捞。

> 这属于你项目铁律里明令禁止的**"同一概念两处各写一套"**与**"判据口径必须与去重口径同口径"**的实际违反。

## 6. 企业能怎么补救（自证清白）—— 这是报告的**最大亮点**

### 6.1 强项

```
「本项可能错在哪里：自我反驳与验证清单」 → 16/16 项都有
「请提供以下资料，用来验证或推翻本项」   → 16/16 项都有
「推翻条件」                            → 35 条
「可自证清白」出现                       → 58 次
```

每一项都明确告诉企业：**"什么情况下本项不成立"**。例如 R16：

> 什么情况下不成立：「股权转让协议、工商股权变更登记」补齐后，若显示相关业务真实、口径一致 ⇒ **本项不成立（可自证清白）**。

还有一条**很专业**的设计——「本项最薄弱环节」（可信度分项取值最低的那一项），直接告诉企业"补哪一项最有用"：

> ［弱］最薄弱环节（可信度分项）　反证已提交比例　取值 0.0
> 可能不成立之处：这一项取值最低 ⇒ **它是决定本项可信度上限的环节；只提高其他环节不改变结论。**

**这在同类系统里是罕见的、真正可操作的补救指引。**

### 6.2 弱点

1. **"需企业提供"清单被引用 bug 破坏**：R10 的「五、需企业提供的资料与说明」整节只剩 `〔见疑点R10〕`，**企业看不到要补什么**。
2. **询问清单未单独成章**：数据里生成了 `6 条询问、覆盖 6 个主题`（`inspection_questions_report.available=true`），但页面 **0 次**单独呈现，只零星内联在 4 个疑点里（如 R2 的"询问 1：资金·私户收款性质"，质量很高）。企业拿不到一份可以逐条答复的清单。
3. **复核标准偏"虚"**：「怎样判断企业正在趋于合规 = 问题逐项处理、资料逐步完整、账务与申报能相互核对」——**没有可勾选的清单、没有时限、没有量化门槛**，企业无法自测"我够了吗"。

## 8. 结论与建议（按优先级）

**这份报告的问题不是"分析能力不行"，而是"最后 10% 的呈现环节把前面 90% 的成果糟蹋了"。**

| 优先级 | 事项 | 理由 |

| **P0** | 修「潜在税额」口径：`infer_amount_is_tax` 因正文提及"销项税额"而误判，把含税价税合计当税额（高估 5~7 倍） | 老板看到的头号数字是错的，且与报告自己的口径声明矛盾 |
