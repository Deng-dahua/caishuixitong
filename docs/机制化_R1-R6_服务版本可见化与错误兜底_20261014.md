## 二、逐项：完工定义 vs 实测证据

### R-1 服务版本可见化

**完工定义**：改代码不重启 ⇒ `/healthz` 报 stale 且列出变更文件；页面显示可操作横幅；重启后消失。

**实现**：新增 `engine/runtime_version.py`（**唯一权威**）
- `_BOOT` = 进程导入本模块那一刻的**源码指纹**（root `*.py` + `engine/*.py`，**内容 sha1**，非 mtime ⇒
  改后又改回不算落后）；
- `staleness()` = boot 快照 vs 磁盘当前快照（磁盘快照 2 秒缓存，避免 `/healthz` 高频调用打盘）；
- `health_payload()` 供 `/healthz`；`stale_hint()` 供前端与错误页复用。
- ★ **只监控 Python 源码**：前端/CSS/HTML 本就是每次请求从磁盘读，更新**不需要**重启 ⇒ 算进去会误报。

**实测**（真实 Chrome + 隔离实例，运行中注入）：`/healthz` 由 `stale=false` → **`stale=true`** 且
`changed_files=[{file: engine/js_source.py, change: 已修改}]` → 页面出现横幅（含启动时间与 `start8001.bat`）
→ 逐字节恢复后 **回到 false、横幅消失**。

### R-2 页面路径 HTML 错误兜底

**完工定义**：页面路径 404/500/503 返回 HTML（含处置动作）；`/api/**`、`/static/**` 保持 JSON/原样。

**实现**：新增 `error_pages_api.py`
- `page_404_handler`（注册到 `app.add_exception_handler(404, ...)`）+ `error_route()`（全局异常分流权威）；
- **边界不可越界**：`/api/`、`/static/`、`/docs`、`/redoc`、`/openapi.json` 一律返回 JSON/原样；
- 页面兜底页含：状态码、原因、**处置动作清单**、当前服务启动时间、`/healthz` 自检指引。

**实测**：`GET /not-a-page-xyz` ⇒ **404 + HTML**（含「旧代码」「start8001.bat」「/healthz」）；
`GET /api/v1/not-a-route` ⇒ **仍是 `{"detail":"Not Found"}`**。

### R-3 忙/锁（503）与只读（500）语义拆分

**完工定义**：只读不再被提示"请重试"；忙/锁仍可重试。

**实现**：`database.py` 新增 `is_db_readonly_error()`，并把 `readonly database` 从 `is_db_busy_error()` **移出**。

**实测**：`readonly ⇒ 500 + "重试无效"`；`locked ⇒ 503 + "请重试"`；`ValueError ⇒ 500`。
（首版 `is_db_busy_error` 的语义由本批**收窄**，对应测试与文档同步更新并注明理由。）

### R-4 清 2 条真 404 噪声

- `/api/accounts`：调用（`core.js`）与 `loadAllAccounts()`、`allAccounts` **一并删除** ——
  该值全仓**无人读取**（只有赋值）⇒ 纯噪声。
- `/api/me` → **`/api/auth/me`**（唯一权威，5 个页面脚本）⇒ 子页面用户名恢复显示。

**实测**：主界面加载 **0 条 404**；`/documents` 无 `/api/me` 404，`#whoami = _diag`（登录用户名）。

### R-5 解耦「取数」与「跳转」（消除同款近失）

`core.js` 原第 472 行 `await loadAllAccounts();` **紧贴 `navigateTo(lastPage)` 前一行**，
与 2026-10-07 那次「内容区永久空白」事故**同款位置**（当时是 `loadCompanies` 未定义）。
现改为：取数段包 `try/catch`，失败只 `console.warn`，**`navigateTo` 必执行**。

**实测**：主界面内容区正文 **434,680 字**、**JS 运行时错误 0 条**。

### R-6 前后端审计分层 + **剥注释**（唯一权威）

`scripts/_audit_fe_be_alignment.py`：
- ★ **先剥注释**再提取：原实现直接在源码上找 `/api/...` 字面量，**连注释里提到的路径也算"调用"**
  （本轮实测被自己写的注释坑到）；
- **分层**：A1 真断链 / A2 死代码（归属函数全仓从未被调用）/ A3 路径常量（`var API = "/api/v1"`）。

**实测**：A1 **6** / A2 **7** / A3 **21** / B **1**（405）。
★ 其中 A1 的 6 条全部来自**已下线/遗留子系统**（`human-learning` 3、`tax-assets` 3），
且 **Chrome 实测页面加载路径 0 条** ⇒ 与实际体验一致（脚本已就地标注该口径）。

## 三、★ 过程中修掉的两处"基础工具"缺陷（本批最大隐性收益）

### 1. JS 剥注释遇**正则字面量**脱同步（同款坑第三次出现）

`static/js/documents.js:22` 有 `.replace(/"/g, "&quot;")`。朴素扫描器把正则里的 `"` 当字符串起点
⇒ 状态机脱同步、**其后整段代码被当字符串** ⇒ 注释再也剥不掉 ⇒ **假判据**
（这与 2026-10-07 让 `_js_code_only` 对 `loadCompanies is not defined` 失明是**同一个坑**）。

**处置**：把剥注释上提为**唯一权威** `engine/js_source.strip_comments()`
（识别字符串/模板串/注释/正则字面量，**长度与行数守恒**），
`scripts/_audit_fe_be_alignment.py` 改为**薄转发**（并加闸门禁止脚本再自带实现）。
★ 并在模块头**明确区分两个易混概念**：

| 概念 | 函数 | 字面量处理 | 用途 |
|---|---|---|---|
| 只剥注释（保留字面量） | `engine/js_source.strip_comments` | **保留** | 提取 `/api/...` 路径做对齐审计 |
| 只留代码（字面量也抹掉） | `tools/audit_consistency._js_code_only` | 抹成空格 | 找裸名调用（防字面量里 CSS/中文说明成片误报） |

### 2. 发现 `_js_code_only` **两份实现**（多头维护）——**已登记下一轮，未在本批动手**

`tools/audit_consistency.py` 中 `_js_code_only` 在 **2395** 与 **11026** 各定义一次：
- 2395 那份是 **2026-10-08 的朴素实现**（不识别正则字面量）；
- 11026 那份是 **2026-10-07 修正版**（补了正则识别，108 行）。

Python 后定义覆盖前者 ⇒ 当前**运行的是修正版**，故行为正确；但"同一概念两处实现"本身是事故温床。
**为何本批不动**：两处都在 D1 锁定行（11542/12008/12948/12951）与门禁链（13018）**之前**，
删除/合并会**移动锁定行号** ⇒ 需要单独一轮"重定基线"来做（已登记 `MEC-01`，见下一轮清单）。
