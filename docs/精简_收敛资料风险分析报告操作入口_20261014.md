# 模块精简（第二档）：收敛「资料风险分析报告」的重复操作入口

- 日期：2026-10-14
- 前置：第一档见 `docs/精简_下线系统日志并入审计日志_20261014.md`
- 触发：用户裁定「做精简，保留新研发的模块」
- 改动文件：`static/js/tax-doc-analysis.js`、`static/index.html`（仅版本号）——**后端与数据库零改动**

---

## 一、为什么是"收敛入口"而不是"下线页面"

核查证据（非猜测）：

1. **`tax-doc-analysis.js` 是报告渲染的唯一前端权威**：
   `tools/audit_consistency.py` 对其有 **20+ 处检查（多处直接 ERROR）**；
   闸门 `check_one_click_wiring_coverage` 判据④要求 `report_template_meta` 与
   `extract_corrections` **必须出现在前端脚本的去注释代码里**（落在 `renderAnalyzeHeader`
   / `_renderScopeAdoptedBlock`）；`engine/capability_matrix.py`、`engine/common_clauses.py`
   / `config/common_clauses.json`、`main.py:14481` 能力映射均引用它。
   ⇒ **删页面 = 报告没了**，属重写不属精简。
2. **它的重复只在"操作入口"**：上传/资料删除与 `/documents`（P0-2）重复、
   发起分析与 `/analysis`（P0-4）重复 —— 而**底层是同一份**：
   资料登记 `shared_state._tax_risk_docs`（`engine/document_service.py:94` 桥接）、
   分析引擎 `_execute_tax_risk_analysis`（`main.py:11631` 注释明写两条入口汇聚于此）。
   ⇒ **入口归一，功能不丢失**。

## 二、改了什么

`renderTaxDocAnalysis()`（`/` 默认页的渲染入口）：

| 原 UI | 处置 | 归属 |
|---|---|---|
| 上传资料按钮 + 文件选择框（`tda-file-input`） | **移除** | `/documents`（P0-2） |
| 「一键分析并生成过程报告」「重新计算（强制）」 | **移除** | `/analysis`（P0-4） |
| 「删除选中资料」「清理删除残留」 | **移除** | `/documents`（P0-2） |
| 资料清单（`tda-file-list`）及其加载调用 `refreshTaxDocList()` | **移除** | `/documents`（P0-2） |
| 「导出PDF」「缓存」「删除报告」 | **保留** | 报告阅读/管理，属本页职责 |
| 报告渲染区 + 服务端恢复逻辑 | **保留** | 本页核心 |
| （新增）空态引导 | **新增** | 无报告时提示去 `/documents` 上传、去 `/analysis` 发起 |

操作条下方新增一行**入口指引**：资料操作 → `📎 资料上传与管理`；分析操作 → `⚡ 一键稽查分析任务`。

**有意不删的**：`uploadTaxDocs` / `analyzeTaxDocs` / `refreshTaxDocList` 等**函数本体保留**
（UI 已无任何调用点，纯死代码）—— 目的有二：① 回滚只需还原 `renderTaxDocAnalysis` 一处；
② 它们承载的 `/api/tax-risk-docs/*` 交互契约未动，属可恢复资产。函数级清理留待后续专门一轮。

## 三、安全边界（改前已核实）

- `tools/audit_consistency.py` 中 **不存在**对 `tda-analyze-btn` / `tda-file-input` /
  `一键分析并生成过程报告` / `uploadTaxDocs` / `analyzeTaxDocs` / `refreshTaxDocList`
  的任何断言 ⇒ **闸门未锁定**这些标识，移除 UI 不触发闸门。
- 判据④的渲染点（`renderAnalyzeHeader` / `_renderScopeAdoptedBlock`）**一行未动**。
- 被移除 ID 的其余引用全部位于**死函数体内**（250/311/343/2464 行），无活路径依赖。
- 保留按钮的三个函数实存：`exportTaxDocReportPdf`（8663）/ `deleteTaxDocReport`（8738）/ `showCacheInfo`（9138）。

## 五、对用户操作路径的影响

- 老路径「在首页上传 → 点一键分析」**关闭**；新路径：
  1. 「📎 资料上传与管理」上传资料（分类/查重/状态管理更完整）；
  2. 「⚡ 一键稽查分析任务」发起分析（有进度/步骤/历史/取消/重试）；
  3. 回到「📁 资料风险分析报告」阅读、问答、复核、导出 PDF。
- 页面加载随之变轻：不再拉取 `/api/tax-risk-docs/list` 资料清单。
- **回滚**：还原 `static/js/tax-doc-analysis.js` 单文件即可（后端未动）。
